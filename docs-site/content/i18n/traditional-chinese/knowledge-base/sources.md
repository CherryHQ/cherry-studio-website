# 新增與整理資資

知識庫支援檔案、Cherry Studio 筆記、本機目錄以及單一網頁連結。匯入後需檢查處理狀態、內文與 Chunks，並在資資更新時重新建立索引。

{% hint style="info" %}
完成標準不是「檔案已出現在清單中」，而是資資可被讀取、Chunks 完整，且實際問題能召回正確的來源。
{% endhint %}

## 選擇正確的入口

<figure><img src="../../../assets/4622da2093d43942d7ee443e.webp" alt="新增與整理資資 — 說明圖片"><figcaption><p>依資資來源選擇入口：少量檔案使用【檔案】，同類檔案集合使用【目錄】，Cherry Studio 內容使用【筆記】，公開網頁使用【連結】。</p></figcaption></figure>

| 入口 | 適合什麼資資 | 匯入後的關係 | 主要注意事項 |
| -- | ----------------------- | ----------- | ------------------ |
| 檔案 | PDF、Office、Markdown、文字等 | 儲存託管副本 | 單次最多選擇 20 項 |
| 筆記 | Cherry Studio 中已整理的內容 | 匯入當時的內容快照 | 原始筆記後續修改不會自動同步 |
| 目錄 | 同一主題下的一批本機檔案 | 依目錄內容建立資資項目 | 不要將無關目錄整體匯入 |
| 連結 | 單一可公開存取的網頁 | 儲存抓取時的網頁快照 | 登入頁、腳本渲染或受限網頁可能不完整 |

{% hint style="warning" %}
支援的檔案包括 PDF、DOCX、DOC、PPTX、XLSX、XLS、MD、TXT、CSV、HTML 和 EPUB。掃描版 PDF 或圖片型內容還需檢查 OCR。
{% endhint %}

## 新增並驗收資資

{% stepper %}
{% step %}
### 1. 選擇資資來源

開啟知識庫，點擊新增資資按鈕，選擇【檔案】、【筆記】、【目錄】或【連結】。
{% endstep %}

{% step %}
### 2. 確認選取的內容

檔案和筆記可批次選擇；單次互動式新增最多 20 項。資資較多時請分批新增，或使用目錄入口。
{% endstep %}

{% step %}
### 3. 處理同名衝突

新資資與現有項目同名時，選擇【全部保留】或【取代】。更新制度、手冊和筆記快照時通常選擇【取代】。

{% hint style="warning" %}
選擇【全部保留】會讓新舊內容同時參與召回。只有確實需要並行查詢不同版本時才這樣做，並在名稱中標明日期或版本。
{% endhint %}
{% endstep %}

{% step %}
### 4. 等待處理完成

資資會經過複製、讀取、切分與索引等階段。未設定嵌入模型時不會建立向量，但仍會建立關鍵字索引。

<figure><img src="../../../assets/2414cfc005a860f127a4fd96.webp" alt="新增與整理資資 — 說明圖片"><figcaption><p>資資進入可用狀態後，再抽樣檢查內文和 Chunks。</p></figcaption></figure>
{% endstep %}

{% step %}
### 5. 抽樣檢查內文和 Chunks

開啟資資查看內文，或從資資列選單查看 Chunks。重點檢查標題順序、表格、OCR 文字和關鍵句是否被錯誤拆開。
{% endstep %}

{% step %}
### 6. 完成召回測試

使用一個答案明確的問題檢查正確來源和片段。資資更新後，也要使用同一組問題重新測試。

<figure><img src="../../../assets/b44776524449cdefe62eaed3.webp" alt="新增與整理資資 — 說明圖片"><figcaption><p>最終驗收要看來源、片段完整度和排序，不只看是否返回結果。</p></figcaption></figure>
{% endstep %}
{% endstepper %}

## 資資狀態與處理方法

| 現象 | 可能原因 | 處理方法 |
| ----------- | ------------------ | ------------------ |
| 長時間處理中 | 檔案較大、解析器或模型不可用 | 檢查原始檔案、文件處理和嵌入模型 |
| 顯示錯誤 | 複製、讀取、切分或索引失敗 | 開啟錯誤訊息，依失敗階段處理 |
| 內文缺失或亂碼 | 檔案處理器不適用、掃描內容未 OCR | 更換文件處理方式或設定 OCR |
| Chunk 缺少關鍵句 | 分塊邊界不適當 | 調整分塊後執行【重新索引】 |
| 新舊版本同時命中 | 同名資資選擇了【全部保留】 | 刪除舊項目，或重新匯入並選擇【取代】 |

## 重新索引與刪除

切分、解析器或嵌入設定改變後，舊項目不會自動套用新設定。對單一資資使用【重新索引】，或批次選擇資資後重新索引。

{% hint style="danger" %}
刪除項目會移除目前知識庫中的託管副本和索引。它不會刪除原始檔案或原始筆記，但刪除前仍要確認知識庫中是否有唯一副本。
{% endhint %}

## 設定說明

| 設定項 | 產品預設值 | 建議起點 | 作用 | 適用情境 | 注意事項 |
| ------ | ------- | ---------- | --------------- | ---------- | ---------------- |
| 單次新增數量 | 最多 20 項 | 先新增少量代表性資資 | 控制一次匯入規模 | 第一次建庫或除錯 | 大批量匯入前先驗證解析和召回 |
| 同名處理 | 發生衝突時選擇 | 更新資資優先【取代】 | 決定新舊項目是否並存 | 制度、手冊、筆記更新 | 【全部保留】可能讓舊內容參與召回 |
| 重新索引 | 手動執行 | 設定變化後執行 | 讓舊資資使用新解析、分塊或模型 | 調優或修復資資 | 完成後必須重新做召回測試 |

## 使用者案例

小林每月更新差旅制度。他將新檔案以相同名稱匯入，並選擇【取代】，待資資處理完成後抽樣檢查內文和 Chunks，再用固定問題測試住宿、交通和審批規則。

完成標準是：舊規則不再出現在召回結果中，新規則的條件和金額能夠穩定命中。

## 常見問題

<details>

<summary>修改原始筆記後，知識庫會自動更新嗎？</summary>

不會。筆記匯入的是當時內容的快照。修改後需要重新新增並選擇【取代】，或對對應資資執行【重新索引】。

</details>

<details>

<summary>網頁為什麼只抓到部分內容？</summary>

需要登入、依賴腳本渲染或存在存取限制的網頁可能無法完整抓取。可以改用檔案或筆記儲存內文後再匯入。

</details>

<details>

<summary>刪除知識庫項目會刪除原始檔案嗎？</summary>

不會刪除原始檔案或原始筆記，但會移除知識庫中的託管副本和索引。

</details>
