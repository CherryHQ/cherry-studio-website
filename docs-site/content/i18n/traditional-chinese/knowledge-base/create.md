# 建立知識庫

建立時最重要的兩個選擇是名稱和嵌入模型。資資可以稍後添加，但名稱邊界和檢索方式會影響後續維護。

{% hint style="info" %}
第一次體驗可以把【嵌入模型】設為【不使用】。知識庫仍會使用 BM25 關鍵詞檢索，先把導入和召回流程跑通即可。
{% endhint %}

## 建立前先做兩個決定

### 名稱要說明資資邊界

優先使用「對象 + 用途」，例如【員工差旅制度】、【產品售後手冊】或【市場研究資資】。避免使用【資資】、【測試】這類以後無法判斷內容範圍的名稱。

### 選擇嵌入方式

| 選擇 | 適合場景 | 檢索方式 | 前置條件 |
| ------ | ------------- | ------------- | ------------ |
| 不使用 | 第一次體驗、關鍵詞明確 | BM25 關鍵詞檢索 | 無 |
| 雲端嵌入模型 | 用戶問法與資資原文差異較大 | BM25 + 向量混合檢索 | 對應模型服務可正常調用 |
| 本地嵌入模型 | 希望在本機完成向量化 | BM25 + 本地向量檢索 | 先在【本地模型】完成下載 |

## 建立步驟

{% stepper %}
{% step %}
### 1. 開啟建立視窗

開啟左側導覽【知識庫】，點擊知識庫列表上方的新增按鈕。
{% endstep %}

{% step %}
### 2. 輸入名稱

輸入一個能說明範圍的名稱，例如【員工差旅制度】。
{% endstep %}

{% step %}
### 3. 選擇嵌入模型

選擇可用的雲端或本地嵌入模型；暫時不需要語義檢索時，選擇【不使用】。

<figure><img src="../../../assets/7f1505c0527aeddf65937cdc.webp" alt="建立知識庫 — 說明圖片"><figcaption><p>名稱決定資資邊界；嵌入模型決定是否加入向量檢索。</p></figcaption></figure>
{% endstep %}

{% step %}
### 4. 點擊建立

確認名稱和模型後點擊【建立】。建立完成後會進入空白知識庫。
{% endstep %}

{% step %}
### 5. 添加第一批資資

點擊添加資資按鈕，導入一兩份答案明確的檔案或筆記，再等待處理完成。
{% endstep %}
{% endstepper %}

## 使用本地嵌入模型

開啟【設定】→【本地模型】，在【嵌入模型】區域下載可用模型。介面顯示的模型和下載大小可能隨安裝環境變化，以當前列表為準。

<figure><img src="../../../assets/ba97a6075b29a5304d81dc79.webp" alt="建立知識庫 — 說明圖片"><figcaption><p>下載完成後，回到知識庫建立或設定頁面選擇該模型。</p></figcaption></figure>

{% hint style="warning" %}
本地嵌入只代表向量化在本機完成。文件解析、重排和聊天是否使用雲端，仍取決於各自選擇的服務和模型。
{% endhint %}

## 已有資資後更換模型

從僅使用 BM25 的知識庫啟用嵌入模型時，可以建立向量索引。已有向量的知識庫更換嵌入模型時，介面會進入【重建知識庫】流程。

{% hint style="danger" %}
開始重建前先確認新模型可以正常調用。重建後重新完成召回測試；不要在同一輪又更換模型、又修改分塊，否則無法判斷結果變化來自哪裡。
{% endhint %}

## 設定說明

| 設定項 | 產品預設值 | 建議起點 | 作用 | 適用場景 | 注意事項 |
| ------ | ----- | ----------- | ---------- | ----------- | ------------------ |
| 名稱 | 空 | 對象 + 用途 | 區分資資邊界 | 所有知識庫 | 權限或生命週期不同的資資應分開 |
| 嵌入模型 | 不使用 | 第一次體驗先不使用 | 決定是否加入向量檢索 | 口語問法、同義表達較多 | 雲端模型的計費和資資處理取決於服務商 |
| 本地嵌入模型 | 未下載 | 有本地處理需求時再下載 | 在本機完成向量化 | 離線或隱私要求較高 | 仍需單獨檢查解析、重排和聊天模型 |

## 預期結果

* 新知識庫出現在列表中，名稱能與其他知識庫區分。
* 你清楚當前使用的是關鍵詞檢索還是混合檢索。
* 選擇的雲端模型可以調用，或本地模型已經完成下載。

## 用戶案例

小林第一次建立【員工差旅制度】知識庫。他先選擇【不使用】嵌入模型，導入三份制度並完成召回測試。關鍵詞查詢穩定後，他再設定嵌入模型，用相同問題比較口語問法的結果。

完成標準是：升級檢索方式後，原来的固定問題沒有退化，口語問法能更穩定地找到同一條制度。

## 常見問題

<details>

<summary>建立按鈕不可用怎麼辦？</summary>

檢查名稱是否為空，以及所選模型是否仍可用。模型服務未設定時，可以先改為【不使用】完成建立。

</details>

<details>

<summary>不使用嵌入模型會不會完全搜不到？</summary>

不會。知識庫仍會使用 BM25 關鍵詞檢索，問題用詞與資資越接近，結果通常越穩定。

</details>

<details>

<summary>每個主題都要單獨建庫嗎？</summary>

以「使用時是否應該一起檢索」為判斷標準。權限、生命週期或主題完全不同的資資更適合分開。

</details>
