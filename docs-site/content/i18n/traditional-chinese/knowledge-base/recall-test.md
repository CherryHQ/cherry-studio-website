# 檢查資資與召回

召回測試直接檢查「問題能否找到正確片段」，不會先經過聊天模型潤飾。它能幫助你判斷問題出在資資、解析、分塊還是檢索設定。

{% hint style="info" %}
準備 3～5 個你已經知道答案的真實問題，並在每次更新資資、模型或分塊後重複使用。固定問題比臨時試問更容易發現退化。
{% endhint %}

## 準備測試問題

建議同時覆蓋三類問題：

* 精確事實，例如「國內一線城市住宿上限是多少？」
* 條件規則，例如「海外租車在什麼情況下可以報銷？」
* 容易混淆，例如「5000 元以上的出差由誰追加審批？」

不要只用資資標題或整句原文測試，那會高估真實使用效果。

## 完成一次召回測試

{% stepper %}
{% step %}
### 1. 開啟召回測試

開啟左側導覽【知識庫】→ 選擇知識庫 → 進入【召回測試】。
{% endstep %}

{% step %}
### 2. 輸入真實問題

輸入一個答案明確的問題並執行測試。問題應接近日常說法，不要刻意複製資資原文。
{% endstep %}

{% step %}
### 3. 檢查來源和片段

確認來源正確，片段同時包含回答所需的條件和結論。

<figure><img src="../../../assets/b44776524449cdefe62eaed3.webp" alt="檢查資資與召回 — 說明圖片"><figcaption><p>不要只看有沒有結果，還要檢查來源、片段完整度和順序。</p></figcaption></figure>
{% endstep %}

{% step %}
### 4. 對照現象定位問題

完全沒有正確片段時先查資資、解析和分塊；正確片段能出現但順序不穩時，再考慮嵌入、重排或 Top K。
{% endstep %}

{% step %}
### 5. 單項調整並複測

每輪只修改一項設定。涉及解析、分塊或索引時，先執行【重新索引】，再使用同一組問題複測。
{% endstep %}
{% endstepper %}

## 怎樣讀結果

| 現象 | 說明 | 下一步 |
| ------------- | --------------------- | ---------------------- |
| 正確來源排在前面，片段完整 | 召回基本合格 | 再測試幾種不同問法 |
| 完全沒有正確結果 | 資資未就緒、內容缺失、問法差異大或閾值過高 | 依次檢查資資、正文、Chunks 和檢索設定 |
| 來源正確但片段缺少關鍵句 | 解析或分塊邊界不理想 | 查看 Chunks，調整後重新索引 |
| 舊版本和新版本同時出現 | 同名資資被全部保留 | 刪除舊條目或用【替換】重新匯入 |
| 正確項經常靠後 | 候選較多或排序不穩定 | 清理資資，考慮嵌入或重排模型 |
| 召回正確但聊天回答不準 | 問題更可能在提示詞或聊天模型 | 保留召回設定，調整提問和聊天模型 |

{% hint style="warning" %}
聊天模型無法補回召回階段沒有找到的關鍵資資。召回結果不合格時，不要先靠反覆更換聊天模型排錯。
{% endhint %}

## 調優閉環

<figure><img src="../../../assets/8cd27fa50051cc96320b280a.webp" alt="檢查資資與召回 — 說明圖片"><figcaption><p>固定問題 → 檢查結果 → 定位層級 → 單項調整 → 必要時重新索引 → 複測。</p></figcaption></figure>

推薦順序：

1. 確認資資正確，沒有重複或過期版本。
2. 檢查解析正文和 Chunks。
3. 問法與原文差異很大時，考慮嵌入模型。
4. 候選大致正確但順序不穩時，再考慮重排模型。
5. 調整後重新索引，並重複同一組測試。

<figure><img src="../../../assets/5bd8c12bd8d08e785c6a4c42.webp" alt="檢查資資與召回 — 說明圖片"><figcaption><p>片段不完整時再檢查分塊設定；修改只影響新資資，舊資資需要重新索引。</p></figcaption></figure>

## 配置說明

| 配置項 | 產品預設值 | 建議起點 | 作用 | 適用場景 | 注意事項 |
| ------ | ------------ | -------- | ---------- | ---------- | ----------------- |
| 測試問題數量 | — | 3～5 個 | 建立可重複的品質基線 | 所有知識庫 | 覆蓋精確事實、條件規則和易混淆問題 |
| Top K | 6，可選 1～50 | 先保留 6 | 控制最終片段數量 | 覆蓋與噪聲之間取捨 | 調大可能佔用更多上下文 |
| 相似度閾值 | 0.0，僅配置重排後顯示 | 從 0.0 開始 | 過濾重排後的低分結果 | 重排後仍有噪聲 | 設得過高會移除正確片段 |
| 複測方式 | — | 每輪只改一項 | 判斷設定變化來自哪裡 | 調優、更新資資或模型 | 修改分塊或模型後先重新索引 |

## 預期結果

* 正確來源穩定出現在前幾條結果中。
* 片段包含回答問題所需的條件和結論。
* 換一種自然說法後，結果仍然穩定。
* 更新資資或設定後，固定問題沒有明顯退化。

## 用戶案例

小林發現「住宿費標準」用原文能命中，但「住酒店最多能報多少」不穩定。他先確認資資和 Chunks 正常，再配置嵌入模型並複測。正確片段出現後偶爾排在後面，於是才加入重排模型。

完成標準是：三種不同問法都能在前幾條結果中找到同一條住宿標準，且片段包含適用城市和金額上限。

## 常見問題

<details>

<summary>完全沒有正確片段，先調大 Top K 嗎？</summary>

先檢查資資正文和 Chunks。解析或切分錯誤時，調大 Top K 只會返回更多不正確或不完整的片段。

</details>

<details>

<summary>為什麼看不到相似度閾值？</summary>

只有選擇重排模型後，知識庫設定中才會顯示【相似度閾值】。

</details>

<details>

<summary>召回正確，聊天回答仍不準確怎麼辦？</summary>

保留當前召回設定，檢查問題表達、對話上下文和聊天模型。此時問題通常已經不在資資檢索層。

</details>
