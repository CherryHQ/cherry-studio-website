# 在對話中使用

召回測試合格後，可以在一般對話中選擇一個或多個知識庫，讓模型基於召回片段回答並顯示來源。

{% hint style="info" %}
對話負責組織答案，知識庫負責提供證據。先在【召回測試】確認正確片段，再判斷提示詞或聊天模型是否需要調整。
{% endhint %}

## 使用前提

| 檢查項 | 合格狀態 |
| ----- | ---------------- |
| 聊天模型 | 支援工具呼叫 |
| 知識庫資資 | 至少一條資資已就緒 |
| 目前訊息 | 沒有同時附加檔案 |
| 召回品質 | 關鍵問題能找到正確來源和完整片段 |

{% hint style="warning" %}
目前訊息帶有附件時，知識庫選擇會被停用。先移除附件，再從輸入區選擇知識庫。
{% endhint %}

## 完成一次帶來源的問答

{% stepper %}
{% step %}
### 1. 選擇支援工具呼叫的模型

新建或開啟一般對話，在模型選擇器中確認目前模型支援工具呼叫。若知識庫入口提示能力不足，先更換模型。
{% endstep %}

{% step %}
### 2. 開啟知識庫選擇

點擊輸入區左下角的添加按鈕，選擇【知識庫】，再勾選一個或多個目標庫。
{% endstep %}

{% step %}
### 3. 確認選擇狀態

知識庫名稱應出現在輸入區。問題只涉及一個主題時，優先只選一個庫，減少無關片段競爭。

<figure><img src="../../../assets/5baecf3a1e479cb5a9627b45.webp" alt="在對話中使用 — 說明圖片"><figcaption><p>發送前先確認選中的知識庫和目前問題屬於同一資資範圍。</p></figcaption></figure>
{% endstep %}

{% step %}
### 4. 寫清任務、範圍和格式

例如：`只根據已選取的知識庫回答國內一線城市的住宿上限；依不同職級分項列出，並為每一項標註來源。`
{% endstep %}

{% step %}
### 5. 開啟來源核對

檢查來源名稱、片段內容和適用條件。資資未說明的內容，不應被當成事實補全。
{% endstep %}

{% step %}
### 6. 失敗時回到召回測試

用相同問題檢查知識庫返回的片段。召回錯誤先修資資、解析或檢索；召回正確再調整提示詞和聊天模型。

<figure><img src="../../../assets/b44776524449cdefe62eaed3.webp" alt="在對話中使用 — 說明圖片"><figcaption><p>對話回答不理想時，召回結果能幫助判斷問題在檢索層還是回答層。</p></figcaption></figure>
{% endstep %}
{% endstepper %}

## 推薦提問模板

### 查詢一條明確規則

> 只根據已選擇的知識庫回答：國內一線城市住宿上限是多少？如不同職級標準不同，請分項列出，並在每項後標註來源。

### 對比多份資資

> 對比國內出差和海外出差的審批差異。按「觸發條件、審批人、出發前材資」列成表格；資資沒有寫明的地方標記為「未說明」。

### 要求區分事實和建議

> 先列出制度原文支持的事實，再單獨給出操作建議。建議不得寫成制度要求，每條事實保留來源名稱。

{% hint style="success" %}
一個好問題同時包含四件事：要完成的任務、允許使用的資資範圍、期望輸出格式，以及資資缺失時該怎麼處理。
{% endhint %}

## 選擇一個還是多個知識庫

| 情況 | 建議 | 原因 |
| --------- | -------------- | --------------- |
| 單一制度或產品問題 | 只選一個庫 | 減少無關片段競爭 |
| 跨部門或跨產品比較 | 選擇多個庫並說明各自用途 | 幫助模型保持來源邊界 |
| 多庫結果混杂 | 拆成多個問題分別驗證 | 先確認每個庫都能獨立召回 |
| 需要長期多步研究 | 改用綁定知識庫的 Agent | 更適合持續搜尋、整理和交付檔案 |

## 配置說明

| 配置項 | 推薦起點 | 作用 | 注意事項 |
| ----- | ----------- | --------- | ------------ |
| 知識庫數量 | 1 個 | 控制資資範圍 | 只在確有跨庫需求時增加 |
| 提問範圍 | 明確寫「只根據知識庫」 | 減少常識補全 | 重要結論仍需核對來源 |
| 輸出格式 | 表格或分項列表 | 方便逐條驗收 | 要求「未說明」而不是猜測 |
| 回歸問題 | 與召回測試使用同一問題 | 區分檢索和回答問題 | 每輪只改變一個變數 |

## 把對話內容沉澱回知識庫

Cherry Studio 可以把訊息、話題或筆記儲存到知識庫。儲存前刪除模型猜測、重複內容和臨時討論，並使用能說明主題和版本的標題。

儲存後形成新的資資快照，不會與原對話或筆記即時同步。內容更新時需要重新儲存或替換。

## 使用者案例

小林在【員工差旅制度】中提問住宿上限。第一次回答混入了模型常識，他把提示詞改為「資資未說明時寫未說明」，並要求每項保留來源。隨後逐條開啟引用核對城市級別、職級和金額。

完成標準是：每個金額都能由引用片段直接支持，制度未寫明的例外不會被模型自行補全。

## 常見問題

<details>

<summary>知識庫入口為什麼是灰色的？</summary>

先選擇支援工具呼叫的模型，並移除目前訊息附件；再確認存在至少一個有就緒資資的知識庫。

</details>

<details>

<summary>回答為什麼沒有來源？</summary>

確認輸入區仍顯示已選知識庫，再把相同問題放入召回測試。沒有正確召回時先修復知識庫。

</details>

<details>

<summary>來源正確但結論不準確怎麼辦？</summary>

要求模型只依據引用回答，把任務拆成更小的事實項，並人工核對重要結論。此時通常是提示詞、模型能力或上下文組織問題。

</details>
