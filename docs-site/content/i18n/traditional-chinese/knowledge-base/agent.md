# 與 Agent 協同使用

將知識庫綁定至 Agent 後，Agent 可在多步驟任務中搜尋並讀取授權資資；若明確需要更新資資，亦可啟用知識庫管理功能。

{% hint style="info" %}
一般對話適用於單次問答，Agent 則適用於持續研究、比較、產生檔案及逐步驗收。Agent 僅能存取設定中綁定的知識庫。
{% endhint %}

## 一般對話與 Agent 的差異

| 一般對話 | Agent |
| ------------ | --------------- |
| 每則訊息前臨時選擇知識庫 | 在 Agent 設定中長期綁定 |
| 適用於即時問答與短篇幅比較 | 適用於多步驟研究與檔案交付 |
| 主要使用召回片段進行回答 | 可搜尋資資，並依權限管理知識庫 |
| 由當前對話決定資資範圍 | 由 Agent 設定決定可存取範圍 |

## 設定一名唯讀知識庫 Agent

{% stepper %}
{% step %}
### 1. 先確保知識庫驗收合格

確認目標資資已就緒，並使用實際問題完成召回測試。Agent 無法補救缺失的正文或錯誤的分塊。
{% endstep %}

{% step %}
### 2. 開啟 Agent 編輯視窗

進入【工作】，選擇目標 Agent，在選單中開啟【編輯智能體】。
{% endstep %}

{% step %}
### 3. 綁定最小必要的知識庫

開啟【知識庫】分頁，點擊【新增知識庫】。僅綁定本任務所需的知識庫，避免跨部門或跨版本資資相互干擾。
{% endstep %}

{% step %}
### 4. 啟用知識庫搜尋

開啟【內建工具】，啟用【知識庫搜尋】。對於唯讀研究、問答、摘要及比較，通常至此已足夠。

<figure><img src="../../../assets/39a4ea66c712c2736e5ccf34.webp" alt="與 Agent 協同使用 — 說明圖片"><figcaption><p>搜尋用於讀取，管理用於變更資資；預設從最小權限開始。</p></figcaption></figure>
{% endstep %}

{% step %}
### 5. 使用邊界清晰的任務進行測試

要求 Agent 先列出來源，再給出結論；若資資未提供支援，須明確標註，不允許憑常識補全。
{% endstep %}

{% step %}
### 6. 驗收來源與交付物

檢查每條結論來自哪個知識庫，檔案中的事實與建議是否分開，以及缺乏證據的部分是否已標記。
{% endstep %}
{% endstepper %}

<figure><img src="../../../assets/cc38d8a6378ca8270ceda746.webp" alt="與 Agent 協同使用 — 說明圖片"><figcaption><p>查詢資資使用知識庫，重複方法使用技能，存取外部系統使用 MCP；不要以擴大權限來取代明確的任務定義。</p></figcaption></figure>

## 知識庫搜尋與管理

| 功能 | 可執行事項 | 適用任務 | 預設建議 |
| ----- | -------------- | ----------- | ----------- |
| 知識庫搜尋 | 搜尋、列出並讀取已綁定的知識庫 | 問答、研究、摘要、比較 | 保持啟用 |
| 知識庫管理 | 新增、刪除或重新整理知識庫文件 | 經核准的資資維護 | 預設關閉，按需臨時開啟 |

{% hint style="warning" %}
綁定知識庫僅是授予存取範圍，不會複製出另一份知識庫。資資更新或重新索引後，Agent 下次搜尋將使用更新後的內容。
{% endhint %}

{% hint style="danger" %}
啟用【知識庫管理】後，新增、刪除及重新整理將變更資資或索引。核准前請確認目標知識庫、具體項目、同名衝突處理方式及回退方案。
{% endhint %}

## 推薦任務範本

### 研究並產生報告

> 在已綁定的知識庫中找出所有關於海外出差審批與保險的規定。先列出來源與衝突點，再產生 Markdown 檢查清單。沒有資資支援的內容請勿補全。

### 更新常見問題

> 搜尋住宿報銷的現有項目，比較最新制度與舊版 FAQ。先提供擬修改清單；獲得核准後再重新整理相關文件。

### 多知識庫比較

> 分別從「產品手冊」與「售後案例」知識庫尋找證據，依「官方規則 / 真實案例 / 建議話術」三欄整理。每條結論保留來源名稱。

## 設定說明

| 設定項目 | 推薦起點 | 何時增加 | 風險控制 |
| ----- | ---------- | ------------ | ------------- |
| 綁定知識庫 | 1 個任務相關知識庫 | 確有跨庫比較需求 | 在提示詞中寫清每個知識庫的用途 |
| 知識庫搜尋 | 開啟 | 只要任務需要查詢資資 | 驗收來源是否來自綁定範圍 |
| 知識庫管理 | 關閉 | 明確需要新增、刪除或重新整理 | 逐項核准，並先備份重要資資 |
| 輸出要求 | 事實、推斷、建議分開 | 需要產生報告或檔案 | 每條事實保留來源名稱 |

## 使用者案例

小林為售後 Agent 綁定【官方手冊】與【審核案例】，僅啟用知識庫搜尋。他要求 Agent 依設備型號列出安全警告、官方步驟與案例建議，並將三者分開。發現舊案例需要更新時，才臨時開啟管理工具，先查看擬修改清單再核准。

完成標準為：Agent 不存取未綁定的資資，不將案例建議寫成官方規則，所有寫入操作均有明確目標與驗收結果。

## 結果驗收

* 來源僅來自當前 Agent 綁定的知識庫。
* 搜尋結果涵蓋任務中的每個條件。
* 交付物將資資事實、Agent 推斷與建議分開。
* 管理操作已說明目標、影響與結果。
* 更新資資後重新執行固定召回問題。

## 常見問題

<details>

<summary>一般對話能搜尋到，Agent 為什麼搜尋不到？</summary>

檢查目標知識庫是否已綁定至當前 Agent，以及【知識庫搜尋】是否已啟用。不同 Agent 的綁定範圍互不繼承。

</details>

<details>

<summary>什麼時候不該開啟知識庫管理？</summary>

唯讀研究、團隊共享制度庫及保留歷史版本的資資庫，預設均僅開啟搜尋。需要更新時再臨時開啟管理並逐項核准。

</details>

<details>

<summary>Agent 想要操作未綁定的知識庫怎麼辦？</summary>

不要擴大至所有知識庫。確認任務確實需要後，再將目標知識庫加入當前 Agent，或改用已綁定該知識庫的 Agent。

</details>
