# 讓 AI 使用工具

想讓 AI 查一篇網頁、讀取日曆，或把回答儲存成檔案，需要用到工具。工具負責取得資料或執行操作，模型再根據結果繼續回答。你不需要記住工具名稱，說明要處理什麼、希望得到什麼結果即可。

## 我想做的事，需要哪種工具？

| 你想做什麼 | 需要準備什麼 | 具體教程 |
| --- | --- | --- |
| 查資料、閱讀網頁 | 開啟智能體的網路搜尋，配置搜尋與閱讀服務 | [聯網搜尋與網頁閱讀](web-search.md) |
| 查日程、建立會議或整理待辦 | 開啟日曆或提醒事項，並授予系統權限 | [日曆與提醒事項](calendar-and-reminders.md) |
| 獲取當前位置、彙總已記錄的運動 | 開啟對應裝置能力並授權；健康記錄僅限 iOS | [位置與健康記錄](location-and-health.md) |
| 把內容儲存為清單、表格或網頁檔案 | 選擇支援工具呼叫的文字模型 | [生成與修改檔案](file-generation.md) |
| 把 HTML 檔案變成長圖或 PPT | 開啟已儲存的 HTML 檔案，使用分享選單 | [HTML 轉圖片與 PPT](html-export.md) |
| 閱讀或修改飛書、Notion 等服務中的資料 | 連線相應外掛，帳號能夠訪問目標資料 | [外掛與外部工具](plugins.md) |
| 在文字對話中讓 AI 畫圖 | 開啟圖片生成，並設定繪圖模型 | [圖片生成](image-generation.md) |
| 使用別人提供的遠端工具服務 | 新增 MCP 伺服器，並在已儲存的智能體中開啟 | [自訂工具配置](plugins.md) |

除手動進行的檔案轉換外，讓模型呼叫工具都需要它本身支援工具呼叫。只在模型編輯頁勾選能力標記，不能讓不支援的模型獲得這項能力。

## 第一次使用，可以這樣開始

1. 在對話中選擇支援工具呼叫的文字模型。
2. 開啟當前智能體的編輯頁，在 **系統** 區域開啟這次需要的能力；檔案讀寫沒有單獨的系統能力開關。
3. 使用外掛時先連線帳號；使用裝置能力時按提示授權。開啟智能體開關與授予系統權限是兩件事。
4. 先提出一個明確的小任務，檢視工具結果，再繼續下一步。

例如，先發：

> 先列出手機中可寫的日曆，再讀取明天的日程，按開始時間排序並標明所屬日曆。不要建立或修改任何內容。

等結果回來後，再發下面的請求，將“個人”替換為結果中實際可寫的日曆名稱。沒有可寫日曆時，先在系統日曆中配置：

> 在剛才列出的“個人”日曆裡，明天北京時間下午三點到三點半建立“整理資料”。請告訴我是否儲存成功。

這種分步提問有助於核對物件。希望執行前由 App 彈出審批時，還應把智能體的工具審批方式改為 **需要時確認**；文字裡的“先確認”不能代替審批設定。

## 怎樣把需求說清楚？

可以使用這個順序：**資料在哪裡 → 時間或內容範圍 → 要做的事 → 輸出形式 → 是否現在修改**。

* “閱讀這篇飛書文件：[連結]。只整理第二部分，列出負責人、事項、截止日期；沒有寫的標為待確認。先不要建立任務。”
* “根據我上傳的清單生成一個 CSV 表格檔案，列為物品、數量、備註，儲存為出行清單.csv。”
* “查上海人民廣場到虹橋站的公共交通路線，列出換乘和預計時間。不需要獲取手機位置。”

檔案、網頁、日曆與外掛可以在同一任務中配合，但各自都需要可用。能讀到文件不代表可以建立任務，拿到當前位置也不代表已經接入路線查詢服務。

## 為什麼有些操作會詢問，有些不會？

| 操作 | 使用“需要時確認”時 |
| --- | --- |
| 內建搜尋、讀取檔案、讀取已授權裝置資料 | 通常直接執行 |
| 內建建立或修改文字檔案 | 直接執行，也不會因為選擇該模式就逐次詢問 |
| 建立、修改、刪除系統日曆或提醒事項 | 需要工具審批 |
| 外掛與自訂工具 | 受工具規則控制，可能需要審批 |
| 透過文字模型呼叫圖片生成工具 | 每次需要審批，“自動批准”模式下也一樣 |

**自動批准**會自動透過符合條件的審批，仍不能越過帳號權限或系統權限。當前新建智能體預設使用這個模式。詳見[智能體與工具](agents-and-tools.md)。

## 怎樣知道任務真的完成了？

回答中的處理過程會顯示工具操作。工具還在準備內容、等待批准，或者要求你到系統頁面繼續時，都不能當作已經完成。

* **讀取成功**：核對資料來源和查詢範圍，再看總結；沒有記錄不一定代表不存在記錄。
* **檔案建立成功**：應能開啟生成的檔案卡片或在側邊欄的檔案中找到它。只有程式碼塊或“已生成”的文字，還不能證明檔案已儲存。
* **寫入外部服務成功**：核對工具返回的結果，需要時到對應日曆、文件或任務中檢視。
* **部分失敗**：先分清哪些已完成，哪些沒有完成，只補做剩餘部分。

## 卡住、拒絕或失敗後怎麼辦？

| 現象 | 下一步 |
| --- | --- |
| 只用文字回答，沒有呼叫工具 | 明確要求讀取或儲存；檢查模型、能力開關和工具連線 |
| 等待你的確認 | 閱讀操作物件與內容，再允許或拒絕；系統授權可能還需另行完成 |
| 權限不足 | 在系統設定或服務商中處理權限；反覆改寫提問不會增加權限 |
| 搜尋、讀取失敗 | 根據提示檢查網路、目標連結和帳號，縮小範圍後再試 |
| 寫入超時，結果不確定 | 先到目標服務核對，避免重複建立日程、任務或內容 |
| Android 開啟了系統日曆 | 在日曆頁面核對並完成操作；開啟頁面不等於儲存成功 |

停止回答、刪除聊天或重新回答，都不會撤銷已經完成的外部操作。工具取得的資料也可能交給模型處理，詳見[資料、隱私與權限](data-privacy.md)。
