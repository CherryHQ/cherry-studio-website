# 網路搜尋與網頁閱讀

想了解最新資訊，或讓 AI 閱讀一個網頁時，可以使用聯網工具。搜尋負責“找到相關頁面”，網頁閱讀負責“取出指定連結裡的正文”，兩者可以使用不同服務。

## 先試一次搜尋

1. 選擇支援工具呼叫的文字模型，並確認當前智能體編輯頁的 **網路搜尋** 已開啟。
2. 傳送“搜尋一下這個專案最近釋出了什麼，並附上來源”，或“閱讀這個連結並總結要點：[網頁連結]”。
3. 在回答中檢視搜尋過程與來源，點選來源開啟原網頁。

新安裝通常已預選 ExaMCP 搜尋和 Jina 網頁閱讀，不要求先填寫個人金鑰。已有使用者保留自己的選擇。預設服務也受網路和服務自身限制影響，失敗時可到設定中檢查或更換。

當前輸入框沒有獨立的聯網搜尋開關；在智能體編輯頁開啟 **網路搜尋**、配置好服務後，直接在訊息中要求搜尋即可。是否真正使用了搜尋，應看回答中的工具過程和來源，不能只看模型說“我查到了”。

## 更換搜尋或網頁閱讀服務

開啟 **設定 → 網路搜尋**：

* **搜尋服務商**：根據關鍵詞尋找資料。
* **URL 獲取服務商**：URL 就是網頁連結，這裡決定由誰讀取網頁正文。

1. 選擇所需服務。
2. 頁面要求金鑰或地址時，填寫該搜尋服務提供的內容。
3. 使用 **檢查** 確認配置，再回到對話傳送新的問題。

選擇服務商會立即儲存；金鑰輸入結束、離開輸入框時提交。高階設定中的選項和有效數字也會在選擇或結束編輯後儲存，沒有單獨的頁面儲存按鈕。遇到錯誤提示時先修正再試。

模型服務商金鑰和搜尋服務金鑰通常不是一回事。使用智譜搜尋時，頁面會引導你到模型服務中配置智譜金鑰；其他服務按各自表單填寫。

## 高階設定需要改嗎？

初次使用保留預設即可。搜尋效果有明確問題時，再調整：

| 設定 | 作用 | 取捨 |
| --- | --- | --- |
| 搜尋結果個數 | 一次返回多少條結果 | 更多結果可能提供不同視角，也會增加需要處理的材料 |
| 搜尋結果壓縮 | 決定是否截斷送給模型的搜尋正文 | 截斷可減少用量；不壓縮不表示模型能讀無限長內容 |
| 搜尋正文總量 | 限制保留下來的正文總長度 | 限制較小時，更容易遺漏網頁後面的資訊 |

網頁閱讀也有自己的內容上限，長頁面可能只讀取一部分。需要逐項核對時，開啟原網頁檢視；反覆讀取同一連結不會自動接著讀取後半部分。

## 為什麼模型能聊天，卻不能搜尋？

對話模型、搜尋服務和網頁閱讀服務是分別連線的。對話可用不代表另外兩個服務的網路和憑據正常。

按這個順序排查：

1. 模型是否支援工具呼叫，當前智能體的 **網路搜尋** 是否開啟。
2. 網路搜尋設定中是否選了可用服務，檢查能否透過。
3. 問題是否需要搜尋，是否明確給出了關鍵詞或連結。
4. 檢視工具錯誤：網路、金鑰、帳戶權限、額度或網頁訪問限制分別處理。

某次搜尋或網頁讀取失敗後，這輪迴答會停止新的聯網嘗試，儘量使用已取得的資料並說明缺失資訊，不會悄悄換成另一個搜尋服務。修復問題後傳送一條新訊息再試。

## 為什麼無法讀取登入後的網頁？

網頁閱讀服務從自己的網路訪問連結，不會自動帶上你手機瀏覽器中的登入狀態。需要登入、企業權限或有訪問限制的頁面，可能無法讀取。

飛書、Notion 等帳號裡的資料，優先使用[對應外掛](plugins.md)。也可以把自己有權使用的內容匯出為檔案，按[對話與檔案](chat-and-files.md)中的步驟新增。

## 資料會發給誰？

搜尋關鍵詞和待讀取的連結會發給所選搜尋或閱讀服務，得到的資料會參與模型回答。不要在搜尋關鍵詞里加入金鑰或不需要公開檢索的內部內容。有關其他資料用途，見[資料、隱私與權限](data-privacy.md)。
