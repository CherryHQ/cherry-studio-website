# 功能差異

V2 調整了資資結構與多項功能入口。升級前請先查看需要重新設定的項目；具體步驟請見 [【V1 升級到 V2】](v1-to-v2-migration.md)。

## V2.0.2 遷移變化

| 情況 | V2.0.2 的處理方式 | 注意事項 |
| --------- | ----------------------- | ------------------------------ |
| 首次從 V1 遷移 | 可以直接從 V1.9.13 安裝 V2.0.2 | 不再需要先安裝 V2.0.0。 |
| 正常升級 V2 | 直接升級並繼續使用目前 V2 資資 | 不要點擊【重新遷移】。 |
| 重新遷移 V1 | 在【設定】→【資資】選擇【重新遷移】 | 目前 V2 資資會被永久刪除，僅用於此前遷移失敗或遺漏資資的情況。 |

{% hint style="danger" %}
【重新遷移】不會將 V1 資資補充合併到目前的 V2。它會先刪除目前 V2 資資，再從保留的 V1 資資重新匯入。如果不是 V1 遷移失敗或遺漏資資的情況，請務必不要點擊。
{% endhint %}

## 資資如何處理

| 處理方式 | 資資範圍 | 升級後要做什麼 |
| ---- | --------------------------------------------------------------------- | ------------- |
| 自動遷移 | 設定、模型服務與模型、助手與分組、對話與訊息、Agent 與對話、MCP、知識庫及有效索引、檔案、繪圖、翻譯、筆記、提示詞、用量記錄 | 抽樣檢查常用項目能否正常開啟。 |
| 需要覆核 | Anthropic 憑證、網路搜尋預設服務、Agent 工具權限與知識庫綁定、提示詞順序、知識庫失敗項目、自訂 CSS、側邊欄收藏、缺失檔案 | 依下表重新確認。 |
| 不會繼承 | Agent 排程任務歷史記錄、舊版網站地圖展開結果、部分臨時圖片引用、筆記目前開啟狀態、已移除功能的設定 | 需要時重新建立。 |

{% hint style="info" %}
遷移不會刪除 V1 原始資資。V2 新資資不會同步回 V1，兩個版本的備份也不能相互還原。
{% endhint %}

## 主要差異

| 功能 | V1 | V2 | 升級後要做什麼 |
| --------------- | ------------------------------- | --------------------------------------------- | -------------------------------- |
| 助手與提示詞 | 獨立助手庫；快捷短語可與助手關聯 | 助手在聊天和 Agent 中管理；快捷短語合併為全域提示詞 | 檢查助手分組和提示詞順序。 |
| Agent | 部分設定和工作區跟隨對話；舊授權可自動核准工具 | 身份、記憶和主要設定歸 Agent；對話建立後工作區固定；工具可能重新請求授權 | 檢查模型、工作區、工具和權限。 |
| Agent 知識庫 | 知識工具可能存取全域知識庫 | 只存取明確綁定的知識庫 | 為每個 Agent 重新核對知識庫綁定。 |
| 知識庫檢索 | 可手動選擇檢索模式和網站地圖來源 | 無嵌入模型時使用 BM25，有嵌入模型時使用混合檢索；網站地圖按一般網址處理 | 檢查嵌入與重排序模型；重建失敗來源。 |
| 網路搜尋 | 可在助手或輸入區選擇服務；含本地搜尋、RAG 壓縮和訂閱黑名單 | 在【設定】→【網路搜尋】分別設定關鍵字搜尋和網址讀取；相關舊選項移除 | 重新選擇兩項預設服務並檢查憑證。 |
| MCP | 已新增服務和第三方發現市場並存 | 已新增服務繼續遷移；舊第三方發現市場不再提供 | 檢查服務狀態；新服務從目前市場或 JSON 新增。 |
| 模型服務 | Anthropic 可儲存 OAuth 憑證 | Anthropic OAuth 不遷移；AWS Bedrock 區域保留；新增服務預設關閉 | 為 Anthropic 重新填寫 API Key，按需啟用服務。 |
| 檔案 | 檔案副本與業務物件的引用關係較弱 | 託管檔案按引用管理；最後一個引用刪除後會延遲清理託管副本 | 長期保留的檔案放入【檔案】或匯出；使用者原始檔案不會被刪除。 |
| 繪圖、Mini App 與側邊欄 | 參數和入口位於舊版區域 | 繪圖參數移到提示詞工具列；Mini App 在頂部標籤列；側邊欄收藏重設 | 熟悉新入口並重新設定收藏。 |
| 自訂 CSS | V1 選擇器直接生效 | 內容保留，但遷移後預設停用 | 依 V2 選擇器適配後再啟用。 |
| Code CLI | 可選擇 iFlow | iFlow 由 Qoder 取代 | 需要相關工作流時改用 Qoder。 |

## 開發者相容性

<details>

<summary>API 與外部整合有哪些變化？</summary>

* API Gateway 的模型識別碼由 `provider::model` 改為 `provider:model`。
* Knowledge API 回傳項目使用 V2 欄位。
* MCP-over-HTTP 端點已移除，不影響應用內 MCP。
* SSE 啟動失敗可能直接回傳一般 HTTP 錯誤，客戶端需同時相容 HTTP 與 SSE 錯誤路徑。
* 排程任務介面參數已變化，歷史執行記錄不會遷移。

</details>
