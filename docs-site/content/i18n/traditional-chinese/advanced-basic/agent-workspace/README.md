# Agent 工作區

Agent 適合處理有明確目標、需要使用工具或檔案、可能持續多個步驟的任務。入口是左側導覽【工作】，不是舊版教學中的頂部標籤。

{% hint style="success" %}
最省事的設定方式，是先告訴 Agent 你想完成什麼，再讓它檢查缺少的模型、工具、知識庫或頻道。需要精確控制時，再開啟 Agent 編輯視窗或【設定】手動調整。
{% endhint %}

### 工作區由什麼組成

| 部分 | 作用 | 何時需要關注 |
| ----- | ----------------- | ----------------- |
| Agent | 保存角色、模型、提示詞與能力 | 同一類工作要重複進行時 |
| 任務 | 一次連續的工作記錄 | 每個目標單獨開任務，便於保留上下文 |
| 工作目錄 | Agent 可以直接處理的檔案範圍 | 程式碼、資資整理、文件產生等檔案任務 |
| 輸入區 | 發送目標、附件並調用工具 | 發起任務或追加要求 |
| 右側面板 | 查看狀態、檔案、子任務和訊息流 | 追蹤長任務、檢查產物或排錯 |

### 開始一個任務

{% stepper %}
{% step %}
#### 1. 開啟【工作】並選擇 Agent

已有合適的 Agent 時直接選擇；沒有時點擊【新增智能體】，在【基礎資訊】中先選擇執行模式，再完成系統提示詞、技能和知識庫四步建立。執行模式建立後不能切換。
{% endstep %}

{% step %}
#### 2. 選擇工作目錄

需要處理本機檔案時，選擇本次任務所在目錄；不涉及檔案時可以使用應用程式建立的預設工作區。一個任務對應一個工作區，避免讓 Agent 在不相關目錄間來回查找。
{% endstep %}

{% step %}
#### 3. 用結果描述任務

告訴 Agent 要交付什麼、可以使用哪些資資、有哪些限制以及怎樣算完成。例如：

```
閱讀目前目錄中的會議記錄，整理出決策、負責人和截止時間，產生 action-items.md。不要修改原始檔案。
```
{% endstep %}

{% step %}
#### 4. 在右側面板檢查過程與產物

【狀態】展示活動任務、子智能體、工作流和背景命令；【檔案】可預覽並編輯文字產物；開啟開發者模式後還能查看【調用鏈】。
{% endstep %}
{% endstepper %}

### API 閘道提示

Agent 執行依賴 Cherry Studio 的 API 閘道。閘道未啟用時，應用程式會提示【啟用並啟動】；也可以到【設定】→【API 閘道】檢查埠號、執行狀態和本機安全軟體攔截。

{% hint style="warning" %}
API 閘道是 Agent 的執行依賴，但不等於要把介面公開到網路。保持預設本機使用即可；只有明確要讓其他程式調用時，才需要複製 URL 和 API 金鑰。
{% endhint %}

### 一個 Agent 還是多個 Agent

* 同一角色、同一套能力但任務不同：複用一個 Agent，新建多個任務。
* 角色、資資範圍或權限不同：拆成多個 Agent。
* 一個目標需要並行研究或多個步驟協作：先讓一個 Agent 使用子智能體或工作流，不必立刻手動建立很多 Agent。

### 使用者案例：整理專案資資

產品經理把需求說明、訪談記錄和競品資資放在同一目錄，建立「需求整理」Agent，綁定產品知識庫並使用【逐次確認】權限。Agent 先讀取資資，再將需求清單和待確認問題寫入新檔案。產品經理在右側【檔案】中直接修訂文字，原始資資保持不變。

<details>

<summary>為什麼 Agent 看不到剛綁定的能力？</summary>

Agent 編輯內容會自動保存。正在產生的回覆不會被中斷；模型、技能、MCP 和知識庫等變化會從下一條訊息開始生效。若仍未出現，先確認能力已啟用，再新發一條訊息。

</details>

<details>

<summary>刪除工作目錄會把磁碟檔案一起刪除嗎？</summary>

在任務列表中刪除工作目錄時，只會移除 Cherry Studio 中的目錄記錄和該目錄下的任務記錄，不會刪除磁碟上的真實目錄。Agent 在任務執行中進行的檔案操作仍受所選權限模式影響。

</details>
