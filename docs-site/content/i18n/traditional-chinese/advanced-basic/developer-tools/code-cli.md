# 編碼搭檔（Code CLI）

【編碼搭檔】用於安裝、設定和啟動常見程式設計命令列工具。Cherry Studio 會區分應用程式託管版本、系統 PATH 中已有版本和工具自身的帳號登入，不會自動覆蓋系統安裝。

<figure><img src="../../../../assets/2e66cc9312c27cf740b2eb62.webp" alt="編碼搭檔（Code CLI） — 說明圖片"><figcaption><p>① 左側選擇工具並確認安裝狀態；② 右側選擇統一閘道、工具官方帳號或相容的模型服務。</p></figcaption></figure>

### 頁面能做些什麼

* 檢查工具是否已安裝以及是否有可用更新；
* 安裝、更新或移除 Cherry Studio 託管的工具副本；
* 偵測系統 PATH 中已有的工具；
* 為需要模型服務的 CLI 選擇服務供應商、模型和參數；
* 為使用自身帳號登入的 CLI 保留原生登入方式；
* 選擇工作目錄和系統偵測到的終端機後啟動。

頁面包含 Claude Code、OpenAI Codex、Gemini CLI、OpenCode、Qwen Code、Kimi Code、Qoder CLI、GitHub Copilot CLI、Pi 和 DeepSeek Harness 等工具。實際可見項目會隨產品更新變化，以頁面列表為準。

### 通用啟動流程

{% stepper %}
{% step %}
#### 1. 從【啟動台】開啟【編碼搭檔】

選擇需要的工具，先查看狀態是未安裝、由 Cherry Studio 託管，還是來自系統。
{% endstep %}

{% step %}
#### 2. 完成安裝或登入

未安裝時點擊【安裝】。由工具自身提供帳號登入的 CLI，按照頁面提示完成原生登入，不需要從 Cherry Studio 選擇服務供應商。
{% endstep %}

{% step %}
#### 3. 設定模型連線

需要 Cherry Studio 模型服務的工具，可選擇【統一閘道】或相容的服務供應商和模型。頁面會依 CLI 所需的介面類型篩選，不相容的服務供應商不會列出。
{% endstep %}

{% step %}
#### 4. 選擇目錄和終端機

工作目錄決定 CLI 啟動位置。終端機只能從系統偵測到的列表中選擇；啟動後先用唯讀命令確認目前路徑。
{% endstep %}

{% step %}
#### 5. 啟動並驗證

點擊【啟動】，確認帳號或模型正確，再執行檔案修改或命令。需要調整推理強度、權限或工具專屬選項時，開啟【設定】。
{% endstep %}
{% endstepper %}

### DeepSeek Harness

<figure><img src="../../../../assets/ceedc835426c7413a36609ba.webp" alt="編碼搭檔（Code CLI） — 說明圖片"><figcaption><p>① 未安裝時先完成託管安裝；安裝後設定相容服務供應商、預設權限和 Agent 模式，再啟動 Web UI。</p></figcaption></figure>

DeepSeek Harness 與一般終端機 CLI 的流程不同：安裝並選擇服務供應商後，由 Cherry Studio 託管執行，並可開啟獨立 Web UI。參數中可以選擇預設 Agent 模式和預設權限：

| 設定 | 適合情況 | 注意事項 |
| -------- | -------------------------- | ------------- |
| 【標準】 | 檔案、Shell、檢索、技能、計畫和子代理都可能使用 | 工具面最大，先使用受控權限 |
| 【PTC 程式碼】 | 需要透過 Code Mode 組合多步工具操作 | 更適合複雜編碼任務 |
| 【極簡】 | 只需要持久 Shell 和文字編輯器 | 依賴少，能力範圍也更小 |
| 【唯讀】 | 檢查專案、不寫入檔案 | 有風險操作仍會請求確認 |
| 【工作區寫入】 | 允許修改目前 DSH 工作區 | 不代表可以存取工作區外檔案 |
| 【完全存取】 | 隔離、可信、可恢復的環境 | 不請求操作確認，風險最高 |

### 安裝來源要分清

| 來源 | Cherry Studio 會做些什麼 | 你應該如何維護 |
| ---------------- | ------------------ | ----------------- |
| Cherry Studio 託管 | 安裝、更新和卸載對應託管副本 | 在【編碼搭檔】或【環境相依】中管理 |
| 系統 PATH | 偵測並直接使用，不覆蓋 | 用原套件管理器更新或卸載 |
| 工具官方帳號 | 保留工具自身的登入流程 | 在工具介面管理帳號和授權 |

<figure><img src="../../../../assets/2e66cc9312c27cf740b2eb62.webp" alt="編碼搭檔（Code CLI） — 說明圖片"><figcaption></figcaption></figure>

{% hint style="warning" %}
卸載 Cherry Studio 託管副本後，如果系統中還有同名可執行檔，頁面會自動回退到系統版本。行為變化時，先確認目前使用的是哪一種來源。
{% endhint %}

### 使用者案例：在專案目錄啟動編碼工具

開發者先選定目前專案目錄，選擇一個已經驗證的模型連線，再啟動 Pi 或其他 CLI。第一條命令只讀取儲存庫狀態；確認帳號、模型與目錄無誤後，再允許工具修改檔案並執行檢查。

Cherry Studio 從登入環境和標準位置偵測工具。確認命令在登入終端機中可執行，然後重新啟動應用程式刷新環境。便攜式或非標準路徑目前需要從該終端機手動啟動。
