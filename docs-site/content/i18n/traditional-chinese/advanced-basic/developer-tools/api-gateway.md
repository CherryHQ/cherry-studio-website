# API 閘道

API 閘道將 Cherry Studio 已配置的模型能力透過 OpenAI 和 Anthropic 相容的 HTTP API 提供給本機程式。它也是 Agent 執行所需的內部服務。

路徑：【設定】→【API 閘道】。

<figure><img src="../../../../assets/69025f11c87bd83f70af4a07.webp" alt="API 閘道 — 說明圖片"><figcaption><p>外部程式連線前先檢查狀態和埠號；金鑰只提供給可信的本機程式或受控網路。</p></figcaption></figure>

## Agent 使用與外部呼叫要區分

* 只使用 Cherry Studio Agent：依應用程式提示【啟用並啟動】即可，不需要將 URL 或金鑰複製給其他程式；
* 本機程式需要呼叫 Cherry Studio：啟動閘道，複製 URL 和 API 金鑰，並依 API 文件選擇相容介面；
* 要讓其他裝置存取：這會擴大暴露範圍，需要自行確認網路監聽、防火牆和存取控制，不建議在沒有安全措施時開放。

## 啟動與連線

{% stepper %}
{% step %}
### 1. 檢查埠號

閘道停止時可以修改埠號。選擇未被其他程式佔用的埠號；埠號衝突時服務無法正常啟動。
{% endstep %}

{% step %}
### 2. 啟動閘道

點擊【啟動】，狀態變為【執行中】後，頁面會顯示可用 URL，並提供【API 文件】入口。
{% endstep %}

{% step %}
### 3. 設定授權

外部程式使用 `Authorization: Bearer <API 金鑰>`。頁面可以直接複製授權標頭，不要把金鑰寫入程式碼儲存庫或截圖。
{% endstep %}

{% step %}
### 4. 用最小請求驗證

先按照 API 文件請求模型清單或傳送短文字，再接入完整應用程式。出現錯誤時記錄 HTTP 狀態和回應，不公開完整授權標頭。
{% endstep %}
{% endstepper %}

## 使用情境：讓本機腳本呼叫模型

先在【設定】→【模型服務】確認模型可以正常對話，再啟動 API 閘道。腳本只儲存本機閘道位址和金鑰，先請求模型清單，再傳送一句短文字。接入完整程式前，確認客戶端支援 OpenAI 或 Anthropic 相容介面。

| 設定 | 建議起點 | 作用 | 注意事項 |
| ------ | ---------- | --------- | ----------------- |
| 監聽範圍 | 僅本機使用 | 減少網路暴露 | 不為方便除錯直接開放到區域網路或公網 |
| API 金鑰 | 為目前閘道單獨保管 | 驗證客戶端請求 | 不寫入儲存庫、截圖或共用日誌 |
| 驗證請求 | 先查模型清單和短文字 | 分開驗證連線與生成 | 失敗時記錄狀態碼，不記錄完整金鑰 |

### 完成標準

閘道顯示【執行中】；模型清單可讀取；短文字請求成功；停止閘道後客戶端無法繼續呼叫。

## 安全操作

{% hint style="danger" %}
API 金鑰可以呼叫你在 Cherry Studio 中配置的模型服務。金鑰洩露後，應先停止閘道，在停止狀態下點擊【重新產生】，再更新所有本機客戶端。
{% endhint %}

* 閘道執行時埠號和金鑰保持唯讀，修改前先停止；
* 不在公共儲存庫、Issue、日誌或教學截圖中展示金鑰；
* 只給需要呼叫的程式儲存金鑰；
* 用量和費用仍由實際模型服務商產生，可在【設定】→【用量統計】查看 Cherry Studio 記錄。

<details>

<summary>API 閘道與模型服務有什麼關係？</summary>

模型服務儲存上游服務商連線；API 閘道將這些能力轉換成相容介面。閘道本身不提供模型，仍需要至少一個可用服務商和模型。

</details>

<details>

<summary>埠號正常但客戶端回傳未授權怎麼辦？</summary>

確認請求標頭是 `Authorization: Bearer ...`，沒有多餘引號或空格，並檢查客戶端使用的金鑰是否仍是頁面目前值。

</details>
