# 私有知識庫問答

人事團隊希望同事能查詢現行制度，但不希望 Agent 使用常識補寫答案。此案例將資資範圍、召回測試與回答規則整合在一起；當找不到內容時，Agent 應明確說明。

## 操作流程

{% stepper %}
{% step %}
### 1. 建立主題單一的知识庫

將現行資資集中存放，移除重複與過期版本。檔案名稱應清楚標示主題與生效範圍。
{% endstep %}

{% step %}
### 2. 使用真實問題進行召回測試

至少測試容易混淆的條款、口語化問法以及沒有答案的問題。調整資資或 RAG 設定，直到返回片段穩定為止。
{% endstep %}

{% step %}
### 3. 建立專用 Agent

僅綁定此套知識庫，並在提示詞中要求「優先引用資資；找不到時說明未找到；不要使用常識補寫制度」。權限保持最小範圍。
{% endstep %}

{% step %}
### 4. 從小範圍開始使用

先用於內部查找，不直接取代審批或專業判斷。收集答錯的問題，回到資資與召回測試中進行修正。
{% endstep %}
{% endstepper %}

## 示例問題規則

```
回答時先給結論，再註明資資名稱和相關段落。資資之間有衝突時列出衝突，不要代替我們選擇。知識庫沒有答案時明確寫出「目前資資中找不到」。
```

## 推薦組合與完成標準

| 項目 | 建議做法 |
| ----- | --------------------------- |
| 知識庫 | 一個主題一套資資，刪除重複與過期版本 |
| 召回測試 | 同時測試標準問法、口語問法以及沒有答案的問題 |
| Agent | 僅綁定所需的知識庫，要求引用資資且不補寫 |
| 完成標準 | 能找到正確段落；衝突資資會列出；沒有答案時明確說明未找到 |

{% hint style="danger" %}
私有知識庫中的內容將由您選擇的嵌入模型與對話模型服務處理。使用前請確認資資的保密要求與服務範圍，切勿將金鑰與帳號憑證作為知識資資匯入。
{% endhint %}
