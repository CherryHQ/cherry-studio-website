# 多模型研究回顧

一個產品團隊準備進行季度回顧：內部資資已經齊全，但還需要補充公開資訊，並比較不同模型給出的觀點。最終要交付一份能回到來源核對、明確區分事實與判斷的研究報告。

## 推薦組合

* 【對話】多模型：找出共識、分歧和遺漏；
* 研究 Agent：推進任務、拆分子任務並生成報告；
* 知識庫：檢索內部資資；
* 網頁搜尋或可信 MCP：補充外部來源；
* 工作目錄：保存原始材資和最終產物。

## 操作流程

{% stepper %}
{% step %}
### 1. 用同一問題比較觀點

在【對話】中選擇多個模型，要求分別列出結論、假設、來源和不確定項。把真正的衝突整理成待研究問題。
{% endstep %}

{% step %}
### 2. 建立研究 Agent

綁定相關知識庫和研究技能，權限保持【逐次確認】。工作目錄中把原始資資與 `report/` 輸出目錄分開。
{% endstep %}

{% step %}
### 3. 分配子任務

讓 Agent 分別檢查事實時間軸、數據變化和外部觀點，再由主 Agent 比較衝突。不能確認的資訊保留為待核對，不強行合併。
{% endstep %}

{% step %}
### 4. 生成報告並人工複核

報告包含結論、來源、不確定項和後續行動。在右側【檔案】檢查引用、日期和數字後再發布。
{% endstep %}
{% endstepper %}

## 示例任務

```
複盤目前目錄中的專案資資，並補充公開資訊。將事實、判斷和建議分開撰寫；外部資訊要保留來源連結。分別檢查時間線、資資和風險，最後在 report/review.md 產生報告。不要修改 raw/ 中的檔案。
```

## 使用前準備與完成標準

| 項目 | 建議準備 |
| ---- | ------------------------------- |
| 研究問題 | 一句話寫清要比較的結論 |
| 來源要求 | 指定時間範圍、地區和可接受來源 |
| 推薦組合 | 多模型對比用於收集差異，分支用於追問，筆記用於保存確認後的結論 |
| 完成標準 | 每個關鍵結論能回到來源；分歧單獨列出；未確認內容不寫成事實 |

這個案例適合需要比較觀點、回顧決策過程的研究，不適合把多模型投票直接當成事實判斷。

{% hint style="danger" %}
金融、醫療、法律等高風險主題不能只依賴模型結論。報告應保留來源，並由具備相應經驗或資質的人複核。
{% endhint %}
