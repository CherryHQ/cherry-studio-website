# Agent 專案檔案交付

營運同事要把一批零散資資整理成索引、摘要和交付檔案。為了避免誤改原件，需要把 Agent 的工作目錄、可修改範圍和驗收方式提前說清楚。

## 適合的任務

* 把零散資資整理成目錄和索引；
* 根據模板生成多份文件；
* 修改程式碼並留下變更說明；
* 批次改名、轉換或檢查檔案。

## 操作流程

{% stepper %}
{% step %}
### 1. 選擇最小工作目錄

只選擇目前專案目錄。重要檔案先有備份或版本記錄，權限從【逐次確認】開始。
{% endstep %}

{% step %}
### 2. 明確可改與不可改範圍

寫清哪些檔案只能讀取、產物放在哪裡、哪些操作必須先確認，以及完成標準。
{% endstep %}

{% step %}
### 3. 先讓 Agent 列計畫

高風險任務可使用【僅規劃】。確認檔案清單和步驟後，再切換到允許編輯的模式執行。
{% endstep %}

{% step %}
### 4. 在右側檢查狀態和檔案

長任務先看【狀態】是否等待核准；產物生成後在【檔案】中預覽。確認無誤再移交，不以「任務結束」代替驗收。
{% endstep %}
{% endstepper %}

## 示例任務

```
整理目前目錄。raw/ 中的檔案只能讀取；在 deliverables/ 下建立索引、摘要和缺少資資清單。任何刪除、覆寫或批次重新命名都要先取得確認。最後列出新增和修改的檔案。
```

## 推薦組合

| 能力 | 建議用法 | 為什麼 |
| ---- | ------------ | ----------------- |
| 工作目錄 | 每個專案使用獨立目錄 | 檔案邊界和交付位置清楚 |
| 權限 | 修改檔案保持【逐次確認】 | 便於發現誤刪、覆蓋和越界寫入 |
| 狀態面板 | 結束前檢查產物和失敗步驟 | 不只以「Agent 說完成了」為準 |
| 新任務 | 新階段或新客戶另開任務 | 避免歷史要求影響當前交付 |

{% hint style="danger" %}
【完全存取】會減少確認，但也擴大誤操作影響。只有在隔離、可信且可恢復的目錄中，才考慮臨時使用。
{% endhint %}
