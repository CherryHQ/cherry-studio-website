# 長文件審閱

產品經理收到一份篇幅較長的方案，需要找出事實問題、結構缺口和可執行修改，同時保留原稿和人工確認過程。下面的做法適合報告、制度、投標材資和產品方案。

## 推薦組合

* 【對話】：快速比較不同模型的審閱角度；
* 【工作】Agent：讀取工作目錄並生成修訂稿；
* 知識庫：提供制度、術語或歷史資資；
* 右側【檔案】：檢查原稿與產物。

## 操作流程

{% stepper %}
{% step %}
### 1. 準備原稿和審閱標準

把原稿放入獨立工作目錄，另建一份簡短的審閱說明，寫清讀者、目的、不能改動的事實和交付格式。
{% endstep %}

{% step %}
### 2. 先做小範圍校準

選一個章節，讓 Agent 按「問題、原文位置、影響、建議」輸出。確認尺度合適後再處理全文。
{% endstep %}

{% step %}
### 3. 分開事實與表達

要求 Agent 把需要查證的事實單獨列出，不用語言潤飾掩蓋不確定內容。關鍵數字回到原資資核對。
{% endstep %}

{% step %}
### 4. 生成新檔案並人工定稿

要求保留原檔案，在 `review/` 下生成問題清單和修訂稿。用右側【檔案】逐段檢查，再匯出或分享。
{% endstep %}
{% endstepper %}

## 示例任務

```
審閱目前目錄中的 proposal.docx。先依章節列出事實問題、結構缺口和表達問題，並註明原文位置。不要修改原始檔案；確認清單後，在 review/ 下產生修訂稿和待核對事項。
```

## 使用前準備與完成標準

| 項目 | 建議準備 |
| ---- | -------------------------------- |
| 檔案 | 原文、審閱要求和輸出目錄分開放置 |
| 推薦組合 | 專用 Agent + 只含本專案檔案的工作目錄 + 【逐次確認】 |
| 抽樣方式 | 先抽樣一章，確認引用格式和判斷尺度 |
| 完成標準 | 每條意見帶原文位置；未讀取部分明確標記；原檔案未被覆蓋 |

適合合約、報告、論文或規範的結構化審閱；涉及法律、醫療、財務結論時，輸出只能作為輔助材資。

{% hint style="info" %}
文件很長時，不要在一個對話裡反覆貼上全文。讓 Agent 直接讀取工作目錄，並按章節留下中間產物，更容易覆核和恢復。
{% endhint %}
