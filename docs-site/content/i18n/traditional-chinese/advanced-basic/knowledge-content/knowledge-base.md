# 建立知識庫與召回測試

知識庫將檔案、網頁和筆記處理成可檢索的片段。它適合回答「資資中如何說明」，不等於讓模型永久記住整份文件。

## 新增並匯入資資

{% stepper %}
{% step %}
### 1. 開啟【知識庫】→【新增知識庫】

填寫容易辨識的名稱，並選擇可用的嵌入模型。嵌入模型負責將資資轉換為可搜尋的表示，與對話使用的主模型並非同一事物。
{% endstep %}

{% step %}
### 2. 選擇資資來源

可以新增檔案、資資夾、筆記或網址。常見的文件格式包括 PDF、DOCX、Markdown、Excel、TXT 和 CSV；掃描版可能需要 OCR 才能取得文字。
{% endstep %}

{% step %}
### 3. 等待處理完成

開啟檔案詳情查看預覽和分段。若標題缺失、亂碼或表格結構遺失，請先整理原始檔案，再重新處理。
{% endstep %}

{% step %}
### 4. 執行召回測試

使用真實使用者會提問的問題進行測試，不要僅輸入檔案標題。檢查返回的片段是否相關、是否包含完整的上下文，再決定是否綁定給 Agent。
{% endstep %}
{% endstepper %}

### 使用真實問題驗收召回結果

資資顯示【就緒】後，使用工作中真正會出現的問題測試一次。例如制度庫可以問「海外租車能否報銷？」，再檢查返回內容是否來自正確的資資，是否包含足夠的上下文。

| 看到的結果 | 下一步 |
| --------------- | ----------------------- |
| 命中正確資資，片段足以回答問題 | 可以綁定給 Agent 使用 |
| 命中資資正確，但片段被截斷 | 先檢查原文結構，再調整分段長度 |
| 命中舊制度或無關資資 | 清理過期資資，補充更明確的標題和內容 |
| 完全沒有結果 | 檢查資資狀態和提問用詞，不要先盲目增大返回數量 |

{% hint style="info" %}
召回測試通過後，再在 Agent 中驗證完整問答。這樣能分清是「沒有找到資資」，還是「找到資資後回答得不好」。
{% endhint %}

## 如何理解 RAG 設定

RAG 指「先檢索資資，再讓模型作答」。常見設定控制切分長度、重疊範圍、返回數量和相關度門檻。

| 配置 | 作用 | 建議起點 | 什麼時候調整 |
| ----- | -------------- | -------- | ------------------- |
| 分段長度 | 決定每個檢索片段包含多少內容 | 先使用頁面初始值 | 片段經常截斷句子或混入太多主題時 |
| 分段重疊 | 保留相鄰片段的銜接 | 保持少量重疊 | 條款跨段、上下文經常斷開時 |
| 返回數量 | 一次提供多少候選片段 | 從少量結果開始 | 漏掉關鍵資資時增加，雜訊太多時減少 |
| 相關度門檻 | 過濾不相干內容 | 用召回測試決定 | 無關結果多時提高，正確片段被過濾時降低 |

### 應用案例：建立內部制度問答庫

將現行制度按部門整理，檔案名稱包含主題和生效範圍。匯入後使用「出差住宿超標怎麼處理」「試用期請假需要誰批准」等真實問題進行召回測試。確認片段準確後，只將這套知識庫綁定給「制度問答」Agent，並要求回答時指出資資名稱；遇到缺失內容則明確說未找到。

{% hint style="warning" %}
知識庫不會自動判斷檔案是否過期。制度、價格和流程變化時，應更新或移除舊資資，並重新執行召回測試。
{% endhint %}

</details>
