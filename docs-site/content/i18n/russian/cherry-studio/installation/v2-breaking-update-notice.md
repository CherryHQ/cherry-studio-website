# Уведомление о несовместимых изменениях

V2 — это не обычное обновление. В нём изменена структура данных, а также изменены точки входа и поведение функций: ассистенты, Agent, база знаний, веб-поиск и файлы.

{% hint style="danger" %}
Данные V1 можно перенести в V2 только в одну сторону. Новые сессии, Agent, настройки и файлы, созданные в V2, не синхронизируются обратно в V1. Резервные копии V1 и V2 несовместимы между собой.
{% endhint %}

## V2.0.2 позволяет напрямую переносить данные V1

Если необходимо сохранить данные V1, выполните переход **V1.9.13 → V2.0.2 (прямой перенос данных)**. Промежуточная версия V2.0.0 больше не требуется.

| Текущая ситуация | Рекомендуемые действия |
| --------------- | --------------------------------- |
| Используется V1, данные нужно сохранить | Обновите V1 до 1.9.13, создайте полную резервную копию и установите V2.0.2. |
| Уже используется V2 | Обновите до V2.0.2 и продолжайте использовать текущие данные V2. |
| Предыдущий перенос V1 завершился ошибкой или данные потеряны | Сначала создайте полную резервную копию текущих данных V2, затем рассмотрите использование функции [Повторный перенос]. |
| Данные V1 не нужны | Можно выбрать [Игнорировать и использовать значения по умолчанию], но данные V1 не будут перенесены. |

{% hint style="danger" %}
При обычном обновлении до V2.0.2 не нужно нажимать [Повторный перенос]. Эта операция безвозвратно удаляет текущие данные V2 и повторно импортирует исходные данные V1. Не выполняйте это действие, если предыдущий перенос V1 не завершился ошибкой и данные не были потеряны.
{% endhint %}

## Обязательные действия перед обновлением

1. Обновите V1 до 1.9.13 и запустите приложение хотя бы один раз.
2. Отключите [Компактный резервный режим] и создайте полную резервную копию V1.
3. Полностью закройте Cherry Studio, затем скопируйте весь каталог данных V1.
4. Если используются пользовательский каталог или внешний диск, убедитесь, что путь смонтирован и доступен для чтения и записи.

Мастер переноса читает текущий каталог данных V1, а не ZIP-архив резервной копии. Резервная копия предназначена для восстановления в случае непредвиденных ситуаций и не может заменить исходный каталог данных при переносе.

## [Повторный перенос] — это не объединение данных

В V2.0.2 в разделе [Настройки] → [Данные] добавлена функция [Повторный перенос]. Она предназначена только для исправления ошибок предыдущего переноса V1 или восстановления потерянных данных.

Перед выполнением операции потребуется подтвердить следующие пункты:

* Текущие данные V2 будут безвозвратно удалены.
* Исходные данные V1 сохранятся и будут повторно импортированы после перезапуска.
* Сначала необходимо создать полную резервную копию текущих данных V2.

Полная резервная копия не приводит к автоматическому объединению данных V1 и V2. Новые данные V2, которые нужно сохранить, предварительно экспортируйте отдельно или сохраните полную резервную копию.

{% hint style="danger" %}
Функция [Очистить кэш] в разделе [Настройки] → [Данные] → [Очистить кэш] удаляет исходные данные V1, необходимые для [Повторного переноса]. Не очищайте этот пункт, пока не убедитесь в целостности переноса и не создадите отдельную резервную копию.
{% endhint %}

## Основные проверки после обновления

* Сервисы моделей, API Key и модель по умолчанию; Anthropic OAuth не переносится, необходимо использовать API Key.
* Группировка ассистентов, порядок промптов, права доступа к инструментам Agent и привязка к базе знаний.
* Источники ошибок в базе знаний, сервисы поиска по ключевым словам и чтения URL в веб-поиске.
* Пользовательский CSS, закладки в боковой панели и отсутствующие файлы.

Полное сравнение см. в [Различия в функциях](v1-v2-feature-differences.md).

## Сбой переноса или необходимость отката

* Сначала используйте [Повторить], исправьте проблемы с каталогом данных, диском или данными, затем продолжите.
* [Сохранить информацию об ошибке] сохраняет данные только локально; файл может содержать пути, содержимое или учётные данные — передавайте его только команде поддержки Cherry Studio.
* [Игнорировать и использовать значения по умолчанию] начинает работу с конфигурации по умолчанию, данные V1 не переносятся.
* Для возврата к V1 не нужно удалять базу данных, а резервную копию V2 нельзя восстанавливать в V1.

{% hint style="danger" %}
Не удаляйте и не заменяйте базу данных самостоятельно. При ошибочных действиях, невозможности определить каталог данных или необходимости повторного переноса сначала сохраните все резервные копии и каталоги данных, затем обратитесь в команду поддержки Cherry Studio.
{% endhint %}
