# Обновление с V1 до V2

{% hint style="danger" %}
Миграция является односторонней: данные V1 могут быть перенесены в V2, но новые данные V2 не синхронизируются обратно в V1. Перед обновлением создайте полный резервный экземпляр V1 и скопируйте весь каталог данных V1 после полного выхода из приложения.
{% endhint %}

{% hint style="warning" %}
Правильный путь для сохранения данных: **V1.9.13 → V2 (прямая миграция данных)**. Предварительная установка отдельной промежуточной версии V2 не требуется.
{% endhint %}

## Выберите действие в зависимости от текущей ситуации

| Текущая ситуация | Действие |
| --------------- | ------------------------------------ |
| Всё ещё на V1, нужно сохранить данные | Обновите V1 до 1.9.13, затем установите V2, следуя инструкциям на этой странице. |
| Уже используете V2 | Просто обновите до V2 и продолжайте использовать текущие данные V2; не нажимайте [Повторная миграция]. |
| Предыдущая миграция с V1 завершилась ошибкой или данные потеряны | Сначала создайте полный резервный экземпляр текущего V2, затем используйте [Повторная миграция] для начала процесса заново с V1. |
| Данные V1 не нужны | Можно выбрать [Игнорировать и использовать значения по умолчанию], чтобы начать с конфигурации по умолчанию; данные V1 не будут перенесены. |

## Проверки перед обновлением

* Версия V1 не ниже 1.9.12; рекомендуется сначала обновить до финальной версии 1.9.13 и запустить приложение хотя бы один раз.
* Для первой миграции можно сразу использовать V2.
* Пользовательский каталог данных или внешний диск доступны для чтения и записи.
* Все задачи по чатам, Agent, импорту в базу знаний и обработке файлов завершены.

{% hint style="warning" %}
Мастер миграции читает текущий каталог данных V1, а не ZIP-архив резервной копии V1. Резервная копия предназначена для восстановления в случае непредвиденных ситуаций и не может заменить исходный каталог данных при миграции.
{% endhint %}

## Шаги обновления

{% stepper %}
{% step %}
### Обновление и резервное копирование V1

Обновите V1 до 1.9.13. На странице резервного копирования данных отключите [Упрощенное резервное копирование], создайте полный резервный экземпляр и сохраните его вне каталога данных приложения.
{% endstep %}

{% step %}
### Копирование всего каталога данных V1

Проверьте расположение каталога в настройках данных V1, полностью выйдите из Cherry Studio и скопируйте весь каталог. Не копируйте только файлы базы данных.
{% endstep %}

{% step %}
### Проверка пользовательского каталога

При использовании переносного диска, сетевого тома или другого пользовательского расположения убедитесь, что путь смонтирован и доступен для чтения и записи. Если путь недоступен, не переключайтесь на каталог по умолчанию для продолжения миграции.
{% endstep %}

{% step %}
### Первый запуск V2

Скачайте установочный пакет V2, соответствующий вашей системе и чипу, с [официального сайта V2](https://cherryai.com.cn/download), а также можно использовать [страницу релизов GitCode](https://gitcode.com/CherryHQ/cherry-studio/releases) или [страницу релизов GitHub](https://github.com/CherryHQ/cherry-studio/releases). Полностью выйдите из V1, затем установите и запустите V2.
{% endstep %}

{% step %}
### Завершение [Мастера миграции данных]

Проверьте расположение данных, отображаемое в мастере, затем выберите [Начать миграцию]. Во время миграции не закрывайте приложение, не перемещайте каталог данных и не отключайте внешний диск.
{% endstep %}

{% step %}
### Просмотр результатов и перезапуск

После завершения миграции сначала разверните сообщения о предупреждениях, затем выберите [Перезапустить приложение].
{% endstep %}
{% endstepper %}

## Проверки после обновления

* Проверьте используемые сервисы моделей, API Key и модель по умолчанию.
* Проверьте группы ассистентов, промпты, права Agent и привязки к базе знаний.
* Откройте часто используемые чаты, базу знаний и файлы; пересоздайте только те источники знаний, для которых отображается ошибка.
* В [Настройки] → [Веб-поиск] повторно подтвердите сервисы поиска по ключевым словам и чтения URL.
* Проверьте избранное в боковой панели и пользовательский CSS.
* В [Настройки] → [Данные] создайте новый полный резервный экземпляр V2.

Подробнее об изменениях в интерфейсе см. [«Различия в функциональности»](v1-v2-feature-differences.md).

## Используйте [Повторная миграция] только при неудаче миграции

Если предыдущая миграция из V1 завершилась с ошибкой или часть данных была потеряна, в версии V2 можно выбрать пункт [Повторная миграция] в разделе [Настройки] → [Данные]. Это действие перезапустит приложение и повторно выполнит миграцию из сохранённых данных V1.

{% hint style="danger" %}
[Повторная миграция] безвозвратно удаляет текущие данные V2 и не объединяет данные V1 и V2. Не выполняйте это действие, если предыдущая миграция из V1 не завершилась с ошибкой и данные не были потеряны. Перед выполнением операции обязательно создайте полную резервную копию текущих данных V2; новые данные V2, которые необходимо сохранить, следует дополнительно экспортировать отдельно.
{% endhint %}

## При сбое миграции

| Опция | Когда использовать | Примечания |
| ---------- | --------------- | ---------------------------------------------- |
| [Повторить] | После устранения проблем с каталогом, диском или временными данными | Рекомендуется в первую очередь; не прерывает процесс миграции. |
| [Сохранить информацию об ошибке] | Если повторная попытка не удалась и требуется помощь | Файл сохраняется только локально и может содержать пути, содержимое или учётные данные. Передавайте его только команде поддержки Cherry Studio. |
| [Игнорировать и использовать значения по умолчанию] | Если вы сознательно отказываетесь от импорта данных V1 | Удаляет частично записанные данные V2 из текущей сессии и начинает с конфигурации по умолчанию; автоматическое предложение миграции больше не будет появляться. |
| [Продолжить работу с V1] | Если миграция временно невозможна, но нужно продолжить работу | Переустановите V1 и продолжайте использовать исходный каталог данных V1. |

{% hint style="danger" %}
При сбое миграции или случайном выборе [Игнорировать и использовать значения по умолчанию] не удаляйте базу данных самостоятельно и не выполняйте многократную перезапись установки. Сохраните исходные данные V1 и резервные копии и обратитесь в команду поддержки Cherry Studio.
{% endhint %}

## Частые вопросы

<details>

<summary>Есть только ZIP-архив с резервной копией V1, можно ли выполнить миграцию напрямую?</summary>

Нет. Сначала восстановите данные в совместимой версии V1 и убедитесь в их целостности, затем сохраните полный каталог данных и запустите миграцию в V2.

</details>

<details>

<summary>Необходимо ли перестраивать индексы для всех баз знаний?</summary>

Нет. Действующие индексы будут перенесены; перестроение выполняется только для источников, где отображается ошибка, отсутствует модель встраивания или данные невозможно прочитать.

</details>
