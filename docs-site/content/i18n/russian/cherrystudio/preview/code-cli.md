# Партнёр по кодированию

Раздел «Партнёр по кодированию» предназначен для установки, настройки и запуска популярных командных инструментов для программирования. Cherry Studio распознаёт управляемые им установки, а также обнаруживает CLI, уже доступные в среде системного входа. Системные инструменты по-прежнему обслуживаются исходным менеджером пакетов.

## Возможности страницы

* Проверка наличия инструмента и доступных обновлений;
* Установка или обновление управляемых Cherry Studio копий инструментов;
* Обнаружение инструментов, уже присутствующих в системном PATH;
* Выбор провайдера и модели для CLI, требующих модельного сервиса;
* Сохранение нативного способа входа для CLI, использующих собственные учётные записи;
* Запуск с выбранным рабочим каталогом и обнаруженным системой терминалом.

В настоящее время на странице представлены такие инструменты, как Claude Code, OpenAI Codex, Gemini CLI, OpenCode, Qwen Code, Kimi Code, Qoder CLI и GitHub Copilot CLI. Фактический список может меняться с обновлениями продукта, поэтому ориентируйтесь на отображаемый список.

## Порядок использования

{% stepper %}
{% step %}
### 1. Откройте «Партнёр по кодированию» в левой навигации

Выберите нужный инструмент и проверьте его статус: не установлен, управляется Cherry Studio или получен из системы.
{% endstep %}

{% step %}
### 2. Завершите установку или вход

Если инструмент не установлен, нажмите «Установить». Для CLI, предоставляющих собственный вход по учётной записи, выполните нативный вход согласно подсказкам на странице. Выбор провайдера через Cherry Studio не требуется.
{% endstep %}

{% step %}
### 3. Настройте подключение к модели

Для инструментов, требующих модельного сервиса Cherry Studio, выберите совместимого провайдера и модель. Страница фильтрует варианты по типу интерфейса, необходимому CLI; несовместимые провайдеры не отображаются.
{% endstep %}

{% step %}
### 4. Выберите каталог и терминал

Рабочий каталог определяет место запуска CLI. Терминал можно выбрать только из списка, обнаруженного системой; возможность указать путь к исполняемому файлу пользовательского терминала больше не предоставляется.
{% endstep %}

{% step %}
### 5. Запустите и проверьте

Нажмите «Запустить» и выполните в терминале проверку только для чтения. Убедившись, что учётная запись, модель и каталог указаны верно, приступайте к изменению файлов или выполнению команд.
{% endstep %}
{% endstepper %}

## Режимы моделей для Claude Code

При настройке Claude Code в разделе «Модель» доступны два режима:

* «Универсальный»: все запросы обрабатываются одной и той же моделью, конфигурация проста;
* «Детальный»: в «Сопоставлении ролей моделей» отдельно задаются Fable, Opus, Sonnet, Haiku и Subagent. В таблице «Фактическая модель запроса» указана модель, фактически используемая для каждой роли; при необходимости для соответствующей роли можно включить контекст «1M».

Используйте режим «Детальный» только если действительно необходимо назначать разные модели для фоновых подзадач, сжатия или заголовков. Роли, оставленные пустыми, следуют за основной моделью. После изменений выполните небольшую задачу, чтобы убедиться, что каждая роль корректно отправляет запросы.

## Сценарий использования: запуск инструмента кодирования в каталоге проекта

| Параметр | Рекомендуемая отправная точка | Сценарий применения | Примечания |
| ----- | ----------------------------- | ------------ | ---------------- |
| Источник установки | Если есть системная версия, сначала используйте её | Команда уже централизованно управляет CLI | Обновление и удаление по-прежнему выполняются исходным менеджером пакетов |
| Подключение к модели | Сначала выберите подключение, уже проверенное в Cherry Studio | CLI, требующие модельного сервиса | Инструменты с собственным входом по учётной записи используют нативный процесс входа |
| Рабочий каталог | Выберите только текущий каталог проекта | Изменение кода, запуск проверок | После запуска сначала проверьте путь в терминале |
| Первая команда | Просмотр состояния проекта только для чтения | Проверка учётной записи, модели и каталога | Разрешите запись в файлы только после подтверждения корректности |

### Критерии завершения

Страница распознаёт источник установки; терминал открывается в правильном каталоге; минимальная команда только для чтения выполняется успешно; учётная запись или модель, отображаемые инструментом, соответствуют ожиданиям.

## Различайте источники установки

| Источник | Действия Cherry Studio | Ваши действия по обслуживанию |
| ---------------- | ------------------ | ------------------ |
| Управляемый Cherry Studio | Установка, обновление и удаление соответствующей управляемой копии | Управляйте через «Партнёр по кодированию» или «Зависимости среды» |
| Системный PATH | Обнаружение и прямое использование без перезаписи | Обновляйте или удаляйте через исходный менеджер пакетов |
| Встроенный в приложение | Прямое использование, системное удаление не предоставляется | Обновляется вместе с Cherry Studio |

{% hint style="warning" %}
После удаления управляемой Cherry Studio копии, если в системе остаётся исполняемый файл с тем же именем, страница автоматически переключается на системную версию. При изменении версии или поведения сначала убедитесь, какой источник используется в данный момент.
{% endhint %}

<details>

<summary>Почему не находятся уже установленные терминалы или CLI? </summary>

Cherry Studio обнаруживает инструменты в среде входа и стандартных расположениях. Убедитесь, что команда выполняется в терминале входа, затем перезапустите приложение для обновления среды. Для портативных или нестандартных путей пока требуется ручной запуск из соответствующего терминала.

</details>
