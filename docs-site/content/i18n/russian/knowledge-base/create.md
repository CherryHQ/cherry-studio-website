# Создание базы знаний

Два наиболее важных выбора при создании — это название и модель эмбеддингов. Материалы можно добавить позже, но границы названия и способ поиска повлияют на дальнейшее обслуживание.

{% hint style="info" %}
При первом знакомстве можно установить параметр [Модель эмбеддингов] в значение [Не использовать]. База знаний будет использовать поиск по ключевым словам BM25; достаточно сначала настроить процесс импорта и извлечения.
{% endhint %}

## Два решения перед созданием

### Название должно отражать границы материалов

Используйте формат «объект + назначение», например [Политика командировок сотрудников], [Справочник по послепродажному обслуживанию] или [Материалы рыночных исследований]. Избегайте названий вроде [Материалы] или [Тест], которые не позволяют определить объем содержимого.

### Выбор способа эмбеддингов

| Выбор | Подходящие сценарии | Способ поиска | Предварительные условия |
| ------ | ------------- | ------------- | ------------ |
| Не использовать | Первое знакомство, четкие ключевые слова | Поиск по ключевым словам BM25 | Нет |
| Облачная модель эмбеддингов | Значительные различия между формулировками пользователей и текстом материалов | Гибридный поиск BM25 + векторы | Соответствующий сервис модели должен быть доступен |
| Локальная модель эмбеддингов | Векторизация выполняется на локальной машине | BM25 + локальный векторный поиск | Сначала скачайте модель в разделе [Локальные модели] |

## Шаги создания

{% stepper %}
{% step %}
### 1. Откройте окно создания

Откройте раздел [Базы знаний] в левой навигации и нажмите кнопку добавления над списком баз знаний.
{% endstep %}

{% step %}
### 2. Введите название

Введите название, отражающее границы содержимого, например [Политика командировок сотрудников].
{% endstep %}

{% step %}
### 3. Выберите модель эмбеддингов

Выберите доступную облачную или локальную модель эмбеддингов; если семантический поиск пока не требуется, выберите [Не использовать].

<figure><img src="../../../assets/7f1505c0527aeddf65937cdc.webp" alt="Название определяет границы материалов; модель эмбеддингов определяет, будет ли добавлен векторный поиск."><figcaption><p>Название определяет границы материалов; модель эмбеддингов определяет, будет ли добавлен векторный поиск. </p></figcaption></figure>
{% endstep %}

{% step %}
### 4. Нажмите «Создать»

После подтверждения названия и модели нажмите [Создать]. После создания вы попадете в пустую базу знаний.
{% endstep %}

{% step %}
### 5. Добавьте первую партию материалов

Нажмите кнопку добавления материалов, импортируйте один-два файла или заметки с четкими ответами и дождитесь завершения обработки.
{% endstep %}
{% endstepper %}

## Использование локальной модели эмбеддингов

Откройте [Настройки] → [Локальные модели] и скачайте доступную модель в разделе [Модели эмбеддингов]. Отображаемые модели и размеры загрузки могут меняться в зависимости от среды установки; ориентируйтесь на текущий список.

<figure><img src="../../../assets/ba97a6075b29a5304d81dc79.webp" alt="После завершения загрузки вернитесь на страницу создания или настройки базы знаний и выберите эту модель."><figcaption><p>После завершения загрузки вернитесь на страницу создания или настройки базы знаний и выберите эту модель. </p></figcaption></figure>

{% hint style="warning" %}
Локальные эмбеддинги означают только то, что векторизация выполняется на локальной машине. Использование облачных сервисов для анализа документов, переупорядочивания и чата зависит от выбранных вами сервисов и моделей.
{% endhint %}

## Замена модели при наличии материалов

При включении модели эмбеддингов в базе знаний, использующей только BM25, можно создать векторный индекс. При замене модели эмбеддингов в базе знаний, уже содержащей векторы, интерфейс перейдет в процесс [Перестроения базы знаний].

{% hint style="danger" %}
Перед началом перестроения убедитесь, что новая модель доступна. После перестроения повторно выполните тест извлечения; не меняйте модель и не изменяйте разбиение на блоки в одном и том же цикле, иначе невозможно будет определить источник изменений в результатах.
{% endhint %}

## Описание конфигурации

| Параметр | Значение по умолчанию | Рекомендуемая стартовая точка | Функция | Подходящие сценарии | Примечания |
| ------ | ----- | ----------- | ---------- | ----------- | ------------------ |
| Название | Пусто | Объект + назначение | Разграничение материалов | Все базы знаний | Материалы с разными правами доступа или жизненным циклом следует разделять |
| Модель эмбеддингов | Не использовать | При первом знакомстве лучше не использовать | Определяет добавление векторного поиска | Разговорные формулировки, много синонимов | Тарификация и обработка данных облачных моделей зависят от провайдера |
| Локальная модель эмбеддингов | Не скачана | Скачивайте при необходимости локальной обработки | Векторизация на локальной машине | Офлайн или высокие требования к конфиденциальности | Необходимо отдельно проверять модели анализа, переупорядочивания и чата |

## Ожидаемый результат

* Новая база знаний появляется в списке, и ее название отличается от других.
* Вы понимаете, используется ли сейчас поиск по ключевым словам или гибридный поиск.
* Выбранная облачная модель доступна, или локальная модель уже скачана.

## Пример пользователя

Сяо Линь впервые создал базу знаний [Политика командировок сотрудников]. Сначала он выбрал [Не использовать] для модели эмбеддингов, импортировал три документа и выполнил тест извлечения. После того как поиск по ключевым словам стал стабильным, он настроил модель эмбеддингов и сравнил результаты для разговорных формулировок с использованием тех же вопросов.

Критерий готовности: после улучшения способа поиска исходные фиксированные вопросы не ухудшились, а разговорные формулировки стали более стабильно находить один и тот же документ.

## Частые вопросы

<details>

<summary>Что делать, если кнопка создания недоступна? </summary>

Проверьте, не пустое ли название и доступна ли выбранная модель. Если сервис модели не настроен, можно сначала выбрать [Не использовать], чтобы завершить создание.

</details>

<details>

<summary>Будет ли поиск полностью не работать без модели эмбеддингов? </summary>

Нет. База знаний будет использовать поиск по ключевым словам BM25; чем ближе формулировка вопроса к материалам, тем стабильнее результаты.

</details>

<details>

<summary>Нужно ли создавать отдельную базу для каждой темы? </summary>

Критерий — «должны ли эти материалы извлекаться вместе при использовании». Материалы с разными правами доступа, жизненным циклом или полностью разными темами лучше разделять.

</details>
