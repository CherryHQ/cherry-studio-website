# Рецензирование длинных документов

Продуктовый менеджер получает объёмный проект документа и должен выявить фактические ошибки, структурные пробелы и конкретные правки, сохранив исходный текст и процесс ручного подтверждения. Описанный ниже подход подходит для отчётов, регламентов, тендерной документации и продуктовых предложений.

## Рекомендуемая комбинация

* 【Диалог】: быстрое сравнение подходов разных моделей к рецензированию;
* 【Рабочий】Agent: чтение рабочего каталога и создание исправленного черновика;
* База знаний: предоставление регламентов, терминологии или исторических материалов;
* 【Файлы】 справа: проверка исходного текста и результатов.

## Порядок действий

{% stepper %}
{% step %}
### 1. Подготовка исходного текста и критериев рецензирования

Поместите исходный текст в отдельный рабочий каталог и создайте краткое описание рецензирования, указав целевую аудиторию, цель, неизменяемые факты и формат предоставления.
{% endstep %}

{% step %}
### 2. Начните с локальной калибровки

Выберите один раздел и попросите Agent вывести результаты по схеме «проблема, местоположение в тексте, влияние, рекомендация». После подтверждения подходящего масштаба обработайте весь текст.
{% endstep %}

{% step %}
### 3. Разделите факты и формулировки

Попросите Agent отдельно перечислить факты, требующие проверки, не маскируя неопределённость стилистической правкой. Ключевые цифры сверяйте с первоисточниками.
{% endstep %}

{% step %}
### 4. Создайте новый файл и завершите работу вручную

Попросите сохранить исходный файл и сгенерировать список проблем и исправленный черновик в `review/`. Проверьте текст по абзацам через 【Файлы】 справа, затем экспортируйте или поделитесь результатом.
{% endstep %}
{% endstepper %}

## Пример задачи

```
Проверьте proposal.docx в текущем каталоге. По разделам перечислите фактические ошибки, пробелы в структуре и проблемы формулировок с указанием места в исходном тексте. Не изменяйте исходный файл; после подтверждения списка создайте в review/ исправленную версию и перечень вопросов для проверки.
```

## Подготовка перед использованием и критерии завершения

| Пункт | Рекомендуемая подготовка |
| ---- | -------------------------------- |
| Файлы | Исходный текст, требования к рецензированию и каталог вывода хранятся отдельно |
| Рекомендуемая комбинация | Специализированный Agent + рабочий каталог только с файлами данного проекта + 【Подтверждение по шагам】 |
| Способ проверки | Сначала проверьте один раздел, подтвердив формат цитирования и масштаб оценок |
| Критерий завершения | Каждая рекомендация содержит местоположение в тексте; непрочитанные части явно отмечены; исходный файл не перезаписан |

Подходит для структурированного рецензирования контрактов, отчётов, диссертаций или стандартов; при наличии юридических, медицинских или финансовых выводов результат может использоваться только как вспомогательный материал.

{% hint style="info" %}
Если документ очень длинный, не вставляйте весь текст повторно в одном диалоге. Позвольте Agent напрямую читать рабочий каталог и оставлять промежуточные результаты по разделам — это упрощает проверку и восстановление.
{% endhint %}
