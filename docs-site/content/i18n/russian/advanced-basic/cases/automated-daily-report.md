# Каналы и автоматический ежедневный отчёт

Операционная команда хочет автоматически собирать определённые материалы каждое рабочее утро, формировать ежедневный отчёт и отправлять его в командный канал. Перед автоматизацией рекомендуется вручную выполнить один отчёт, чтобы своевременно выявить проблемы с отсутствием данных, ошибками путей и целями уведомлений.

## Что подготовить заранее

* Ежедневный отчёт Agent, проверенный в разделе [Работа];
* Чётко определённые источники данных и рабочая директория, содержащая только необходимые материалы;
* Фиксированный формат можно оформить как навык;
* Подключённый канал с ограничением области сообщений;
* Планируемая задача на рабочие дни.

## Шаги настройки

{% stepper %}
{% step %}
### 1. Вручную сформировать один отчёт

Попросите Agent вывести четыре раздела: «Прогресс, Метрики, Риски, Задачи». Проверьте, явно ли указано отсутствие данных, а не выдумывается ли контент.
{% endstep %}

{% step %}
### 2. Настроить канал уведомлений

Сначала укажите в диалоге с Agent платформу и группу для подключения, затем проверьте в [Настройки] → [Каналы] учётные данные, разрешённые ID сессий, рабочее пространство и режим прав.
{% endstep %}

{% step %}
### 3. Создать планируемую задачу

Попросите Agent создать расписание на рабочие дни или откройте [Настройки] → [Планируемые задачи] → [Создать]. Выберите Agent для отчёта, рабочую директорию, время выполнения и канал уведомлений.
{% endstep %}

{% step %}
### 4. Немедленно протестировать

После сохранения нажмите [Запустить], просмотрите сгенерированную сессию, историю выполнения и сообщения в канале. Не ждите до следующего дня, чтобы обнаружить ошибки путей или целей получения.
{% endstep %}

{% step %}
### 5. Наблюдать и корректировать

В первых нескольких запусках проверяйте время выполнения, потребление ресурсов и причины сбоев. При изменении источников данных или формата команды обновляйте навык или промпт задачи, не поддерживая противоречивые правила в разных местах.
{% endstep %}
{% endstepper %}

## Пример промпта задачи

```
Прочитайте данные, добавленные вчера в рабочий каталог, и создайте ежедневный операционный отчёт на китайском языке. Обязательно включите прогресс, ключевые показатели, отклонения и задачи на сегодня. Если данных нет, напишите «Нет данных» и перечислите отсутствующие файлы, не придумывая значения. Отправьте результат в настроенный командный канал и сохраните копию Markdown в рабочем каталоге.
```

## Обработка сбоев

| Симптом | Место проверки |
| ------ | --------------------- |
| Не запускается | Статус планированной задачи, время следующего запуска, режим сна системы |
| Сбой выполнения | [История выполнения] → [Просмотр сессии] |
| Файл не создан | Рабочая директория, запросы прав и файловые инструменты Agent |
| Сообщение не доставлено | Статус канала, цель получения и журналы платформы |
| Дублирование контента | Одновременно активированы heartbeat и несколько одинаковых расписаний |

## Рекомендуемые комбинации и критерии завершения

| Элемент | Рекомендуемый подход |
| ----- | ---------------------------------- |
| Agent | Сначала вручную выполните тот же отчёт, затем передайте его планированной задаче |
| Расписание | Предпочтительно использовать [Ежедневно] или [Рабочие дни], подтвердите время следующего запуска |
| Канал | Сначала отправляйте в тестовую сессию, затем переключитесь на официальную группу |
| Критерий завершения | Успех в истории выполнения; файл отчёта открывается; в канале получено только одно сообщение; при отсутствии данных результаты не выдумываются |

{% hint style="warning" %}
Планируемые задачи выполняются в автономном режиме. Перед запуском в продакшен ограничьте минимальный набор файлов и соответствующие права, избегайте передачи высокорисковых операций записи или внешних изменений в режиме полного доступа.
{% endhint %}

{% hint style="info" %}
В демонстрационной среде на скриншоте не подключён внешний канал, поэтому отображается только сохранённая и активированная задача. Для использования в рабочей среде необходимо нажать [Запустить], убедиться в успехе в [Истории выполнения] и увидеть одно реальное сообщение в тестовом канале перед началом регулярной работы.
{% endhint %}
