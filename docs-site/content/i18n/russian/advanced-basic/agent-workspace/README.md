# Рабочая область Agent

Agent предназначен для задач с чёткой целью, требующих использования инструментов или файлов, которые могут выполняться в несколько этапов. Вход находится в левой навигации в разделе «Работа», а не в верхней вкладке, как в старых руководствах.

{% hint style="success" %}
Самый простой способ настройки — сначала сообщить Agent, что вы хотите выполнить, а затем позволить ему проверить наличие недостающих моделей, инструментов, баз знаний или каналов. При необходимости точного контроля откройте окно редактирования Agent или раздел «Настройки» для ручной корректировки.
{% endhint %}

### Из чего состоит рабочая область

| Компонент | Назначение | Когда обратить внимание |
| ----- | ----------------- | ----------------- |
| Agent | Хранит роль, модель, промпты и возможности | При повторном выполнении однотипных задач |
| Задача | Запись одного непрерывного рабочего процесса | Создавайте отдельную задачу для каждой цели, чтобы сохранять контекст |
| Рабочий каталог | Диапазон файлов, с которыми Agent может работать напрямую | Задачи с файлами: код, систематизация материалов, генерация документов |
| Область ввода | Отправка целей, вложений и вызов инструментов | Для запуска задачи или добавления требований |
| Правая панель | Просмотр статуса, файлов, подзадач и потока сообщений | Для отслеживания длительных задач, проверки результатов или устранения неполадок |

### Начало задачи

{% stepper %}
{% step %}
#### 1. Откройте «Работа» и выберите Agent

Если подходящий Agent уже есть, выберите его. Если нет, нажмите «Добавить агента», в разделе «Базовая информация» сначала выберите режим работы, затем завершите создание в четыре шага: системный промпт, навыки и база знаний. Режим работы нельзя изменить после создания.
{% endstep %}

{% step %}
#### 2. Выберите рабочий каталог

Если нужно работать с локальными файлами, выберите каталог для текущей задачи. Если файлы не используются, можно применить рабочую область по умолчанию, созданную приложением. Одна задача соответствует одной рабочей области, чтобы Agent не искал файлы в нерелевантных каталогах.
{% endstep %}

{% step %}
#### 3. Опишите задачу через ожидаемый результат

Сообщите Agent, что именно нужно предоставить, какие материалы можно использовать, какие есть ограничения и как определить завершение. Например:

```
Прочитайте протоколы совещаний в текущем каталоге, соберите решения, ответственных и сроки и создайте action-items.md. Не изменяйте исходные файлы.
```
{% endstep %}

{% step %}
#### 4. Проверьте процесс и результаты в правой панели

Раздел «Статус» отображает активные задачи, под-агентов, рабочие процессы и фоновые команды; в разделе «Файлы» можно просматривать и редактировать текстовые результаты; при включенном режиме разработчика также доступен раздел «Цепочка вызовов».
{% endstep %}
{% endstepper %}

### Уведомления о API-шлюзе

Работа Agent зависит от API-шлюза Cherry Studio. Если шлюз не активирован, приложение предложит «Включить и запустить». Также можно проверить порт, статус работы и блокировки локальным программным обеспечением безопасности в разделе «Настройки» → «API-шлюз».

{% hint style="warning" %}
API-шлюз является зависимостью для работы Agent, но это не означает, что нужно открывать доступ к интерфейсу из сети. Достаточно оставить использование по умолчанию на локальной машине. Копирование URL и API-ключа требуется только в том случае, если вы явно хотите, чтобы другие программы обращались к этому интерфейсу.
{% endhint %}

### Один Agent или несколько

* Одна и та же роль, один и тот же набор возможностей, но разные задачи: используйте один Agent и создавайте несколько задач.
* Разные роли, диапазоны материалов или права доступа: разделите на несколько Agent.
* Если для одной цели требуется параллельное исследование или взаимодействие нескольких этапов: сначала используйте под-агентов или рабочие процессы в одном Agent, не создавая вручную множество Agent.

### Пример пользователя: систематизация проектных материалов

Продуктовый менеджер помещает спецификации требований, записи интервью и материалы конкурентов в один каталог, создает Agent «Систематизация требований», привязывает продуктовую базу знаний и использует право «Подтверждение по каждому шагу». Agent сначала читает материалы, затем записывает список требований и вопросы, требующие подтверждения, в новый файл. Продуктовый менеджер вносит правки в текст непосредственно в разделе «Файлы» справа, при этом исходные материалы остаются неизменными.

<details>

<summary>Почему Agent не видит только что привязанные возможности?</summary>

Изменения в Agent сохраняются автоматически. Текущий генерируемый ответ не прерывается; изменения моделей, навыков, MCP и баз знаний вступают в силу с следующего сообщения. Если изменения все еще не видны, сначала убедитесь, что возможность активирована, затем отправьте новое сообщение.

</details>

<details>

<summary>Удаляет ли удаление рабочего каталога файлы на диске?</summary>

При удалении рабочего каталога из списка задач удаляются только записи каталога и задач в Cherry Studio, реальный каталог на диске не удаляется. Операции с файлами, выполняемые Agent во время задачи, по-прежнему зависят от выбранного режима прав доступа.

</details>
