# Права доступа, память и фоновые задачи

Agent может выполнять операции с файлами, терминалом и сетью, а также вызывать субагентов и фоновые задачи. Права доступа определяют, нужно ли запрашивать разрешение, память определяет, будет ли информация доступна в будущем, а панель состояния справа показывает, что происходит прямо сейчас.

### Режимы прав доступа

| Режим | Поведение | Сценарии применения | Примечания |
| -------- | ------------- | ------------- | ---------------- |
| 【Подтверждение каждого действия】 | Запрос разрешения перед редактированием файлов или выполнением команд | Точка отхода, реальные каталоги проектов | При большом количестве операций подтверждения будут частыми, но это самый контролируемый вариант |
| 【Автопринятие правок】 | Можно редактировать файлы, но перед выполнением команд запрашивается разрешение | Организация документации, обратимые изменения кода | Сначала проверьте рабочий каталог и состояние системы контроля версий |
| 【Умное одобрение】 | Решение о разрешении принимается на основе проверок безопасности | Поддерживается моделью, а границы задач четкие | Некоторые модели могут по-прежнему запрашивать разрешение для каждого действия |
| 【Только планирование】 | Только планирование, без редактирования файлов | Рецензирование планов, проверка перед релизом | Подходит для предварительного рассмотрения плана перед выполнением |
| 【Полный доступ】 | Пропуск проверок прав доступа | Изолированные, доверенные и обратимые среды | Может удалять файлы или получать доступ к сети, максимальный риск |

Диапазон прав, предоставляемых в разных режимах выполнения, не всегда одинаков: Pi не поддерживает режим 【Только планирование】, при создании нового Pi Agent по умолчанию используется режим 【Умное одобрение】; DeepSeek Harness не поддерживает режим 【Умное одобрение】; 【Усиление: Claude Agent】 поддерживает все пять режимов.

Путь настройки: левая навигация 【Работа】 → меню Agent → 【Редактировать】 → 【Основное】 → 【Режим прав доступа】.

{% hint style="danger" %}
Каналы могут индивидуально переопределять режим прав доступа Agent. Внешние чат-интерфейсы чаще получают непредвиденные команды, поэтому обычно следует выбирать 【Наследовать настройки агента】 или более строгий режим, чем у Agent. Не открывайте полный доступ только ради уменьшения количества подтверждений.
{% endhint %}

### Память Agent

Память Agent привязана к самому Agent, а не к конкретной задаче или рабочему каталогу. Она подходит для хранения долгосрочных предпочтений, фактов о проекте, технических решений и опыта; одноразовый прогресс записывается в журнал с временными метками для последующего поиска в других задачах.

Просто сообщите Agent в разделе 【Работа】:

```
Запомните: во всех публикуемых текстах на китайском языке используйте полноширинную пунктуацию и избегайте преувеличенных заголовков. Применяйте это правило в следующих связанных задачах.
```

Если нужно внести исправления, явно укажите, что старые данные устарели, и запросите обновление памяти. Не записывайте в долгосрочную память пароли, API Key, конфиденциальную личную информацию или краткосрочные нерелевантные данные.

### Субагенты, рабочие процессы и фоновые команды

В сложных задачах Agent может распределять исследование, организацию и верификацию между субагентами или использовать рабочие процессы для оркестрации нескольких шагов. Долгие команды могут выполняться в фоне, не блокируя весь диалог. Agent также может создать новую сессию после вашего подтверждения или отправить задачу в существующую сессию; запрос возвращается немедленно, а результат выполнения позже приходит в исходную сессию, сохраняя источник и статус доставки.

В разделе 【Состояние】 справа можно просмотреть:

* текущие и завершенные задачи;
* субагентов и рабочие процессы;
* фоновые команды и возможность их остановки;
* успех, неудачу и количество вызовов инструментов;
* использование контекста и заявленные артефакты.

После включения 【Настройки】 → 【Уведомления】 → 【Уведомление о завершении диалога】, при работе в других вкладках или окнах вы получите системные уведомления о завершении ответа ассистента, завершении задачи Agent или ожидании одобрения; клик по уведомлению вернет вас в соответствующий диалог.

### Пример пользователя: постоянное поддержание стандартов проекта

Команда записывает стабильные соглашения о коде в память Agent, а подробные шаги рецензирования оформляет как навык. При рецензировании новой ветки создается задача, где Agent использует субагентов для отдельной проверки интерфейсов, миграции данных и тестов, а затем основной Agent сводит выводы. При изменении правил обновляется память, без необходимости изменения истории каждой задачи.

<details>

<summary>Может ли память заменить базу знаний? </summary>

Нет. Память подходит для небольшого количества стабильных фактов и опыта, используемых между задачами; база знаний подходит для систематизированной документации и позволяет контролировать область поиска Agent.

</details>

<details>

<summary>Задача кажется зависшей, куда смотреть в первую очередь? </summary>

Сначала откройте раздел 【Состояние】 справа, проверьте, не ожидает ли система разрешения, не выполняется ли фоновая команда, не провалилась ли подзадача или не происходит ли повторная попытка со стороны провайдера. Если нужны более глубокие детали запроса, включите режим разработчика для просмотра цепочки вызовов.

</details>
