# Длинные диалоги, контекст и очередь сообщений

Чем длиннее диалог, тем больше истории модель должна обрабатывать. Когда использование контекста приближается к пределу, ранние сообщения могут перестать участвовать в формировании ответа. Вместо постоянного добавления фразы «продолжи» периодически структурируйте выводы и нерешённые вопросы.

### Управление длинными диалогами

{% stepper %}
{% step %}
#### 1. Наблюдайте за индикаторами контекста

Когда интерфейс сигнализирует о высокой нагрузке на контекст, прекратите добавление крупных вложений и проверьте, какие элементы истории всё ещё относятся к текущей цели.
{% endstep %}

{% step %}
#### 2. Попросите модель создать сводку для передачи

Попросите её отдельно перечислить «подтверждённые факты, текущие выводы, нерешённые вопросы, ограничения, которые нельзя потерять». Это эффективнее обычной просьбы «сделай краткое изложение» для продолжения работы.
{% endstep %}

{% step %}
#### 3. Начните новую тему для продолжения

Перенесите сводку и необходимые файлы в новую тему. В первом сообщении укажите, какая цель будет рассматриваться далее. Старую тему оставьте для справки.
{% endstep %}
{% endstepper %}

### Настройка глобального управления контекстом

Путь: [Настройки] → [Общие] → [Управление контекстом]. Эти настройки применяются к обычным диалогам с ассистентом; отдельный ассистент может переопределить их в собственных настройках.

| Параметр | Значение по умолчанию | Рекомендуемая стартовая точка | Функция | Сценарии применения | Примечания |
| -------- | -------- | ------- | ------------- | ------------- | --------------- |
| Количество последних сообщений | Без ограничений | Без ограничений | Передавать модели только последние несколько сообщений | Кратковременные задачи с фиксированным окном | Слишком малое значение может привести к тому, что модель забудет действующие требования |
| Включить управление контекстом | Включено | Оставить включённым | Управление сверхдлинными результатами инструментов и сжатие истории | Длинные диалоги, задачи с частыми вызовами инструментов | При отключении крупные результаты быстрее заполняют контекст |
| Порог обрезки вывода инструментов | 50000 символов | Оставить по умолчанию | Сохранять крупные результаты и позволять модели читать их по частям | Результаты инструментов: веб-страницы, журналы, длинные документы | Это не удаление исходного результата |
| Автоматическое сжатие | Включено | Оставить включённым | Суммировать раннюю историю при приближении к пределу окна | Непрерывная многошаговая работа | Сжатие — это сводка, не гарантируется сохранение каждой детали |
| Модель для сжатия | Текущая модель | Оставить текущую модель | Выбор модели для генерации сводки истории | Необходимость отдельного контроля скорости или стоимости | Смена модели увеличивает количество переменных при отладке |

В разделе [Настройки] → [Модель по умолчанию] также доступен параметр [Повторные попытки вызова модели]. По умолчанию отключён; при включении выполняется не более 3 попыток с экспоненциальной задержкой, также можно выбрать резервные модели в определённом порядке. Повторные попытки и резервирование действуют только до начала вывода модели и не позволяют продолжить сгенерированный наполовину ответ с другой моделью.

### Использование очереди сообщений

Пока модель отвечает, можно добавить следующее требование в очередь. Это подходит для добавления конкретного последующего действия, например «после завершения сформулируйте три вывода». Если во время работы Agent нужно немедленно скорректировать текущее направление, используйте [Горячие клавиши для управления]; если требуется полный перезапуск, остановите текущую генерацию и заново сформулируйте цель.

<figure><img src="../../../../assets/a62a413bccd43d18b59ee293.webp" alt="При приостановке можно сначала проверить результаты; после возобновления сообщения из очереди будут отправляться в порядке сверху вниз."><figcaption><p>При приостановке можно сначала проверить результаты; после возобновления сообщения из очереди будут отправляться в порядке сверху вниз. </p></figcaption></figure>

На изображении: ① два сообщения в очереди в текущей теме; ② возобновление автоматической отправки. После возобновления сообщения будут отправляться в порядке сверху вниз.

{% hint style="info" %}
Очередь — это не автоматизированное планирование. Она управляет только последующими сообщениями в текущей теме; для запуска в определённое время используйте [Планировщик задач].
{% endhint %}

#### Пример применения: рецензирование длинного отчёта

Сначала загрузите отчёт и попросите перечислить проблемы по разделам. Пока модель обрабатывает запрос, добавьте в очередь «после завершения составить список рисков» и «в конце создать чек-лист». Если нужно сначала проверить результаты первого этапа, можно приостановить автоматическую отправку; после подтверждения корректности возобновите. Это позволяет не следить за диалогом и отправлять сообщения по одному, а также избежать выполнения следующего требования до проверки.

<details>

<summary>Почему модель внезапно забыла ранее сформулированные требования? </summary>

Сначала проверьте, не слишком ли длинный диалог, не менялась ли модель и упоминалось ли ключевое требование только один раз. Внесите стабильные правила в явное описание текущей задачи; для долгосрочного повторного использования передайте их в промпт Agent или навык.
