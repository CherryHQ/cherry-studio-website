# Цепочка вызовов и режим разработчика

Цепочка вызовов используется для просмотра модельных запросов, вызовов инструментов и взаимодействий MCP, происходящих внутри одного диалога или задачи Agent. Она подходит для устранения неполадок и анализа производительности, но не является обязательной функцией для повседневного общения.

### Способ включения

{% stepper %}
{% step %}
#### 1. Откройте [Настройки] → [Общие]

В разделе [Режим разработчика] включите [Включить режим разработчика].
{% endstep %}

{% step %}
#### 2. Перезапустите Cherry Studio

Режим разработчика вступает в силу после перезапуска. Перед перезапуском рекомендуется проверить статус выполняющихся задач Agent.
{% endstep %}

{% step %}
#### 3. Воспроизведите проблему

Отправьте минимальное тестовое сообщение, оставив только необходимые модели и инструменты, чтобы сократить количество нерелевантных вызовов.
{% endstep %}

{% step %}
#### 4. Откройте цепочку вызовов

В правой панели диалога или Agent перейдите в [Цепочка вызовов], выберите узел и просмотрите входные данные, выходные данные, время выполнения и статус. Для задач Agent также отображаются имя Agent, действия и количество вызовов инструментов.
{% endstep %}
{% endstepper %}

### Как читать основные узлы

| Узел | Что проверять | Частые проблемы |
| -------- | ------------------ | ---------------- |
| Запрос модели | Модель, входные данные, выходные данные, Token и статус | Ошибки провайдера, слишком длинный контекст, пустой вывод |
| Вызов инструмента | Название инструмента, параметры, результат | Ошибки параметров, ожидание разрешений, аномальный возврат инструмента |
| Вызов MCP | Название сервиса, тип подключения, входные и выходные данные | Разрыв соединения с сервером, ошибка аутентификации, удаленные ошибки |
| Выполнение Agent | Agent, действия, количество инструментов и статус | Сбой подзадач, незавершенный процесс |
| HTTP-запрос | Метод, URL, статус и ответ | Ошибки адреса, сетевые проблемы или проблемы с аутентификацией |

{% hint style="danger" %}
Цепочка вызовов может содержать промпты, содержимое файлов, заголовки запросов и параметры инструментов. Перед отправкой скриншотов или экспортом данных обязательно удалите API Key, Authorization, Cookie, адреса электронной почты, локальные пути и бизнес-данные.
{% endhint %}

### Пример от пользователя: пустой результат инструмента MCP

Сначала убедитесь, что сервер работает нормально на странице настроек MCP, затем заставьте Agent вызвать только один инструмент. Если в цепочке вызовов видно, что запрос достиг сервера, но вывод пуст, проблема, скорее всего, связана с данными на стороне сервера или параметрами, а не с отсутствием привязки в Agent. Если узел MCP отсутствует вовсе, вернитесь к [MCP] в Agent и проверьте привязку.

<details>

<summary>Почему после включения цепочка вызовов не отображается? </summary>

Убедитесь, что приложение было перезапущено, и отправьте новый запрос после перезапуска. Для исторических сообщений, созданных до включения функции, данные вызовов не добавляются автоматически.
