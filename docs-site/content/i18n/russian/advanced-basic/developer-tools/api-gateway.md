# API-шлюз

API-шлюз предоставляет возможности моделей, настроенных в Cherry Studio, локальным программам через HTTP API, совместимые с OpenAI и Anthropic. Он также является внутренним сервисом, необходимым для работы Agent.

Путь: [Настройки] → [API-шлюз].

## Различайте использование Agent и внешние вызовы

* Если используется только Agent Cherry Studio: следуйте подсказкам приложения и нажмите [Включить и запустить]; не нужно копировать URL или ключ в другие программы;
* Если локальная программа должна вызывать Cherry Studio: запустите шлюз, скопируйте URL и API-ключ, а также выберите совместимый интерфейс согласно документации API;
* Если требуется доступ с других устройств: это расширяет область видимости, поэтому необходимо самостоятельно проверить сетевое прослушивание, настройки файрвола и контроль доступа. Не рекомендуется открывать доступ без мер безопасности.

## Запуск и подключение

{% stepper %}
{% step %}
### 1. Проверка порта

Порт можно изменить, когда шлюз остановлен. Выберите порт, не занятый другими программами; при конфликте портов сервис не сможет корректно запуститься.
{% endstep %}

{% step %}
### 2. Запуск шлюза

Нажмите [Запустить]. После изменения статуса на [Работает] на странице отобразится доступный URL и появится ссылка на [Документацию API].
{% endstep %}

{% step %}
### 3. Настройка авторизации

Внешние программы используют `Authorization: Bearer <API-ключ>`. На странице можно напрямую скопировать заголовок авторизации. Не записывайте ключ в репозитории кода или скриншоты.
{% endstep %}

{% step %}
### 4. Проверка минимальным запросом

Сначала запросите список моделей или отправьте короткий текст согласно документации API, а затем подключайте полное приложение. При возникновении ошибок записывайте HTTP-статус и ответ, не публикуя полный заголовок авторизации.
{% endstep %}
{% endstepper %}

## Сценарий использования: вызов моделей локальными скриптами

Сначала убедитесь в [Настройках] → [Сервисы моделей], что модели могут нормально вести диалог, затем запустите API-шлюз. Скрипт должен хранить только адрес локального шлюза и ключ. Сначала запросите список моделей, затем отправьте короткий текст. Перед подключением полной программы убедитесь, что клиент поддерживает интерфейсы, совместимые с OpenAI или Anthropic.

| Настройка | Рекомендуемая начальная точка | Назначение | Примечания |
| ------ | ---------- | --------- | ----------------- |
| Область прослушивания | Только локальное использование | Снижение сетевой видимости | Не открывайте доступ в локальную сеть или интернет только для удобства отладки |
| API-ключ | Храните отдельно для текущего шлюза | Проверка запросов клиента | Не записывайте в репозитории, скриншоты или общие логи |
| Проверочный запрос | Сначала список моделей и короткий текст | Раздельная проверка подключения и генерации | При неудаче записывайте код состояния, но не полный ключ |

### Критерии завершения

Шлюз отображает статус [Работает]; список моделей доступен для чтения; запрос короткого текста успешен; после остановки шлюза клиент не может продолжать вызовы.

## Безопасные операции

{% hint style="danger" %}
API-ключ позволяет вызывать сервисы моделей, настроенные вами в Cherry Studio. При утечке ключа сначала остановите шлюз, затем в остановленном состоянии нажмите [Перегенерировать] и обновите все локальные клиенты.
{% endhint %}

* Во время работы шлюза порт и ключ доступны только для чтения; перед изменением остановите шлюз;
* Не публикуйте ключ в публичных репозиториях, Issue, логах или скриншотах в руководствах;
* Храните ключ только в программах, которым он необходим для вызовов;
* Использование и расходы все еще генерируются фактическим провайдером моделей; записи Cherry Studio можно просмотреть в [Настройках] → [Статистика использования].

<details>

<summary>Какова связь между API-шлюзом и сервисами моделей? </summary>

Сервисы моделей хранят соединения с провайдерами; API-шлюз преобразует эти возможности в совместимые интерфейсы. Сам по себе шлюз не предоставляет модели, для работы требуется как минимум один доступный провайдер и модель.

</details>

<details>

<summary>Порт работает, но клиент возвращает ошибку «Не авторизован». Что делать? </summary>

Убедитесь, что заголовок запроса содержит `Authorization: Bearer ...`, без лишних кавычек или пробелов, и проверьте, что ключ, используемый клиентом, совпадает с текущим значением на странице.

</details>
