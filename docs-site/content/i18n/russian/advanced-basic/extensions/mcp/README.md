# MCP и внешние инструменты

MCP — это способ подключения внешних инструментов и ресурсов для использования Agent. Cherry Studio позволяет управлять серверами MCP, встроенными серверами, сервисным рынком и некоторыми входами провайдеров, а затем связывать подключённые серверы с конкретными Agent.

### Когда нужен MCP

<figure><img src="../../../../../assets/79e45524b78de312b0ea7d2b.webp" alt="MCP и внешние инструменты — Иллюстрация"><figcaption></figcaption></figure>

* Agent должен вызывать сервисы, выходящие за рамки встроенных инструментов Cherry Studio;
* у команды уже есть базы данных, браузеры или бизнес-системы с интерфейсом MCP;
* требуется, чтобы один и тот же набор внешних возможностей использовался несколькими Agent;
* необходимо предоставлять модели инструменты, ресурсы или промпты в унифицированном формате.

Если нужен только фиксированный процесс, используйте навыки. Если требуется только поиск в базе знаний Cherry Studio, просто привяжите базу знаний. Не создавайте MCP исключительно ради «более продвинутого» решения.

### Добавление сервера

Путь: [Настройки] → [MCP] → [Серверы MCP] → [Добавить].

{% stepper %}
{% step %}
#### 1. Определите способ подключения

Локальные команды обычно используют стандартные потоки ввода-вывода; удалённые сервисы обычно предоставляют адрес SSE или HTTP, поддерживающий потоковую передачу. Заполните настройки в соответствии с инструкциями провайдера сервиса, не догадываясь по названию.
{% endstep %}

{% step %}
#### 2. Заполните конфигурацию и проверьте права

Для локальных серверов требуются команда, аргументы и переменные окружения; для удалённых серверов — URL, а для некоторых сервисов — авторизация. Перед сохранением проверьте источник команды и объём данных.
{% endstep %}

{% step %}
#### 3. Запустите и просмотрите инструменты

Включите сервер, дождитесь нормального состояния, затем откройте детали, чтобы проверить предоставляемые им инструменты, ресурсы и промпты. При неудачном подключении сначала просмотрите журнал сервера.

В списке инструментов разверните нужный инструмент, чтобы увидеть полное описание в формате Markdown, а также параметры, типы, обязательные поля и перечисленные значения, отображённые по уровням. Перед вызовом проверьте обязательные параметры; параметры объектов или массивов следует развернуть по уровням, чтобы не полагаться только на название инструмента при определении формата ввода.
{% endstep %}

{% step %}
#### 4. Привяжите к Agent

Откройте [Рабочая область] → меню Agent → [Редактировать] → [MCP] и включите этот сервер. Не запущенные серверы не могут быть корректно привязаны и использованы.
{% endstep %}
{% endstepper %}

### Встроенные серверы и сервисный рынок

[Встроенные MCP] предоставляют часто используемые возможности, которые можно установить или включить напрямую; [Сервисный рынок] используется для управления источниками сторонних рынков. Перед установкой всё равно следует проверять инструкции, команды, переменные окружения и права. Наличие встроенного входа не означает, что все операции внешнего сервиса безопасны.

<figure><img src="../../../../../assets/3892f8eaa6ef4645921a382d.webp" alt="① Встроенный список указывает, требуется ли учётная запись, API Key или конфигурация каталога; после установки всё равно необходимо завершить настройку и проверить подключение."><figcaption><p>① Встроенный список указывает, требуется ли учётная запись, API Key или конфигурация каталога; после установки всё равно необходимо завершить настройку и проверить подключение. </p></figcaption></figure>

QVeris находится в разделе [Встроенные серверы] и используется для обнаружения, проверки и вызова внешних возможностей Agent. После установки необходимо настроить `QVERIS_API_KEY`; не записывайте ключи в промпты Agent, навыки или публичные скриншоты.

### Использование промптов и ресурсов MCP в области ввода

Помимо инструментов, серверы могут предоставлять «промпты» и «ресурсы». После привязки сервера к текущему помощнику или Agent откройте панель [+] в области ввода:

* Выберите [Промпты MCP], чтобы вставить шаблон сервера в поле ввода; обязательные параметры шаблона отобразятся как заполняемые поля;
* Выберите [Ресурсы MCP], чтобы выбрать файлы, записи или другие ресурсы из привязанных серверов;
* Короткие текстовые ресурсы вставляются непосредственно в поле ввода; большие или бинарные ресурсы добавляются как ссылки, которые модель, поддерживающая вызов инструментов, читает при необходимости.

{% hint style="info" %}
Панель отображает только подключённые серверы в текущем диапазоне диалога, которые действительно предоставляют соответствующие возможности. Если [Промпты MCP] или [Ресурсы MCP] не видны, сначала проверьте соответствующие вкладки в деталях сервера, затем убедитесь, что текущий помощник или Agent привязан к этому серверу.
{% endhint %}

| -------- | -------------- | ----------------- | --------- | ------------- | ------------ |
| Состояние сервера | Определяется конфигурацией после добавления | Включайте и проверяйте по одному | Управление доступностью сервера | Первоначальное подключение, устранение неполадок | При одновременном сбое нескольких сервисов сложно определить причину |
| Привязка к Agent | Не привязывает все серверы автоматически | Привязывайте только необходимые для текущего Agent | Управление областью возможностей | Разделение задач между несколькими Agent | Избегайте использования контекста нерелевантными инструментами |
| Переменные окружения | Ключи не заполняются заранее | Используйте минимально необходимые права доступа | Предоставление аутентификации или параметров выполнения | Приватные сервисы | Закрывайте конфиденциальные данные перед скриншотами и экспортом |
| Одобрение инструментов | Определяется режимом прав Agent | Требуйте подтверждения для инструментов записи или с оплатой | Предотвращение непреднамеренных действий | Базы данных, файлы, внешние API | Для входов в каналы можно использовать более строгий режим |

### Пример пользователя: подключение проектной базы данных к Agent анализа

Администратор предоставляет подключение MCP только для чтения. Пользователь проверяет работоспособность сервера в [Настройки] → [MCP], затем привязывает его только к Agent «Анализ данных». Agent использует инструменты только для чтения для получения данных и записывает отчёт в рабочую директорию; инструменты, изменяющие данные, не включаются. Таким образом, даже при неверном понимании промпта, бизнес-база данных не будет изменена напрямую.

<details>

<summary>MCP и API-шлюз: в чём разница? </summary>

MCP подключает внешние инструменты к Cherry Studio; API-шлюз предоставляет возможности моделей Cherry Studio другим программам в формате совместимого API. Направление потока данных противоположное.

</details>

<details>

<summary>Сервер показывает статус «Подключено», но Agent не находит инструменты. Что делать? </summary>

Проверьте, привязан ли Agent к этому серверу, отключены ли инструменты и ожидают ли запросы прав обработки. После изменения конфигурации Agent отправьте новое сообщение, чтобы среда выполнения загрузила новые инструменты.

</details>

<summary>Сервер показывает статус «Подключено», но Agent не находит инструменты. Что делать? </summary>

</details>
