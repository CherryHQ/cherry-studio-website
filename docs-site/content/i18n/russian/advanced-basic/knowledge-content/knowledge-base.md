# Создание базы знаний и тестирование поиска

База знаний обрабатывает файлы, веб-страницы и заметки в виде извлекаемых фрагментов. Она подходит для ответов на вопрос «что сказано в материалах», но не означает, что модель навсегда запоминает весь документ.

## Создание и импорт материалов

{% stepper %}
{% step %}
### 1. Откройте [База знаний] → [Создать базу знаний]

Введите легко узнаваемое имя и выберите доступную модель эмбеддингов. Модель эмбеддингов преобразует материалы в поисковое представление; это не то же самое, что основная модель для диалога.
{% endstep %}

{% step %}
### 2. Выберите источники материалов

Можно добавлять файлы, папки, заметки или URL. Распространенные форматы документов: PDF, DOCX, Markdown, Excel, TXT и CSV; для сканов может потребоваться OCR для извлечения текста.
{% endstep %}

{% step %}
### 3. Дождитесь завершения обработки

Откройте детали файла, чтобы просмотреть предпросмотр и фрагменты. Если отсутствуют заголовки, есть ошибки кодировки или потеряна структура таблиц, сначала приведите исходный файл в порядок, затем повторите обработку.
{% endstep %}

{% step %}
### 4. Проведите тестирование поиска

Тестируйте с помощью вопросов, которые реально задают пользователи, а не только вводя заголовки файлов. Проверьте, релевантны ли возвращаемые фрагменты и содержат ли они полный контекст, прежде чем связывать их с Agent.
{% endstep %}
{% endstepper %}

### Проверка результатов поиска реальными вопросами

После того как материалы отображаются как [Готово], протестируйте их с помощью вопросов, которые действительно возникают в работе. Например, для базы регламентов можно спросить: «Можно ли возместить аренду автомобиля за рубежом?», затем проверьте, происходит ли ответ из правильных материалов и содержит ли он достаточный контекст.

| Результат | Следующий шаг |
| --------------- | ----------------------- |
| Найден правильный материал, фрагмент достаточен для ответа | Можно связать с Agent |
| Материал найден верно, но фрагмент обрезан | Сначала проверьте структуру исходника, затем отрегулируйте длину фрагмента |
| Найден устаревший регламент или нерелевантный материал | Удалите устаревшие материалы, добавьте более четкие заголовки и содержание |
| Нет результатов | Проверьте статус материалов и формулировку вопроса, не увеличивайте количество возвращаемых результатов без необходимости |

{% hint style="info" %}
После успешного тестирования поиска проверьте полный диалог в Agent. Это позволяет отличить «материалы не найдены» от «материалы найдены, но ответ неудовлетворительный».
{% endhint %}

## Как понимать настройки RAG

RAG означает «сначала поиск материалов, затем ответ модели». Типичные настройки управляют длиной фрагментов, перекрытием, количеством возвращаемых результатов и порогом релевантности.

| Настройка | Функция | Рекомендуемое начальное значение | Когда настраивать |
| ----- | -------------- | -------- | ------------------- |
| Длина фрагмента | Определяет, сколько содержания включает каждый извлекаемый фрагмент | Используйте начальные значения страницы | Когда фрагменты часто обрезают предложения или содержат слишком много тем |
| Перекрытие фрагментов | Сохраняет связь между соседними фрагментами | Поддерживайте небольшое перекрытие | Когда пункты пересекают фрагменты, а контекст часто разрывается |
| Количество возвращаемых | Сколько кандидатов предоставляется за раз | Начните с малого количества результатов | Увеличивайте при пропуске ключевых материалов, уменьшайте при избытке шума |
| Порог релевантности | Фильтрует нерелевантное содержание | Определяйте с помощью тестирования поиска | Повышайте при большом количестве нерелевантных результатов, понижайте при фильтрации правильных фрагментов |

### Пример применения: создание базы вопросов и ответов по внутренним регламентам

Сгруппируйте действующие регламенты по отделам, включайте в имена файлов тему и область действия. После импорта проведите тестирование поиска с реальными вопросами, такими как «Что делать при превышении лимита на проживание в командировке?» или «Кто утверждает отпуск в испытательный срок?». После подтверждения точности фрагментов свяжите эту базу знаний только с Agent «Вопросы по регламентам» и потребуйте указывать название материала в ответе; при отсутствии содержания явно сообщайте, что материал не найден.

{% hint style="warning" %}
База знаний не автоматически определяет, устарел ли файл. При изменении регламентов, цен и процессов обновляйте или удаляйте старые материалы и повторяйте тестирование поиска.
{% endhint %}

<details>

<summary>Почему после импорта нет результатов? </summary>

Проверьте статус обработки файла, подключение модели эмбеддингов и предпросмотр документа. Если в сканированном PDF нет извлекаемого текста, сначала настройте OCR или замените на версию с поиском.

</details>
