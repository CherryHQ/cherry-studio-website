# Каналы

Канал связывает Agent с внешней платформой сообщений. В настоящее время можно настроить Feishu, Telegram, QQ, WeChat, Discord и Slack; для каждой платформы требуются различные учётные данные бота и идентификаторы сессий.

{% hint style="success" %}
Рекомендуется сначала в разделе 【Работа】 сообщить Agent: «Настрой канал Feishu для текущего Agent, чтобы получать сообщения из групп и отправлять результаты задач». Agent запросит необходимую информацию в зависимости от цели, что быстрее, чем заполнять все поля для всех платформ. Для точной настройки используйте 【Настройки】→【Каналы】.
{% endhint %}

## Путь ручной настройки

【Настройки】→【Каналы】→выберите платформу→【Добавить】.

{% stepper %}
{% step %}
### 1. Подготовка учётной записи платформы

Создайте бота или приложение в соответствии с правилами платформы. Для Feishu и WeChat, поддерживающих процесс сканирования QR-кода, можно завершить настройку после активации канала, следуя подсказкам в интерфейсе. Для других платформ введите соответствующий Token или учётные данные приложения.
{% endstep %}

{% step %}
<figure><img src="../../../../assets/c074e4e1278ff6cd86f433ed.webp" alt="Сначала привяжите протестированный Agent и ограничьте разрешённый диапазон чатов; открывайте только те учётные данные и разрешения, которые необходимы для выполнения задач."><figcaption><p>Сначала привяжите протестированный Agent и ограничьте разрешённый диапазон чатов; открывайте только те учётные данные и разрешения, которые необходимы для выполнения задач. </p></figcaption></figure>

### 2. Привязка Agent и рабочей области

Выберите проверенный и работающий Agent и укажите рабочую область для сообщений канала. Внешние сообщения будут выполняться в этом контексте, не выбирайте каталоги, содержащие нерелевантные конфиденциальные файлы.
{% endstep %}

{% step %}
### 3. Ограничение источников сообщений

Введите разрешённые Chat ID, ID канала или ID пользователя. Пустое поле может означать разрешение для всех, точное значение зависит от описания поля текущей платформы. Можно отправить боту `/whoami`, чтобы получить идентификатор в правильном формате.
{% endstep %}

{% step %}
### 4. Выбор режима разрешений и активация

По умолчанию используется 【Наследовать настройки Agent】. Для открытых групп, групп с несколькими участниками или ненадёжных источников следует использовать более строгий режим. После активации сначала отправьте тестовое сообщение без побочных эффектов.
{% endstep %}
{% endstepper %}

## Рекомендуемая конфигурация

| Параметр | Значение по умолчанию | Рекомендуемая начальная точка | Функция | Сценарии применения | Примечания |
| -------- | --------- | --------------- | ------------ | --------- | ---------------- |
| Привязанный Agent | Требуется выбор | Подготовьте отдельный Agent для канала | Определяет, кто обрабатывает сообщения | Групповые чаты, личные сообщения бота | Не смешивайте с Agent с высокими привилегиями для разработки |
| Рабочая область | Требуется выбор | Используйте отдельный каталог без личных данных | Ограничивает обрабатываемые файлы | Сбор данных в группе, доставка отчётов | Не выбирайте домашний каталог пользователя |
| Разрешённые источники сообщений | Зависит от поля платформы | Сначала разрешите только тестовые аккаунты или группы | Ограничивает, кто может активировать Agent | Внутреннее тестирование, командные группы | Прочитайте описание поля перед оставлением пустым |
| Режим разрешений | 【Наследовать настройки Agent】 | Используйте более строгое одобрение для внешних входов | Управляет операциями инструментов | Открытые группы, группы с несколькими участниками | Не рекомендуется использовать 【Полный доступ】 |

## Сценарий использования: группа дежурства команды

Создайте Agent, который обрабатывает только руководство дежурного, привяжите протестированную базу знаний и отдельную рабочую область, разрешите активацию только из группы дежурства. Сначала протестируйте сообщения типа «найти пункт регламента» и «ответ не найден», затем протестируйте генерацию сводки передачи смены без конфиденциальной информации.

### Критерии завершения

Источники вне разрешённого списка не могут активировать задачи; ответы возвращаются в указанную группу; при отсутствии содержимого в базе знаний это явно указывается; запись файлов по-прежнему требует одобрения.

## Ключевые моменты настройки платформ

| Платформа | Основные учётные данные | Ключевые моменты области сессии |
| --------- | ----------------------- | ------------------ |
| Feishu / Lark | App ID, App Secret или процесс сканирования QR-кода | Chat ID и домен (китайский/международный) |
| Telegram | Bot Token | Chat ID |
| QQ | App ID, Client Secret | Формат идентификатора для личных сообщений, групп или каналов |
| WeChat | Вход по QR-коду или путь к учётным данным | Разрешённые ID пользователей |
| Discord | Bot Token | ID канала или личных сообщений |
| Slack | Bot Token, App Token | Socket Mode и ID канала |

{% hint style="danger" %}
Bot Token, App Secret и токены верификации эквивалентны паролю от учётной записи. Не записывайте их в долгосрочную память Agent, промпты задач, скриншоты или публичные Issue; при утечке немедленно отзовите и перегенерируйте их на стороне платформы.
{% endhint %}

<details>

<summary>Что делать, если в запланированной задаче нельзя выбрать канал как цель получения? </summary>

Сначала отправьте боту сообщение на соответствующей платформе, чтобы Cherry Studio зафиксировал доступный Chat ID, затем вернитесь к запланированной задаче и выберите цель уведомления.

</details>

<details>

<summary>Что делать, если канал подключён, но не отвечает? </summary>

Проверьте разрешённые ID сессий, привязанного Agent, рабочую область и режим разрешений, затем просмотрите журнал канала. Если платформа получила сообщение, но Agent не выполнил его, продолжите проверку API-шлюза и состояния задачи Agent.

</details>
