# 長文書のレビュー

プロダクトマネージャーが長文の提案書を受け取り、事実上の問題点、構造上の欠落、実行可能な修正点を見つけ出す必要があります。同時に、原稿と人間による確認プロセスを保持します。以下のアプローチは、レポート、制度、入札資料、プロダクト提案書に適しています。

## 推奨される組み合わせ

* 【対話】：異なるモデルのレビュー観点の迅速な比較；
* 【ワーク】Agent：ワークディレクトリを読み取り、修正稿を生成；
* ナレッジベース：制度、用語、または過去の資料を提供；
* 右側の【ファイル】：原稿と成果物の確認。

## 操作フロー

{% stepper %}
{% step %}
### 1. 原稿とレビュー基準の準備

原稿を独立したワークディレクトリに配置し、簡潔なレビュー説明書を別途作成します。読者、目的、変更できない事実、納品形式を明確に記述してください。
{% endstep %}

{% step %}
### 2. まず小範囲でキャリブレーションを行う

1つの章を選び、Agentに「問題点、原文の位置、影響、提案」の形式で出力させます。尺度が適切であることを確認してから、全文を処理してください。
{% endstep %}

{% step %}
### 3. 事実と表現を分離する

Agentに、確認が必要な事実を単独でリストアップさせ、言語の磨き上げで不確実な内容を隠さないようにします。重要な数値は元の資料に戻って照合してください。
{% endstep %}

{% step %}
### 4. 新しいファイルを生成し、人間が最終決定する

原ファイルを保持し、`review/` 以下に問題点リストと修正稿を生成するよう要求します。右側の【ファイル】で段落ごとに確認し、その後エクスポートまたは共有してください。
{% endstep %}
{% endstepper %}

## 例示タスク

```
現在のディレクトリにある proposal.docx をレビューしてください。章ごとに事実上の問題、構成の不足、表現上の問題を原文の位置とともに列挙してください。元のファイルは変更せず、一覧を確認した後に review/ 配下へ改訂版と確認事項を作成してください。
```

## 使用前の準備と完了基準

| 項目 | 推奨される準備 |
| ---- | -------------------------------- |
| ファイル | 原文、レビュー要件、出力ディレクトリを分離して配置 |
| 推奨組み合わせ | 専用 Agent + 本プロジェクトのファイルのみを含むワークディレクトリ + 【逐次確認】 |
| 抜き打ち検査方法 | まず1章を抜き出して、引用形式と判断尺度を確認 |
| 完了基準 | 各意見に原文の位置を付与；未読部分は明確にマーク；原ファイルが上書きされていない |

契約、レポート、論文、規格などの構造化レビューに適しています。法律、医療、財務の結論に関わる場合、出力は補助資料としてのみ使用できます。

{% hint style="info" %}
文書が長い場合、1つの対話内で全文を繰り返し貼り付けないでください。Agentにワークディレクトリを直接読み取らせ、章ごとに中間成果物を残すことで、レビューと復元が容易になります。
{% endhint %}
