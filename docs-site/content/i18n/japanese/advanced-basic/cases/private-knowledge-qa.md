# プライベートナレッジベースによるQ&A

人事チームは、同僚が現行の制度を照会できるようにしたいが、Agentが常識に基づいて回答を補完することを望んでいない。このケースでは、資料の範囲、リコールテスト、回答ルールをまとめて設定します。内容が見つからない場合、Agentは明確にその旨を伝える必要があります。

## 操作手順

{% stepper %}
{% step %}
### 1. トピック単一のナレッジベースを作成

現行資料をまとめ、重複や期限切れのバージョンを削除します。ファイル名にはトピックと適用範囲を明記します。
{% endstep %}

{% step %}
### 2. 実際の質問でリコールテストを実施

混同しやすい条項、口語的な質問、回答が存在しない質問を少なくともテストします。資料やRAG設定を調整し、返却されるスニペットが安定するまで続けます。
{% endstep %}

{% step %}
### 3. 専用Agentを作成

このナレッジベースのみをバインドし、プロンプト内で「資料を優先的に引用すること。見つからない場合は『見つかりません』と伝えること。常識で制度を補完しないこと」を指定します。権限は最小限に保ちます。
{% endstep %}

{% step %}
### 4. 小規模な範囲から利用を開始

まず社内検索に使用し、承認や専門的な判断を直接代替しないようにします。誤答した質問を収集し、資料とリコールテストに戻って修正します。
{% endstep %}
{% endstepper %}

## 質問例のルール

```
回答では最初に結論を示し、その後に資料名と該当箇所を記載してください。資料間に矛盾がある場合はその内容を列挙し、こちらに代わって選択しないでください。ナレッジベースに回答がない場合は「現在の資料には見つかりません」と明記してください。
```

## 推奨組み合わせと完了基準

| 項目 | 推奨される方法 |
| ----- | --------------------------- |
| ナレッジベース | 1つのトピックにつき1セットの資料とし、重複と期限切れのバージョンを削除 |
| リコールテスト | 標準的な質問、口語的な質問、回答が存在しない質問を同時にテスト |
| Agent | 必要なナレッジベースのみをバインドし、資料の引用と補完の禁止を要求 |
| 完了基準 | 正しい段落を見つけられること。競合する資料が列挙されること。回答がない場合は明確に「見つかりません」と伝えること |

{% hint style="danger" %}
プライベートナレッジベースの内容は、選択した埋め込みモデルと対話モデルサービスによって処理されます。使用前に、資料の機密要件とサービス範囲を確認し、キーやアカウント認証情報をナレッジ資料としてインポートしないようにしてください。
{% endhint %}
