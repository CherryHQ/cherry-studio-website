# チャンネルと定期日報

運営チームは、各営業日の午前中に指定された資料を自動的に集約し、日報を生成してチームのチャンネルに送信することを希望しています。自動化の前に一度手動で実行し、データの欠落、パスエラー、通知先の問題を早期に発見できるようにします。

## 事前準備

* 【作業】で検証済みの日報用 Agent
* 明確なデータソースと、必要な資料のみを含む作業ディレクトリ
* 固定フォーマットをスキルとして作成
* 接続済みかつメッセージ範囲が制限されたチャンネル
* 営業日限定の定期タスク

## 設定手順

{% stepper %}
{% step %}
### 1. 手動で日報を1件生成する

Agent に「進捗、指標、リスク、TODO」の4つの部分を含む出力を求めます。データが欠落している場合に明確に説明しているか、内容を捏造していないかを確認します。
{% endstep %}

{% step %}
### 2. 通知チャンネルを設定する

まず Agent の対話内で接続するプラットフォームとグループを指定し、次に【設定】→【チャンネル】で認証情報、許可されたセッション ID、ワークスペース、権限モードを確認します。
{% endstep %}

{% step %}
### 3. 定期タスクを作成する

Agent に営業日のスケジュールを作成させるか、【設定】→【定期タスク】→【新規作成】を開きます。日報用 Agent、作業ディレクトリ、実行時刻、通知チャンネルを選択します。
{% endstep %}

{% step %}
### 4. すぐにテストする

保存後、【実行】をクリックし、生成されたセッション、実行履歴、チャンネルメッセージを確認します。翌日まで待ってパスや受信先のエラーを発見しないようにします。
{% endstep %}

{% step %}
### 5. 監視して調整する

最初の数回の実行で所要時間、使用量、失敗原因を確認します。データソースやチームのフォーマットが変更された場合は、スキルまたはタスクのプロンプトを更新し、複数の場所で矛盾するルールを管理しないようにします。
{% endstep %}
{% endstepper %}

## タスクプロンプトの例

```
現在の作業ディレクトリで昨日追加されたデータを読み、中国語の運用日報を作成してください。進捗、主要指標、異常、本日のタスクを必ず含めます。データがない場合は「データなし」と記載して不足ファイルを列挙し、数値を補完しないでください。結果を設定済みのチームチャンネルへ送信し、作業ディレクトリにも Markdown ファイルを保存してください。
```

## 失敗時の対処

| 現象 | 確認箇所 |
| ------ | --------------------- |
| 実行されていない | 定期タスクの状態、次回実行時刻、システムの休止状態 |
| 実行失敗 | 【実行履歴】→【セッションを表示】 |
| ファイルが生成されていない | 作業ディレクトリ、権限リクエスト、Agent のファイルツール |
| メッセージが届いていない | チャンネルの状態、受信先、プラットフォームログ |
| 内容が重複している | ハートビートと複数の同じスケジュールが同時に有効化されていないか |

## 推奨組み合わせと完了基準

| 項目 | 推奨事項 |
| ----- | ---------------------------------- |
| Agent | まず手動で同じ日報を実行し、その後定期タスクに引き継ぐ |
| スケジュール | 【毎日】または【営業日】を優先使用し、次回実行時刻を確認する |
| チャンネル | まずテストセッションに送信し、その後正式なグループに切り替える |
| 完了基準 | 実行履歴が成功；レポートファイルが開ける；チャンネルに1件のみ受信；データ欠落時に結果を捏造しない |

{% hint style="warning" %}
定期タスクは無人時に実行されます。本番運用前にファイル範囲を最小限にし、適切な権限を設定し、高リスクな書き込みや外部変更を完全アクセスモードに委ねないようにします。
{% endhint %}

{% hint style="info" %}
スクリーンショットのデモ環境では外部チャンネルがバインドされていないため、保存・有効化済みのタスクのみが表示されています。本番運用では、【実行】をクリックし、【実行履歴】が成功することを確認し、テストチャンネルで実際のメッセージが1件受信されたことを確認してから日常運用に移行してください。
{% endhint %}
