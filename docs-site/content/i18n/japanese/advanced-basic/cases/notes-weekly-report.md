# 週報の生成

プロジェクトマネージャーが1週間にわたって会議メモ、進捗更新、断片的なタスクを蓄積しており、金曜日に構造が安定し、事実を確認できる週報にまとめたいと考えています。重要なのは、Agentに欠落した状態を推測させるのではなく、まず記録方法を統一し、その後Agentに集約させることです。

## 操作手順

{% stepper %}
{% step %}
### 1. 記録方法の統一

毎日、同じメモフォルダに事項を記録し、少なくとも日付、結果、責任者、状態を含めます。未完了の事項は完了済みとして記載しないでください。
{% endstep %}

{% step %}
### 2. 金曜日にまず手動で整理

重複する事項を統合し、重要な数値やリンクを補完します。長期的な背景情報はナレッジベースに格納し、今週の变化は現在のメモに残します。
{% endstep %}

{% step %}
### 3. Agentに草稿の生成を依頼

「今週完了、進行中、リスク、来週計画」に従って出力するよう求め、資料が不足している場合は補完が必要な項目を列挙させます。
{% endstep %}

{% step %}
### 4. 確認してエクスポート

状態、数値、責任者を確認した後、【メモ】内で最終版を作成しエクスポートします。安定したフォーマットはスキルとして作成し、来週以降も再利用できます。
{% endstep %}
{% endstepper %}

## 例示タスク

```
今週のノートを読み、週報の下書きを作成してください。同じ項目はまとめますが、日付ごとの状態変化は残し、完了状況を推測しないでください。担当者、数値、次のステップが不足している場合は「要追記」に記載してください。
```

## 推奨組み合わせと完了基準

| 項目 | 推奨される方法 |
| ----- | --------------------------------- |
| 日常入力 | メモは日付またはプロジェクト別に記録し、事実とタスクのみ記載 |
| Agent | 固定の週報構造を使用し、今週のメモを読み取った後に生成 |
| 出力 | 週報は独立したファイルに書き込み、元のメモを上書きしない |
| 完了基準 | 各進捗が元のメモに遡れること。未完了事項に責任者または次のステップがあること。根拠のないデータの追加がないこと |

記録済みの作業を週報にまとめるのに適していますが、Agentに断片的な記憶に基づいて1週間の成果を推測させるのには適していません。

{% hint style="info" %}
固定時間での自動週報生成の前に、まず数週間手動で実行してください。入力フォーマットが安定し、欠落情報の処理が信頼できることを確認してから、定期タスクを作成してください。
{% endhint %}
