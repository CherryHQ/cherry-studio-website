# Agent によるプロジェクトファイルの納品

運営担当者が散在する資料を整理し、インデックス、要約、納品ファイルを作成するケースです。誤って元ファイルを修正しないよう、Agent の作業ディレクトリ、変更可能な範囲、検収方法を事前に明確にしておく必要があります。

## 適用タスク

* 散在する資料を目次やインデックスに整理する
* テンプレートに基づいて複数のドキュメントを生成する
* コードを変更し、変更説明を残す
* ファイルの一括リネーム、変換、チェックを行う

## 操作手順

{% stepper %}
{% step %}
### 1. 最小限の作業ディレクトリを選択

現在のプロジェクトディレクトリのみを選択します。重要なファイルには事前にバックアップまたはバージョン管理を行い、権限は【逐次確認】から開始します。
{% endstep %}

{% step %}
### 2. 変更可能範囲と不可範囲を明確にする

読み取り専用ファイル、成果物の保存場所、事前確認が必要な操作、完了基準を明記します。
{% endstep %}

{% step %}
### 3. まず Agent に計画を立てさせる

高リスクタスクでは【プランニングのみ】を使用できます。ファイル一覧と手順を確認した後、編集許可モードに切り替えて実行します。
{% endstep %}

{% step %}
### 4. 右側で状態とファイルを確認

長時間実行タスクでは、まず【状態】で承認待ちかどうかを確認します。成果物が生成された後は【ファイル】でプレビューします。問題がないことを確認してから引き渡しを行い、「タスク終了」だけで検収に代用しないようにします。
{% endstep %}
{% endstepper %}

## 例示タスク

```
現在のディレクトリを整理してください。raw/ 内のファイルは読み取り専用とし、deliverables/ に索引、要約、不足資料の一覧を作成してください。削除、上書き、一括名称変更は事前に確認を取り、最後に追加・変更したファイルを列挙してください。
```

## 推奨組み合わせ

| 機能 | 推奨用法 | 理由 |
| ---- | ------------ | ----------------- |
| 作業ディレクトリ | プロジェクトごとに独立したディレクトリを使用 | ファイルの境界と納品先が明確になる |
| 権限 | ファイル変更は【逐次確認】を維持 | 誤削除、上書き、範囲外書き込みの発見が容易になる |
| 状態パネル | 終了前に成果物と失敗ステップを確認 | 「Agent が完了と言った」だけで判断しない |
| 新規タスク | 新フェーズまたは新規クライアントでは別タスクを作成 | 過去の要件が現在の納品に影響しないようにする |

{% hint style="danger" %}
【完全アクセス】は確認回数を減らしますが、誤操作の影響範囲も拡大します。隔離、信頼性があり、復元可能なディレクトリでのみ、一時的な使用を検討してください。
{% endhint %}
