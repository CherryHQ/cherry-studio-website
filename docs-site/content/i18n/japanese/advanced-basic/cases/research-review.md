# 複数モデルによる研究レビュー

あるプロダクトチームが四半期レビューを準備しています。社内資料は揃っていますが、公開情報の補完と、異なるモデルが提示する視点の比較が必要です。最終的に、出典に遡って検証でき、事実と判断を明確に区別した研究レポートを納品します。

## 推奨構成

* 【チャット】複数モデル：共通点、相違点、見落としを特定します。
* 研究 Agent：タスクの推進、サブタスクの分割、レポート生成を行います。
* ナレッジベース：社内資料を検索します。
* ウェブ検索または信頼できる MCP：外部ソースを補完します。
* 作業ディレクトリ：原材料と最終成果物を保存します。

## 操作手順

{% stepper %}
{% step %}
### 1. 同じ質問で視点を比較する

【チャット】で複数のモデルを選択し、それぞれに結論、仮定、出典、不確実な項目を列挙させます。実際の対立点を研究対象の質問として整理します。
{% endstep %}

{% step %}
### 2. 研究 Agent を作成する

関連するナレッジベースと研究スキルをバインドし、権限は【都度確認】に設定します。作業ディレクトリでは、原材料と `report/` 出力ディレクトリを分離します。
{% endstep %}

{% step %}
### 3. サブタスクを割り当てる

Agent に事実のタイムライン、データの変化、外部の視点をそれぞれ確認させ、メイン Agent が対立点を比較します。確認できない情報は「要確認」として保持し、無理に統合しません。
{% endstep %}

{% step %}
### 4. レポート生成と手動レビュー

レポートには結論、出典、不確実な項目、今後のアクションを含めます。右側の【ファイル】で引用、日付、数値を確認してから公開します。
{% endstep %}
{% endstepper %}

## 例示タスク

```
現在のディレクトリにあるプロジェクト資料を振り返り、公開情報を補足してください。事実、判断、提案を分け、外部情報には出典リンクを残してください。タイムライン、データ、リスクを個別に確認し、最後に report/review.md へレポートを作成してください。raw/ 内のファイルは変更しないでください。
```

## 事前準備と完了基準

| 項目 | 推奨準備 |
| ---- | ------------------------------- |
| 研究課題 | 比較対象となる結論を一文で明確にします |
| ソース要件 | 期間、地域、許容されるソースを指定します |
| 推奨構成 | 複数モデル比較で差異を収集、ブランチで追問、ノートで確認済み結論を保存します |
| 完了基準 | 重要な結論はすべて出典に遡れること。相違点は個別に列挙すること。未確認の内容を事実として記載しないこと |

このケースは、視点の比較や意思決定プロセスのレビューが必要な研究に適していますが、複数モデルの投票をそのまま事実判断として扱うことには適していません。

{% hint style="danger" %}
金融、医療、法律などの高リスクテーマでは、モデルの結論だけに依存しないでください。レポートには出典を保持し、適切な経験や資格を持つ者がレビューを行う必要があります。
{% endhint %}
