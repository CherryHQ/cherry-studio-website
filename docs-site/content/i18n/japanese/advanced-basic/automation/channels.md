# チャネル

チャネルは、Agent を外部メッセージプラットフォームに接続します。現在設定可能なプラットフォームは、Feishu、Telegram、QQ、WeChat、Discord、Slack です。各プラットフォームで必要なボット認証情報と会話識別子は異なります。

{% hint style="success" %}
まずは【作業】で Agent に「現在の Agent 用に Feishu チャネルを設定し、グループメッセージを受信してタスク結果を送信できるようにしてください」と指示することをお勧めします。Agent は用途に応じて必要な情報を質問するため、すべてのプラットフォームのフィールドに直接対応するよりも迅速です。正確な修正が必要な場合は、【設定】→【チャネル】を使用してください。
{% endhint %}

## 手動設定の手順

【設定】→【チャネル】→プラットフォームを選択→【追加】。

{% stepper %}
{% step %}
### 1. プラットフォームアカウントの準備

プラットフォームのルールに従って、ボットまたはアプリを作成します。Feishu と WeChat は、QR コードスキャンに関連するフローをサポートする場合、チャネルを有効化した後に画面の指示に従って完了できます。その他のプラットフォームでは、対応する Token またはアプリ認証情報を入力してください。
{% endstep %}

{% step %}
<figure><img src="../../../../assets/c074e4e1278ff6cd86f433ed.webp" alt="チャネル — 説明画像"><figcaption><p>テスト済みの Agent をバインドし、許可されるチャット範囲を制限してください。認証情報と権限は、タスク完了に必要な部分のみを開放してください。</p></figcaption></figure>

### 2. Agent とワークスペースのバインド

検証済みで利用可能な Agent を選択し、チャネルメッセージ用にワークスペースを指定します。外部メッセージはこのコンテキスト内で実行されるため、無関係な機密ファイルを含むディレクトリを選択しないでください。
{% endstep %}

{% step %}
### 3. メッセージソースの制限

許可する Chat ID、チャネル ID、またはユーザー ID を入力します。空欄の場合、すべて許可されることを意味する場合がありますが、具体的な内容は現在のプラットフォームのフィールド説明に従ってください。ボットに `/whoami` を送信して、正しい形式の識別子を取得することもできます。
{% endstep %}

{% step %}
### 4. 権限モードを選択して有効化

デフォルトでは【エージェント設定を継承】を使用します。公開グループ、多数のメンバーがいるグループ、または信頼できないソースに対しては、より厳格なモードを使用してください。有効化後、まず副作用のないテストメッセージを送信してください。
{% endstep %}
{% endstepper %}

## 推奨設定

| 設定項目 | プロダクト既定値 | 推奨される初期値 | 役割 | 適用シーン | 注意事項 |
| -------- | --------- | --------------- | ------------ | --------- | ---------------- |
| Agent のバインド | 選択が必要 | チャネル用に個別の Agent を用意 | メッセージの処理者を決定 | グループチャット、ボットとの個別チャット | 高権限の開発用 Agent と混用しない |
| ワークスペース | 選択が必要 | 個人データを含まない専用ディレクトリを使用 | 処理可能なファイルを限定 | グループ内での収集、日報の提出 | ユーザーのホームディレクトリを選択しない |
| 許可されたメッセージソース | プラットフォームのフィールドによる | まずテストアカウントまたはテストグループのみ許可 | Agent をトリガーできる者を制限 | 内部テスト、チームグループ | 空欄にする前にフィールド説明を読む |
| 権限モード | 【エージェント設定を継承】 | 外部入口ではより厳格な承認を使用 | ツール操作を制御 | 公開グループ、多数のメンバーがいるグループ | 【完全アクセス】の使用は非推奨 |

## 使用シーン：チームのオンコールグループ

オンコールマニュアルのみを処理する Agent を作成し、リコールテスト済みのナレッジベースと専用ワークスペースをバインドし、オンコールグループからのトリガーのみを許可します。まず「制度を1件照会する」と「回答が見つからない」の2種類のメッセージをテストし、その後、機密情報を含まない引き継ぎサマリーを生成するテストを行います。

### 完了基準

許可されていないソースからのトリガーは不可；回答は指定されたグループに返される；ナレッジベースに内容がない場合は明確に説明する；ファイル書き込みには引き続き承認を要求する。

## プラットフォーム設定のポイント

| プラットフォーム | 主な認証情報 | 会話範囲のポイント |
| --------- | ----------------------- | ------------------ |
| Feishu / Lark | App ID、App Secret、または QR コードスキャンフロー | チャット ID と国内/国際ドメイン |
| Telegram | Bot Token | Chat ID |
| QQ | App ID、Client Secret | 個別チャット、グループまたはチャネル識別子の形式 |
| WeChat | QR コードログインまたは認証情報パス | 許可されたユーザー ID |
| Discord | Bot Token | チャネルまたは個別チャット ID |
| Slack | Bot Token、App Token | Socket Mode とチャネル ID |

{% hint style="danger" %}
ボット Token、App Secret、検証トークンはアカウントのパスワードと同様です。Agent の長期メモリ、タスクプロンプト、スクリーンショット、公開 Issue に書き込まないでください。漏洩が発生した場合は、直ちにプラットフォーム側で失効させ、再発行してください。
{% endhint %}

<details>

<summary>定期タスクでチャネル受信ターゲットを選択できない場合はどうすればよいですか？</summary>

まず対応するプラットフォームで、ボットにメッセージを1件送信し、Cherry Studio が利用可能な Chat ID を記録させます。その後、定期タスクに戻って通知ターゲットを選択してください。

</details>

<details>

<summary>チャネルは接続されているが応答がない場合はどうすればよいですか？</summary>

許可された会話 ID、バインドされた Agent、ワークスペース、権限モードを確認し、チャネルログを参照してください。プラットフォームがメッセージを受信したが Agent が実行していない場合は、API ゲートウェイと Agent タスクの状態を継続して確認してください。

</details>
