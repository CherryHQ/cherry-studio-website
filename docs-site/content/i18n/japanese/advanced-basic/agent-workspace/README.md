# Agent ワークスペース

Agent は、明確な目標があり、ツールやファイルの使用が必要で、複数ステップにわたる可能性があるタスクの処理に適しています。入口は左側のナビゲーションにある【作業】です。旧版チュートリアルの上部タブではありません。

{% hint style="success" %}
最も手間のかからない設定方法は、まず Agent に達成したいことを伝え、次に不足しているモデル、ツール、ナレッジベース、またはチャネルを確認させることです。正確な制御が必要な場合は、Agent 編集ウィンドウまたは【設定】を開いて手動で調整してください。
{% endhint %}

### ワークスペースの構成要素

| 部分 | 役割 | 注目すべきタイミング |
| ----- | ----------------- | ----------------- |
| Agent | 役割、モデル、プロンプト、機能を保存 | 同種の作業を繰り返し行う場合 |
| タスク | 1回の連続的な作業記録 | 各目標ごとに個別のタスクを作成し、コンテキストを保持しやすくする |
| 作業ディレクトリ | Agent が直接処理できるファイル範囲 | コード、資料整理、ドキュメント生成などのファイル関連タスク |
| 入力エリア | 目標、添付ファイルを送信し、ツールを呼び出す | タスクを開始したり、要求を追加したりする場合 |
| 右側パネル | ステータス、ファイル、サブタスク、メッセージフローを確認 | 長時間のタスクを追跡、成果物を確認、またはトラブルシューティングを行う場合 |

### タスクを開始する

{% stepper %}
{% step %}
#### 1. 【作業】を開き、Agent を選択する

適切な Agent が既に存在する場合は直接選択してください。存在しない場合は【エージェントを追加】をクリックし、【基本情報】で実行モードを選択してから、システムプロンプト、スキル、ナレッジベースの4ステップで作成を完了します。実行モードは作成後に切り替えられません。
{% endstep %}

{% step %}
#### 2. 作業ディレクトリを選択する

ローカルファイルの処理が必要な場合は、今回のタスクが所在するディレクトリを選択してください。ファイルに関係しない場合は、アプリケーションが作成したデフォルトのワークスペースを使用できます。1つのタスクは1つのワークスペースに対応しており、Agent が無関係なディレクトリ間を行き来して検索することを避けます。
{% endstep %}

{% step %}
#### 3. 結果でタスクを説明する

Agent に何を納品すべきか、どの資料を使用できるか、どのような制限があるか、どのようにすれば完了とみなされるかを伝えます。例：

```
現在のディレクトリにある会議記録を読み、決定事項、担当者、期限を整理して action-items.md を作成してください。元のファイルは変更しないでください。
```
{% endstep %}

{% step %}
#### 4. 右側パネルでプロセスと成果物を確認する

【ステータス】ではアクティブなタスク、サブエージェント、ワークフロー、バックグラウンドコマンドが表示されます。【ファイル】ではテキスト成果物をプレビューおよび編集できます。開発者モードを有効にすると、【呼び出しチェーン】も確認できます。
{% endstep %}
{% endstepper %}

### API ゲートウェイに関する注意

Agent の実行は Cherry Studio の API ゲートウェイに依存しています。ゲートウェイが有効化されていない場合、アプリケーションは【有効化して起動】と表示します。また、【設定】→【API ゲートウェイ】でポート、実行状態、ローカルセキュリティソフトウェアによるブロックを確認することもできます。

{% hint style="warning" %}
API ゲートウェイは Agent の実行に必要ですが、インターフェースをネットワークに公開することを意味しません。デフォルトのローカル使用を維持してください。他のプログラムから明示的に呼び出させる必要がある場合のみ、URL と API キーをコピーしてください。
{% endhint %}

### 1つの Agent か、複数の Agent か

* 役割と機能が同じだがタスクが異なる場合：1つの Agent を再利用し、複数のタスクを作成します。
* 役割、資料範囲、または権限が異なる場合：複数の Agent に分割します。
* 1つの目標に対して並行調査や複数ステップの協調が必要な場合：まず1つの Agent にサブエージェントまたはワークフローを使用させ、すぐに多数の Agent を手動で作成する必要はありません。

### ユーザー事例：プロジェクト資料の整理

プロダクトマネージャーは、要件説明、インタビュー記録、競合他社の資料を同じディレクトリに配置し、「要件整理」Agent を作成して、プロダクトナレッジベースをバインドし、【逐次確認】権限を使用します。Agent はまず資料を読み取り、次に要件リストと確認待ちの質問を新しいファイルに書き込みます。プロダクトマネージャーは右側の【ファイル】で直接テキストを修正し、元の資料は変更されません。

<details>

<summary>なぜ Agent は新たにバインドした機能を見ることができないのですか？</summary>

Agent の編集内容は自動的に保存されます。生成中の返信は中断されません。モデル、スキル、MCP、ナレッジベースなどの変更は、次のメッセージから有効になります。それでも表示されない場合は、まず機能が有効化されていることを確認し、新しいメッセージを送信してください。

</details>

<details>

<summary>作業ディレクトリを削除すると、ディスク上のファイルも一緒に削除されますか？</summary>

タスクリストから作業ディレクトリを削除する場合、Cherry Studio 内のディレクトリ記録と当該ディレクトリ配下のタスク記録のみが削除され、ディスク上の実際のディレクトリは削除されません。Agent がタスク実行中に実施するファイル操作は、選択された権限モードの影響を受けます。

</details>
