# 権限、メモリとバックグラウンドタスク

Agent はファイル、ターミナル、ネットワーク操作を実行でき、サブエージェントやバックグラウンドタスクを呼び出すこともできます。権限は「事前に確認するか」を、メモリは「次回も知っているか」を、右側のステータスパネルは「今何をしているか」を示します。

### 権限モード

| モード | 動作 | 適用シーン | 注意事項 |
| -------- | ------------- | ------------- | ---------------- |
| 【逐次確認】 | ファイルの編集やコマンド実行前に確認 | デフォルトの起点、実際のプロジェクトディレクトリ | 操作が多いと頻繁に確認が必要ですが、最も制御しやすい |
| 【自動承認編集】 | ファイルの編集は可能、コマンド実行前に確認 | ドキュメント整理、復元可能なコード修正 | 作業ディレクトリとバージョン管理の状態を先に確認 |
| 【スマート承認】 | セキュリティチェックに基づいて許可を決定 | モデルがサポートしておりタスクの境界が明確な場合 | 一部のモデルでは依然として逐次確認を行う可能性がある |
| 【プランニングのみ】 | プランニングのみ、ファイルの編集はしない | 案のレビュー、リリース前の審査 | まず計画を確認してから実行する場合に適する |
| 【完全アクセス】 | 権限チェックをスキップ | 隔離、信頼でき、復元可能な環境 | ファイルの削除やネットワークアクセスの可能性があり、リスクが最も高い |

異なる実行モードで提供される権限範囲は完全に同一ではありません：Pi は【プランニングのみ】を提供せず、新しい Pi Agent を作成する際はデフォルトで【スマート承認】を使用します。DeepSeek Harness は【スマート承認】を提供しません。【拡張：Claude Agent】は完全な5つのモードを提供します。

設定パス：左側ナビゲーション【ワーク】→ Agent メニュー→【編集】→【基本】→【権限モード】。

{% hint style="danger" %}
チャンネルは Agent の権限モードを個別に上書きできます。外部チャット入口では予期しない指示を受けやすいため、通常は【エージェント設定を継承】または Agent よりも厳格なモードを選択し、確認の手間を省くために完全アクセスを開放しないでください。
{% endhint %}

### Agent メモリ

Agent のメモリは Agent に従属し、特定のタスクや作業ディレクトリに従属しません。長期的に有効な好み、プロジェクトの事実、技術的な決定、経験の保存に適しています。一時的な進捗はタイムスタンプ付きのログとして記録し、後続のタスクで検索できるようにします。

【ワーク】で直接 Agent に指示してください：

```
覚えておいてください。外部公開する中国語の文章では全角句読点を使い、誇張した見出しは使いません。今後の関連タスクではこのルールに従ってください。
```

修正が必要な場合は、古い情報が無効になったことを明確に示し、メモリの更新を要求してください。パスワード、API キー、機密の個人情報、または短期的に関連しない内容を長期メモリに書き込まないでください。

### サブエージェント、ワークフロー、バックグラウンドコマンド

複雑なタスクでは、Agent は調査、整理、検証をサブエージェントに割り当てたり、ワークフローで複数のステップを編成したりできます。時間のかかるコマンドはバックグラウンドで実行でき、対話全体をブロックする必要はありません。Agent はユーザーの確認後、新しいセッションを作成したり、既存のセッションにタスクを送信したりすることもできます。リクエストは即座に返され、完了結果はその後発話セッションに戻り、ソースと納品状態が保持されます。

右側の【ステータス】で確認できます：

* 進行中および完了したタスク；
* サブエージェントとワークフロー；
* バックグラウンドコマンドと停止入口；
* ツール呼び出しの成功、失敗、回数；
* コンテキスト使用量と宣言された成果物。

【設定】→【通知】→【対話完了通知】を有効にすると、他のタブやウィンドウで作業中に、アシスタントの返信完了、Agent タスクの完了、承認待ちの場合にシステム通知で知らせます。通知をクリックすると対応する対話に戻ります。

### ユーザー事例：プロジェクト規範の継続的なメンテナンス

チームは安定したコード規約を Agent のメモリに書き込み、詳細なレビュー手順をスキルとして作成します。新しいブランチをレビューするたびにタスクを作成し、Agent にサブエージェントを使ってインターフェース、データマイグレーション、テストをそれぞれチェックさせ、メイン Agent が結論をまとめます。ルールが変更された場合はメモリを更新し、各タスクの履歴記録を変更する必要はありません。

<details>

<summary>メモリはナレッジベースに代わりますか？</summary>

いいえ。メモリは少量で安定しており、タスク間で使用される事実や経験に適しています。ナレッジベースは体系的なドキュメントに適しており、Agent の検索範囲を制御できます。

</details>

<details>

<summary>タスクが停止したように見える場合、まずどこを確認しますか？</summary>

まず右側の【ステータス】を開き、権限を待っているか、バックグラウンドコマンドがまだ実行中か、サブタスクが失敗したか、プロバイダーが再試行中かをチェックしてください。より詳細なリクエスト情報が必要な場合は、開発者モードを開いて呼び出しチェーンを確認してください。

</details>
