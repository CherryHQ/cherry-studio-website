# Agent とモデルの役割分担の作成

作成入口：左側のナビゲーション【作業】→【エージェントを追加】。

新規作成ウィザードは【基本情報】、【システムプロンプト】、【スキル】、【ナレッジベース】の4ステップで構成されています。最初のステップでは実行モードを選択する必要があります。実行モードは、Agent が利用可能なモデルの役割分担、権限モード、一部のツールを決定し、作成後は変更できません。

<figure><img src="../../../../assets/0797ee2c9878cf471b44fe2e.webp" alt="Agent とモデルの役割分担の作成 — 説明画像"><figcaption></figcaption></figure>

### 実行モードの選択方法

| 実行モード | 主な特徴 | モデル設定 | 権限と制限 |
| ------------------ | ------------------- | -------------------- | ------------------------------------ |
| 【強化：Claude Agent】 | 機能面が充実しており、複雑な多段階タスクに適しています | メインモデル、Plan モデル、Small モデル | すべての権限モードとハートビート検出に対応 |
| 【高速：Pi】 | 応答が速く、コストが低く、日常のファイルやコーディングタスクに適しています | メインモデルのみ設定 | 【プランニングのみ】は提供されません。新規作成時のデフォルトは【スマート承認】です |
| 【DeepSeek Harness】 | 複数のモデルサービスに互換性があり、目標駆動型の実行をサポートします | メインモデルのみ設定 | 【スマート承認】とハートビート検出は提供されません。`/compact`、`/goal` をサポート |

{% hint style="warning" %}
実行モードは作成後に変更できません。目標、モデルの互換性、権限要件が根本的に変更された場合は、既存の Agent を修正し続けるのではなく、新しい Agent を作成してください。
{% endhint %}

### 4ステップの入力方法

{% stepper %}
{% step %}
#### 1. 基本情報

名称は職種やタスクタイプとして記載します。例：「契約書チェック」「コンテンツ企画」。まず実行モードを選択し、次にページに表示される互換性のあるモデルを選択します。説明は用途の識別を助けるためにのみ使用されます。メインモデルは主要な推論と実行を担当します。
{% endstep %}

{% step %}
#### 2. システムプロンプトの作成

役割、目標、境界、出力方法を明確に記述します。形容詞を並べるよりも、実行可能なルールを提示する方が効果的です。まずリスクを列挙し、次に原文を引用し、最後に修正提案を行います。資料が不足している場合は明確にマークし、推測しないでください。
{% endstep %}

{% step %}
#### 3. スキルの選択

この Agent の長期的な作業方法に関連するスキルのみを選択してください。スキルは【設定】→【スキル】からインストールすることも、後で Agent に検索・インストールを依頼することもできます。
{% endstep %}

{% step %}
#### 4. ナレッジベースのバインド

Agent が実際に検索が必要なナレッジベースのみをバインドしてください。ナレッジベースがバインドされていない場合、ナレッジベースの検索および管理ツールは、その Agent のツールリストに表示されません。
{% endstep %}
{% endstepper %}

### 作成後の継続設定

Agent リストでメニューを開き、編集を選択すると、以下の内容を調整できます：

* 【基本】：実行モードを確認し、そのモードがサポートするモデル、権限、ハートビート設定を調整します；
* 【プロンプト】：役割の説明、処理ルール、行動の境界；
* 【組み込みツール】：ファイル、検索、画像、通知、スケジュールタスク、メモリ、サブエージェント、ワークフローなど；
* 【ナレッジベース】：Agent がアクセスできるナレッジベースを制限します；
* 【MCP】：接続済みの MCP サーバーをバインドします；
* 【スキル】：インストール済みのスキルを選択します；
* 【詳細】：実際に必要なツールに環境変数を設定します。

{% hint style="info" %}
現在の編集ウィンドウは変更を自動保存します。ウィンドウを閉じる前に未保存の内容がある場合、アプリケーションはまず保存を完了します。保存に失敗した場合、ウィンドウは開いたままになり、エラーが表示されます。
{% endhint %}

### 推奨される開始点

| 設定項目 | プロダクトのデフォルト値 | 推奨される開始点 | 役割 | 適用シーン | 注意事項 |
| --------------- | ----------------------------- | ----------------------- | -------------- | ------------------ | ---------------------------------- |
| 実行モード | 【強化：Claude Agent】 | 不明な場合はまず【強化：Claude Agent】を使用 | モデルの役割分担、権限、ツールの範囲を決定 | すべての Agent | 作成後は変更不可 |
| メインモデル | 作成時に選択したモデルを使用 | ツールの呼び出しが安定して検証済みのモデルを選択 | 主要な推論と実行 | すべての Agent | セレクターは実行モードに基づいて非互換モデルをフィルタリングします |
| Plan / Small モデル | メインモデルと同じ | まずメインモデルと一致させます | タスクの分解、単純な判断、フォーマット | 【強化：Claude Agent】のみ | Pi と DeepSeek Harness ではこれらのフィールドは表示されません |
| 権限モード | Claude/DSH は【逐次確認】；Pi は【スマート承認】 | 実際のプロジェクトディレクトリでは【逐次確認】を優先 | ツールが承認を必要とするかどうかを決定 | ファイル、ターミナル、ネットワークタスク | 【完全アクセス】ではファイルの削除やネットワークアクセスの可能性あり |
| ハートビート検出 | サポートされる実行モードでは初期状態でオン、間隔 30 分 | 継続的なタスクがない場合はオフにできます | Agent が定期的に作業を確認 | Claude Agent、Pi | DeepSeek Harness ではハートビート検出は提供されません；固定時間はスケジュールタスクを使用 |

### ユーザー事例：契約書チェック Agent

「契約書チェック」Agent を作成し、メインモデルとして検証済みのモデルを選択します。プロンプトでは「リスク条項、原文の位置、影響、提案」に従って出力することを要求し、社内規程のナレッジベースをバインドし、権限は【逐次確認】を維持します。各契約書ごとに新しいタスクを作成し、対応するファイルディレクトリを選択することで、異なる顧客の資料が同じコンテキストに混在することを避けます。

<details>

<summary>なぜ作成時に MCP と権限の完全な設定が見えなかったのですか？</summary>

作成ウィザードではよく使われるステップのみが保持されています。作成が完了したら Agent の編集ウィンドウを開き、【基本】【組み込みツール】【ナレッジベース】【MCP】【スキル】【詳細】で設定を継続できます。具体的なタブは実行モードの機能に応じて変化します。

</details>
