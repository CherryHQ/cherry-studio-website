# コーディングパートナー（Code CLI）

【コーディングパートナー】は、一般的なプログラミングコマンドラインツールのインストール、設定、起動に使用します。Cherry Studio は、アプリがホストするバージョン、システム PATH に既に存在するバージョン、ツール独自のアカウントログインを区別し、システムインストールを自動的に上書きしません。

<figure><img src="../../../../assets/2e66cc9312c27cf740b2eb62.webp" alt="コーディングパートナー（Code CLI） — 説明画像"><figcaption><p>① 左側でツールを選択し、インストール状態を確認します。② 右側で統一ゲートウェイ、ツール公式アカウント、または互換性のあるモデルサービスを選択します。</p></figcaption></figure>

### ページの機能

* ツールのインストール状況と利用可能な更新の確認
* Cherry Studio がホストするツールコピーのインストール、更新、削除
* システム PATH に既に存在するツールの検出
* モデルサービスが必要な CLI に対して、プロバイダー、モデル、パラメータの選択
* 独自のアカウントログインを使用する CLI に対して、ネイティブログイン方式を維持
* 作業ディレクトリとシステムで検出されたターミナルを選択して起動

ページには Claude Code、OpenAI Codex、Gemini CLI、OpenCode、Qwen Code、Kimi Code、Qoder CLI、GitHub Copilot CLI、Pi、DeepSeek Harness などのツールが含まれます。表示される項目は製品更新に応じて変更されるため、ページ上のリストを基準としてください。

### 一般的な起動フロー

{% stepper %}
{% step %}
#### 1. 【起動台】から【コーディングパートナー】を開く

必要なツールを選択し、状態が未インストール、Cherry Studio によるホスト、またはシステム由来のいずれかであるかを確認します。
{% endstep %}

{% step %}
#### 2. インストールまたはログインを完了する

未インストールの場合は【インストール】をクリックします。ツール自体がアカウントログインを提供する CLI の場合は、ページの指示に従ってネイティブログインを完了してください。Cherry Studio からプロバイダーを選択する必要はありません。
{% endstep %}

{% step %}
#### 3. モデル接続を設定する

Cherry Studio のモデルサービスが必要なツールでは、【統一ゲートウェイ】または互換性のあるプロバイダーとモデルを選択できます。ページは CLI が必要なインターフェースタイプに基づいて絞り込みを行い、互換性のないプロバイダーはリストに表示されません。
{% endstep %}

{% step %}
#### 4. ディレクトリとターミナルを選択する

作業ディレクトリは CLI の起動場所を決定します。ターミナルはシステムで検出されたリストから選択する必要があります。起動後、まず読み取り専用コマンドで現在のパスを確認してください。
{% endstep %}

{% step %}
#### 5. 起動して検証する

【起動】をクリックし、アカウントまたはモデルが正しいことを確認してから、ファイルの変更やコマンドの実行を行います。推論強度、権限、ツール固有のオプションを調整する必要がある場合は、【設定】を開きます。
{% endstep %}
{% endstepper %}

### DeepSeek Harness

<figure><img src="../../../../assets/ceedc835426c7413a36609ba.webp" alt="コーディングパートナー（Code CLI） — 説明画像"><figcaption><p>① 未インストールの場合はまずホストインストールを完了します。インストール後、互換性のあるプロバイダー、デフォルト権限、Agent モードを設定し、Web UI を起動します。</p></figcaption></figure>

DeepSeek Harness は通常のターミナル CLI とはフローが異なります。インストールしてプロバイダーを選択した後、Cherry Studio によってホストされ、独立した Web UI を開くことができます。パラメータでデフォルトの Agent モードとデフォルト権限を選択できます：

| 設定 | 適用状況 | 注意事項 |
| -------- | -------------------------- | ------------- |
| 【標準】 | ファイル、Shell、検索、スキル、計画、サブエージェントのいずれも使用可能 | ツール範囲が最大。まず制御された権限を使用してください |
| 【PTC コード】 | Code Mode を使用して複数ステップのツール操作を組み合わせる必要がある場合 | 複雑なコーディングタスクに適しています |
| 【ミニマル】 | 永続 Shell とテキストエディタのみ必要な場合 | 依存関係が少なく、機能範囲も狭くなります |
| 【読み取り専用】 | プロジェクトの確認、ファイルの書き込みなし | リスクのある操作でも確認を要求します |
| 【ワークスペース書き込み】 | 現在の DSH ワークスペースの変更を許可 | ワークスペース外のファイルへのアクセスを許可するものではありません |
| 【完全アクセス】 | 隔離、信頼、復元可能な環境 | 操作確認を要求せず、リスクが最も高いです |

### インストールソースの区別

| ソース | Cherry Studio の動作 | ユーザーのメンテナンス方法 |
| ---------------- | ------------------ | ----------------- |
| Cherry Studio ホスト | 対応するホストコピーのインストール、更新、アンインストール | 【コーディングパートナー】または【環境依存】で管理 |
| システム PATH | 検出し直接使用、上書きしない | 元のパッケージマネージャーで更新またはアンインストール |
| ツール公式アカウント | ツール独自のログインフローを維持 | ツールのインターフェースでアカウントと認可を管理 |

{% hint style="warning" %}
Cherry Studio がホストするコピーをアンインストールした後、システムに同名の実行可能ファイルが存在する場合、ページは自動的にシステムバージョンにフォールバックします。動作が変わった場合は、まず現在どのソースを使用しているかを確認してください。
{% endhint %}

### ユーザー事例：プロジェクトディレクトリでコーディングツールを起動

開発者はまず現在のプロジェクトディレクトリを選択し、検証済みのモデル接続を選択してから、Pi または他の CLI を起動します。最初のコマンドはリポジトリの状態を読み取るだけです。アカウント、モデル、ディレクトリが正しいことを確認した後、ツールによるファイル変更とチェックの実行を許可します。

<details>

<summary>インストール済みのターミナルまたは CLI が見つからないのはなぜですか？</summary>

Cherry Studio はログイン環境と標準的な場所からツールを検出します。ログインターミナルでコマンドが実行できることを確認し、アプリを再起動して環境を更新してください。ポータブル版または非標準パスは、現在そのターミナルから手動で起動する必要があります。

</details>
