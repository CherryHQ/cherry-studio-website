# API ゲートウェイ

API ゲートウェイは、Cherry Studio で設定済みのモデル機能を、OpenAI および Anthropic 互換の HTTP API 経由でローカルプログラムに提供します。また、Agent の実行に必要な内部サービスとしても機能します。

パス：【設定】→【API ゲートウェイ】。

<figure><img src="../../../../assets/69025f11c87bd83f70af4a07.webp" alt="API ゲートウェイ — 説明画像"><figcaption><p>外部プログラムを接続する前に、ステータスとポートを確認してください。API キーは、信頼できるローカルプログラムまたは管理されたネットワークにのみ提供してください。</p></figcaption></figure>

## Agent の使用と外部呼び出しの区別

* Cherry Studio の Agent のみを使用する場合：アプリの指示に従って【有効化して起動】するだけで、他のプログラムに URL や API キーをコピーする必要はありません。
* ローカルプログラムから Cherry Studio を呼び出す場合：ゲートウェイを起動し、URL と API キーをコピーして、API ドキュメントに従って互換インターフェースを選択してください。
* 他のデバイスからアクセスする場合：これにより公開範囲が拡大します。ネットワークのリスニング、ファイアウォール、アクセス制御を自ら確認する必要があります。セキュリティ対策なしで公開することは推奨されません。

## 起動と接続

{% stepper %}
{% step %}
### 1. ポートの確認

ゲートウェイが停止している間はポートを変更できます。他のプログラムで使用されていないポートを選択してください。ポートが競合すると、サービスが正常に起動できません。
{% endstep %}

{% step %}
### 2. ゲートウェイの起動

【起動】をクリックすると、ステータスが【実行中】に変更され、ページに利用可能な URL が表示され、【API ドキュメント】への入口が提供されます。
{% endstep %}

{% step %}
### 3. 認証の設定

外部プログラムは `Authorization: Bearer <API キー>` を使用します。ページから認証ヘッダーを直接コピーできますが、API キーをコードリポジトリやスクリーンショットに書き込まないでください。
{% endstep %}

{% step %}
### 4. 最小リクエストによる検証

まず API ドキュメントに従ってモデルリストを取得するか、短いテキストを送信して検証し、その後完全なアプリケーションに統合してください。エラーが発生した場合は、HTTP ステータスとレスポンスを記録し、完全な認証ヘッダーを公開しないでください。
{% endstep %}
{% endstepper %}

## 使用例：ローカルスクリプトによるモデル呼び出し

まず【設定】→【モデルサービス】でモデルが正常に会話できることを確認し、その後 API ゲートウェイを起動します。スクリプトにはローカルゲートウェイのアドレスと API キーのみを保存し、まずモデルリストを取得してから短いテキストを送信してください。完全なプログラムに統合する前に、クライアントが OpenAI または Anthropic 互換インターフェースをサポートしていることを確認してください。

| 設定 | 推奨される初期設定 | 役割 | 注意事項 |
| ------ | ---------- | --------- | ----------------- |
| リスニング範囲 | ローカル使用のみ | ネットワーク公開範囲の縮小 | デバッグの利便性のために、LAN やパブリックネットワークに直接公開しない |
| API キー | 現在のゲートウェイ用に個別に管理 | クライアントリクエストの検証 | リポジトリ、スクリーンショット、共有ログに書き込まない |
| 検証リクエスト | まずモデルリストと短いテキストを確認 | 接続と生成を分離して検証 | 失敗時はステータスコードを記録し、完全な API キーを記録しない |

### 完了基準

ゲートウェイが【実行中】と表示されていること。モデルリストを読み取れること。短いテキストのリクエストが成功すること。ゲートウェイを停止した後、クライアントから呼び出せなくなること。

## セキュリティ操作

{% hint style="danger" %}
API キーは、Cherry Studio で設定したモデルサービスを呼び出すことができます。API キーが漏洩した場合、まずゲートウェイを停止し、停止状態で【再生成】をクリックして、すべてのローカルクライアントを更新してください。
{% endhint %}

* ゲートウェイ実行中はポートと API キーが読み取り専用になります。変更する前に停止してください。
* 公開リポジトリ、Issue、ログ、チュートリアルのスクリーンショットに API キーを表示しないでください。
* 呼び出しが必要なプログラムにのみ API キーを保存してください。
* 使用量と費用は実際のモデルプロバイダーによって発生します。Cherry Studio の記録は【設定】→【使用量統計】で確認できます。

<details>

<summary>API ゲートウェイとモデルサービスはどのような関係がありますか？</summary>

モデルサービスは上流プロバイダーへの接続を保存し、API ゲートウェイはこれらの機能を互換インターフェースに変換します。ゲートウェイ自体はモデルを提供せず、少なくとも 1 つの利用可能なプロバイダーとモデルが必要です。

</details>

<details>

<summary>ポートは正常ですが、クライアントが未認証を返す場合はどうすればよいですか？</summary>

リクエストヘッダーが `Authorization: Bearer ...` であり、余分な引用符やスペースがないことを確認し、クライアントで使用している API キーがページの現在の値であるかどうかを確認してください。

</details>
