# トレースと開発者モード

トレースは、1回の対話または Agent タスク内で発生したモデルリクエスト、ツール呼び出し、MCP 相互作用を確認するために使用します。トラブルシューティングやパフォーマンス分析に適していますが、日常のチャットで必ず有効にする必要のある機能ではありません。

<figure><img src="../../../../assets/7cb797e89c5a180b57971c67.webp" alt="トレースと開発者モード — 説明画像"><figcaption><p>MCP の呼び出しをトラブルシューティングする際は、まずサーバーと認証を確認し、次にトレースを使用してリクエストが Agent およびツール実行フェーズに到達したかどうかを判断します。</p></figcaption></figure>

### 有効化方法

{% stepper %}
{% step %}
#### 1. 【設定】→【一般】を開く

【開発者モード】セクションで【開発者モードを有効にする】をオンにします。
{% endstep %}

{% step %}
#### 2. Cherry Studio を再起動する

開発者モードは再起動後に有効になります。再起動前に実行中の Agent タスクの状態を確認してください。
{% endstep %}

{% step %}
#### 3. 問題を再現する

最小限のテストメッセージを再送信し、必要なモデルとツールのみを保持して、関連のない呼び出しを減らします。
{% endstep %}

{% step %}
#### 4. トレースを開く

対話または Agent の右側パネルから【トレース】に入り、ノードを選択して入力、出力、所要時間、状態を確認します。Agent タスクでは、Agent 名、操作、ツール呼び出し数も確認できます。
{% endstep %}
{% endstepper %}

### 一般的なノードの読み方

| ノード | 重点確認項目 | 一般的な問題 |
| -------- | ------------------ | ---------------- |
| モデルリクエスト | モデル、入力、出力、Token、状態 | プロバイダーエラー、コンテキストが長すぎる、出力が空 |
| ツール呼び出し | ツール名、パラメータ、結果 | パラメータエラー、権限待機、ツールの異常な返却 |
| MCP 呼び出し | サービス名、接続タイプ、入力と出力 | サーバー切断、認証失敗、リモートエラー |
| Agent 実行 | Agent、操作、ツール数と状態 | サブタスク失敗、フローが終了していない |
| HTTP リクエスト | メソッド、URL、状態とレスポンス | アドレスエラー、ネットワークまたは認証の問題 |

{% hint style="danger" %}
トレースにはプロンプト、ファイル内容、リクエストヘッダー、ツールパラメータが含まれる可能性があります。スクリーンショットを共有したり情報をエクスポートする前に、API Key、Authorization、Cookie、メールアドレス、ローカルパス、ビジネスデータを削除する必要があります。
{% endhint %}

### ユーザー事例：MCP ツールが空の結果を返す

まず MCP 設定ページでサーバーが正常であることを確認し、次に Agent にツールを1つだけ呼び出させます。トレースでリクエストがサーバーに到達したが出力が空であることが示されている場合、問題は Agent のバインド不足ではなく、サーバー側のデータまたはパラメータにある可能性が高いです。MCP ノードが全く存在しない場合は、Agent の【MCP】に戻ってバインドを確認してください。

<details>

<summary>有効化してもトレースが表示されないのはなぜですか？</summary>

アプリケーションが再起動されたことを確認し、再起動後にリクエストを再送信してください。有効化前に生成された履歴メッセージには、トレースデータが自動的に補完されません。

</details>
