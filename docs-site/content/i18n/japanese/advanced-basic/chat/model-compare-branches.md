# 複数モデルの比較とメッセージの分岐

複数モデルの比較は、唯一の正解が存在しない問題（例：方案のレビュー、文案の方向性、資料のクロスチェック）に向いています。メッセージの分岐を使用すると、特定のノードから別の経路を試すことができ、会話全体をコピーする必要はありません。

## 複数のモデルを同時に比較する

{% stepper %}
{% step %}
### 1. 【チャット】を開き、モデル名をクリックする

モデルセレクターで比較するモデルにチェックを入れます。初めて使用する際は、これらのモデルが属するサービスが正常に接続できることを確認してください。
{% endstep %}

{% step %}
### 2. 同じ質問を送信する

評価基準を質問に含めましょう。例えば「実行可能性、リスク、コストの3つの観点から比較してください」とします。「どちらが良いか」だけを尋ねることは避けてください。
{% endstep %}

{% step %}
### 3. 最も長い回答を選ぶのではなく、違いを比較する

事実が一致しているか、前提が明確か、何が欠落しているか、そしてどの項目があなたの制約条件に合致するかを重点的に確認してください。重要な事実は、元の資料に戻って照合してください。
{% endstep %}
{% endstepper %}

{% hint style="warning" %}
一度に複数のモデルを選択すると、それぞれにリクエストが送信されます。コスト、速度、または機密資料に関わる場合は、まず短い質問で接続と効果を確認し、その後長い資料を処理してください。
{% endhint %}

## メッセージから分岐を作成する

再検討したいメッセージを見つけ、メッセージメニューを開いて分岐操作を選択します。新しい分岐はそれまでのコンテキストを保持し、その後のメッセージは元の経路とは別に記録されます。分岐マネージャーを使用すると、異なる経路の切り替え、比較、および元の経路への戻りが可能です。

また、分岐キャンバスで空の分岐を作成することもできます。空の分岐は作成後すぐに保存され、アプリを再起動しても保持され、分岐キャンバスに残ります。次に入力欄で内容を送信すると、その分岐に埋め込まれます。一時的に不要な空の分岐は、ノードの右クリックメニューから削除できます。

<figure><img src="../../../../assets/0bc4cb0c28265626960cd849.webp" alt="複数モデルの比較とメッセージの分岐 — 説明画像"><figcaption><p>分岐マネージャーは、「リリース前チェックリスト」と「クイックパイロット」の2つの経路を同時に保持します。</p></figcaption></figure>

図の説明：① 分岐ノードと現在のパス；② ユーザー、アシスタント、現在のパス、無効化されたパスの凡例。例では「リリース前チェックリスト」と「クイックパイロット」の2つの経路が保持されており、合計2つの分岐、6つのメッセージノードがあります。

### 応用例：2つのリリース方案のレビュー

まずモデルに方案内のリスクと欠落点を見つけさせ、同じ返信から「リリース前チェックリストを補完する」と「クイックパイロットの観点で評価する」をそれぞれ追問します。分岐マネージャーを開くと、2つの経路が並べて保持され、それぞれに追問を続けたり、いつでも別の経路に戻って結論を確認したりできます。

<details>

<summary>複数のモデルを使用すべきでない場合とは？</summary>

明確な事実の確認、短いテキストの整理、または複数のプロバイダーに送信すべきでない内容を含む資料の場合は、単一モデルの使用が適切です。

</details>

<details>

<summary>分岐は元のメッセージを変更しますか？</summary>

いいえ。分岐は選択したノードから継続し、元の経路は保持されたまま、いつでも戻ることができます。

</details>
