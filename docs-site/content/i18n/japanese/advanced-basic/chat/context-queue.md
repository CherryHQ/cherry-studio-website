# 長い対話、コンテキストとキューイングメッセージ

対話が長くなるほど、モデルが読み取る必要がある履歴情報も増加します。コンテキスト使用量が上限に近づくと、初期の内容が回答に反映されなくなる可能性があります。毎回「続けて」と追記するのではなく、定期的に結論と未解決の問題を整理することをお勧めします。

### 長い対話の管理

{% stepper %}
{% step %}
#### 1. コンテキストのヒントを確認する

インターフェースでコンテキスト負荷が高まっていると表示された場合、まず大きな添付ファイルの追加を停止し、現在の目標に関連する履歴がどれかを確認してください。
{% endstep %}

{% step %}
#### 2. モデルに引き継ぎサマリーを生成させる

「確認済みの事実、現在の結論、未解決の問題、失ってはいけない制約」を別々に列挙するように指示してください。これは単なる「要約して」という指示よりも、作業を継続するのに適しています。
{% endstep %}

{% step %}
#### 3. 新しいトピックで継続する

引き継ぎサマリーと必要なファイルを新しいトピックに配置し、最初のメッセージで次に処理する目標を明確にしてください。元のトピックは参照用に保持します。
{% endstep %}
{% endstepper %}

### グローバルコンテキスト管理の調整

パス：【設定】→【一般】→【コンテキスト管理】。これらの設定は通常のアシスタント対話に適用されます。個々のアシスタントは、自身の設定で上書きすることもできます。

| 設定項目 | 製品デフォルト値 | 推奨開始値 | 機能 | 適用シーン | 注意事項 |
| -------- | -------- | ------- | ------------- | ------------- | --------------- |
| 直近メッセージの保持数 | 制限なし | 制限なし | 直近のいくつかのメッセージのみをモデルに送信 | 固定ウィンドウの短いタスク | 値が小さすぎると、まだ有効な要求をモデルが忘れる可能性があります |
| コンテキスト管理の有効化 | 有効 | 有効のまま | 超長ツール結果と履歴の圧縮を管理 | 長い対話、ツール呼び出しが多いタスク | 無効にすると、大きな結果がコンテキストを埋めやすくなります |
| ツール出力の切り詰めしきい値 | 50,000 文字 | デフォルトのまま | 大きな結果を保存し、モデルが分割して読み取れるようにする | ウェブページ、ログ、長い文書のツール結果 | 元の結果を削除するものではありません |
| 自動圧縮 | 有効 | 有効のまま | ウィンドウ上限に近づいた際に初期の履歴を要約 | 継続的な複数ラウンドの作業 | 圧縮は要約であり、すべての詳細が保持される保証はありません |
| 圧縮モデル | 現在のモデルに従う | 現在のモデルに従う | 履歴サマリーを生成するモデルを選択 | 速度やコストを個別に制御する必要がある場合 | モデルを変更すると、トラブルシューティングの変数が増えます |

【設定】→【デフォルトモデル】には【モデル呼び出しのリトライ】も提供されています。デフォルトでは無効です。有効にすると、デフォルトで最大 3 回試行し、指数バックオフを使用します。また、フォールバックモデルを順番に選択することもできます。リトライとフォールバックは、モデルが出力を開始する前にのみ有効であり、生成が半ばで止まった回答を別のモデルで継続することはありません。

### メッセージキューの使用

モデルがまだ回答中であっても、次の要求をキューに追加できます。明確な後続アクションを追記する場合に適しています。例えば「完了後に 3 つの結論に整理する」などです。Agent が実行中に現在の方向を即座に修正する場合は、【ガイドショートカット】を使用してください。完全にやり直す必要がある場合は、現在の生成を停止し、目標を再説明してください。

図中：① 現在のトピック内の 2 つのキューイングメッセージ；② 自動送信の再開。再開後、メッセージは上から順に送信が続けられます。

{% hint style="info" %}
キューは自動化スケジュールではありません。現在のトピック内の後続メッセージのみを担当します。固定時刻で実行する必要がある場合は、【スケジュールタスク】を使用してください。
{% endhint %}

#### 応用例：長いレポートのレビュー

まずレポートをアップロードし、章ごとに問題を列挙するよう要求します。モデルが処理している間に、「完了後にリスクリストを整理する」と「最後にチェックリストを生成する」を順にキューに追加します。最初のラウンドの結果を確認する必要がある場合は、自動送信を一時停止できます。問題がないことを確認してから再開します。これにより、対話の前に座って 1 つずつ送信する必要がなく、次のステップの要求が確認前に実行されることも避けられます。

<summary>なぜモデルは突然、以前述べた要求を忘れるのですか？</summary>

まず、対話が長すぎないか、モデルを切り替えていないか、重要な要求が一度しか表示されていないかを確認してください。安定したルールは、現在のタスクの明確な説明に書き込みます。長期的に再利用する必要がある場合は、Agent プロンプトやスキルに委ねてください。
