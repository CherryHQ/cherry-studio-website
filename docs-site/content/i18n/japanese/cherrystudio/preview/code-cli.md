# コーディングパートナー

【コーディングパートナー】は、一般的なプログラミング用コマンドラインツールのインストール、設定、および起動に使用します。Cherry Studio は、自社が管理するインストールを識別し、システムログイン環境で利用可能な CLI も検出します。システムツールは引き続き元のパッケージマネージャーによって管理されます。

<figure><img src="../../../../assets/565c03d38bfd4fabef8d3013.webp" alt="コーディングパートナー — 説明画像"><figcaption><p>まず、ツールがインストール済みでバージョンが利用可能であることを確認してから、モデル接続とプロジェクトディレクトリを設定してください。</p></figcaption></figure>

## ページの機能

* ツールのインストール状況と利用可能な更新の確認；
* Cherry Studio が管理するツールコピーのインストールまたは更新；
* システム PATH に存在するツールの検出；
* モデルサービスが必要な CLI に対して、プロバイダーとモデルの選択；
* 独自のアカウントでログインする CLI に対して、ネイティブなログイン方式を維持；
* 作業ディレクトリとシステムで検出されたターミナルを選択して起動。

ページには現在、Claude Code、OpenAI Codex、Gemini CLI、OpenCode、Qwen Code、Kimi Code、Qoder CLI、GitHub Copilot CLI などのツールが含まれています。表示される項目は製品更新に応じて変更されるため、ページ上のリストを基準としてください。

## 使用フロー

{% stepper %}
{% step %}
### 1. 左側ナビゲーションの【コーディングパートナー】を開く

必要なツールを選択し、ステータスが未インストール、Cherry Studio 管理、またはシステム由来のいずれかであるかを確認します。
{% endstep %}

{% step %}
### 2. インストールまたはログインを完了する

未インストールの場合は【インストール】をクリックします。ツール自体がアカウントログインを提供する CLI では、ページの指示に従ってネイティブログインを完了してください。Cherry Studio からプロバイダーを選択する必要はありません。
{% endstep %}

{% step %}
### 3. モデル接続を設定する

Cherry Studio のモデルサービスが必要なツールでは、互換性のあるプロバイダーとモデルを選択します。ページは CLI が必要とするインターフェースタイプに基づいてフィルタリングを行い、非互換のプロバイダーはリストに表示されません。
{% endstep %}

{% step %}
### 4. ディレクトリとターミナルを選択する

作業ディレクトリは CLI の起動場所を決定します。ターミナルはシステムで検出されたリストから選択する必要があります。カスタムターミナルの実行ファイルパスは提供されなくなりました。
{% endstep %}

{% step %}
### 5. 起動して検証する

【起動】をクリックし、ターミナルで読み取り専用のチェックを実行します。アカウント、モデル、ディレクトリが正しいことを確認してから、ファイルの変更やコマンドの実行を行ってください。
{% endstep %}
{% endstepper %}

## Claude Code のモデルモード

Claude Code を設定する際、【モデル】には 2 つのモードが提供されます：

* 【汎用】：すべてのリクエストで同じモデルを使用し、設定が簡単です；
* 【詳細】：【モデルロールマッピング】で Fable、Opus、Sonnet、Haiku、Subagent を個別に設定します。テーブル内の【実際のリクエストモデル】は、各ロールが最終的に使用するモデルです。必要に応じて、対応するロールに【1M】コンテキストを有効にできます。

バックグラウンドサブタスク、圧縮、タイトルなどのロールに異なるモデルを指定する必要がある場合のみ、【詳細】を使用してください。空欄のロールはメインモデルに従います。変更後は、小さなタスクで各ロールが正常にリクエストできることを確認してください。

## 使用シーン：プロジェクトディレクトリでコーディングツールを起動する

| 選択項目 | 推奨される出発点 | 適用シーン | 注意事項 |
| ----- | ----------------------------- | ------------ | ---------------- |
| インストールソース | システムバージョンがある場合は、まずシステムバージョンを使用 | チームが CLI を一元管理している場合 | 更新とアンインストールは元のパッケージマネージャーが担当 |
| モデル接続 | Cherry Studio で利用可能と検証済みの接続を 1 つ選択 | モデルサービスが必要な CLI | 独自のアカウントログインを持つツールはネイティブフローでログイン |
| 作業ディレクトリ | 現在のプロジェクトディレクトリのみを選択 | コードの変更、チェックの実行 | 起動後、ターミナルのパスを確認 |
| 初回コマンド | プロジェクト状態を読み取り専用で確認 | アカウント、モデル、ディレクトリの検証 | 確認後にファイル書き込みを許可 |

### 完了基準

ページがインストールソースを識別できること；ターミナルが正しいディレクトリで開かれること；最小限の読み取り専用コマンドが成功すること；ツールに表示されるアカウントまたはモデルが期待通りであること。

## インストールソースを区別する

| ソース | Cherry Studio の動作 | 管理方法 |
| ---------------- | ------------------ | ------------------ |
| Cherry Studio 管理 | 対応する管理コピーのインストール、更新、アンインストール | 【コーディングパートナー】または【環境依存】で管理 |
| システム PATH | 検出して直接使用し、上書きしない | 元のパッケージマネージャーで更新またはアンインストール |
| アプリ内蔵 | 直接使用し、システムレベルのアンインストールは提供しない | Cherry Studio の更新に伴う |

{% hint style="warning" %}
Cherry Studio 管理コピーをアンインストールした後、システムに同名の実行ファイルが存在する場合、ページは自動的にシステムバージョンにフォールバックします。バージョンまたは動作が変更された場合、現在どのソースを使用しているかを確認してください。
{% endhint %}

<details>

<summary>インストール済みのターミナルや CLI が見つからないのはなぜですか？</summary>

Cherry Studio は、ログイン環境と標準的な場所からツールを検出します。ログインターミナルでコマンドが実行可能であることを確認し、環境を更新するためにアプリを再起動してください。ポータブル版や非標準パスは、現在そのターミナルから手動で起動する必要があります。

</details>
