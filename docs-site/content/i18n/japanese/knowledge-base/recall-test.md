# 資料の確認とリコール

リコールテストは「質問が正しいチャンクを見つけられるか」を直接検証します。チャットモデルによる事前の推敲は行われません。問題が資料、解析、チャンク分割、または検索設定のいずれにあるかを判断するのに役立ちます。

{% hint style="info" %}
答えが既知の実際の質問を3〜5個準備し、資料、モデル、チャンク分割を更新するたびに繰り返し使用してください。固定された質問は、その場で適当に試すよりも、性能の劣化を特定しやすくなります。
{% endhint %}

## テスト質問の準備

以下の3種類の質問をカバーすることを推奨します。

* 正確な事実、例：「国内の一线城市での宿泊費の上限はいくらか？」
* 条件付きルール、例：「海外でのレンタカー費用はどのような場合に経費精算できるか？」
* 混同しやすい項目、例：「5,000元を超える出張費は誰が追加承認を行うか？」

資料のタイトルや原文の全文のみでテストすると、実際の使用時の効果を過大評価することになります。

## リコールテストの実行

{% stepper %}
{% step %}
### 1. リコールテストを開く

左側のナビゲーションで【ナレッジベース】→ ナレッジベースを選択 → 【リコールテスト】に進みます。
{% endstep %}

{% step %}
### 2. 実際の質問を入力

答えが明確な質問を入力し、テストを実行します。質問は日常の表現に近いものであり、資料の原文を意図的にコピーしないでください。
{% endstep %}

{% step %}
### 3. ソースとチャンクを確認

ソースが正しいこと、チャンクに回答に必要な条件と結論が両方含まれていることを確認します。

<figure><img src="../../../assets/b44776524449cdefe62eaed3.webp" alt="資料の確認とリコール — 説明画像"><figcaption><p>結果があるかどうかだけでなく、ソース、チャンクの完全性、順序も確認してください。</p></figcaption></figure>
{% endstep %}

{% step %}
### 4. 現象に基づいて問題を特定

正しいチャンクが全くない場合は、まず資料、解析、チャンク分割を確認します。正しいチャンクは出るが順序が不安定な場合は、埋め込み、リランキング、またはTop Kを検討します。
{% endstep %}

{% step %}
### 5. 単一項目を調整して再テスト

1回のサイクルでは設定を1項目のみ変更します。解析、チャンク分割、またはインデックスに関わる変更を行った場合は、まず【再インデックス】を実行し、その後同じ質問セットで再テストします。
{% endstep %}
{% endstepper %}

## 結果の読み方

| 現象 | 説明 | 次のステップ |
| ------------- | --------------------- | ---------------------- |
| 正しいソースが上位に表示され、チャンクが完全 | リコールは概ね合格 | 異なる表現でさらにテスト |
| 正しい結果が全くない | 資料が未準備、内容欠落、質問表現との乖離、閾値が高すぎる | 資料、本文、チャンク、検索設定を順に確認 |
| ソースは正しいが、チャンクに重要な文が欠落 | 解析またはチャンク境界が不適切 | チャンクを確認し、調整後に再インデックス |
| 旧バージョンと新バージョンが同時に出現 | 同名の資料がすべて保持されている | 旧エントリを削除するか、【置換】で再インポート |
| 正しい項目が頻繁に下位に表示 | 候補が多すぎるか、ランキングが不安定 | 資料を整理し、埋め込みまたはリランキングモデルを検討 |
| リコールは正しいが、チャット回答が不正確 | 問題はプロンプトまたはチャットモデルにある可能性が高い | リコール設定を維持し、質問表現とチャットモデルを調整 |

{% hint style="warning" %}
チャットモデルは、リコール段階で見つからなかった重要な資料を補完できません。リコール結果が不合格な場合、チャットモデルを何度も変更してデバッグすることから始めるべきではありません。
{% endhint %}

## 最適化のサイクル

<figure><img src="../../../assets/8cd27fa50051cc96320b280a.webp" alt="資料の確認とリコール — 説明画像"><figcaption><p>固定質問 → 結果確認 → レベル特定 → 単一項目調整 → 必要に応じて再インデックス → 再テスト。</p></figcaption></figure>

推奨される順序：

1. 資料が正しく、重複や期限切れのバージョンがないことを確認。
2. 解析された本文とチャンクを確認。
3. 質問表現と原文の乖離が大きい場合、埋め込みモデルを検討。
4. 候補は概ね正しいが順序が不安定な場合、リランキングモデルを検討。
5. 調整後に再インデックスを実行し、同じテストセットを繰り返す。

<figure><img src="../../../assets/5bd8c12bd8d08e785c6a4c42.webp" alt="資料の確認とリコール — 説明画像"><figcaption><p>チャンクが不完全な場合はチャンク分割設定を確認してください。変更は新しい資料にのみ影響し、古い資料には再インデックスが必要です。</p></figcaption></figure>

## 設定の説明

| 設定項目 | 製品デフォルト値 | 推奨開始値 | 役割 | 適用シナリオ | 注意事項 |
| ------ | ------------ | -------- | ---------- | ---------- | ----------------- |
| テスト質問数 | — | 3〜5個 | 再現可能な品質基準を確立 | すべてのナレッジベース | 正確な事実、条件付きルール、混同しやすい質問をカバー |
| Top K | 6（1〜50から選択可） | まず6を維持 | 最終的なチャンク数を制御 | カバレッジとノイズのバランス | 値を上げるとコンテキストの消費が増える可能性 |
| 類似度閾値 | 0.0（リランキング設定後にのみ表示） | 0.0から開始 | リランキング後の低スコア結果をフィルタリング | リランキング後もノイズが残る場合 | 値が高すぎると正しいチャンクが除外される |
| 再テスト方法 | — | 1サイクルで1項目のみ変更 | 設定変更の影響源を特定 | 最適化、資料またはモデル更新時 | チャンク分割またはモデルを変更した場合は先に再インデックス |

## 期待される結果

* 正しいソースが安定して上位の結果に表示される。
* チャンクに、質問への回答に必要な条件と結論が含まれている。
* 自然な別の表現に変更しても、結果が安定している。
* 資料または設定を更新した後、固定質問で顕著な劣化がない。

## ユーザー事例

小林氏は、「宿泊費基準」を原文で検索するとヒットするが、「ホテル宿泊費の最大経費精算額」では不安定であることを発見しました。まず資料とチャンクが正常であることを確認し、その後埋め込みモデルを設定して再テストしました。正しいチャンクが表示されるようになったものの、時々下位に表示されるため、リランキングモデルを追加しました。

完了基準は、3つの異なる質問表現で、上位の結果から同じ宿泊費基準を見つけられ、かつチャンクに適用対象都市と金額上限が含まれていることです。

## よくある質問

<details>

<summary>正しいチャンクが全くない場合、まずTop Kを大きくすべきか？</summary>

まず資料の本文とチャンクを確認してください。解析または分割エラーがある場合、Top Kを大きくしても、不正確または不完全なチャンクがより多く返されるだけです。

</details>

<details>

<summary>類似度閾値が表示されないのはなぜか？</summary>

リランキングモデルを選択した場合にのみ、ナレッジベース設定で【類似度閾値】が表示されます。

</details>

<details>

<summary>リコールは正しいが、チャット回答が不正確な場合の対処法は？</summary>

現在のリコール設定を維持し、質問表現、対話コンテキスト、チャットモデルを確認してください。この場合、問題は通常、資料検索層にはありません。

</details>
