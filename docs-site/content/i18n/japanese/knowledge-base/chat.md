# チャットでの使用

リコールテストに合格した後、通常のチャットで1つ以上のナレッジベースを選択し、モデルがリコールされたスニペットに基づいて回答し、出典を表示できます。

{% hint style="info" %}
チャットは回答の構成を担当し、ナレッジベースは証拠の提供を担当します。まず【リコールテスト】で正しいスニペットを確認し、その後プロンプトやチャットモデルの調整が必要かどうかを判断してください。
{% endhint %}

## 使用前提

| 確認項目 | 合格状態 |
| ----- | ---------------- |
| チャットモデル | ツール呼び出しに対応 |
| ナレッジベース資料 | 少なくとも1件の資料が準備完了 |
| 現在のメッセージ | ファイルが同時に添付されていない |
| リコール品質 | 重要な質問で正しい出典と完全なスニペットが見つかる |

{% hint style="warning" %}
現在のメッセージに添付ファイルがある場合、ナレッジベースの選択は無効になります。まず添付ファイルを削除してから、入力エリアからナレッジベースを選択してください。
{% endhint %}

## 出典付きの質問応答を完了する

{% stepper %}
{% step %}
### 1. ツール呼び出しに対応するモデルを選択

新規または通常のチャットを開き、モデルセレクターで現在のモデルがツール呼び出しに対応していることを確認してください。ナレッジベースのエントリで機能不足と表示される場合は、先にモデルを変更してください。
{% endstep %}

{% step %}
### 2. ナレッジベース選択を開く

入力エリア左下の追加ボタンをクリックし、【ナレッジベース】を選択してから、対象のベースを1つ以上チェックしてください。
{% endstep %}

{% step %}
### 3. 選択状態を確認

ナレッジベース名が入力エリアに表示されるはずです。質問が1つのトピックのみに関わる場合は、関連しないスニペットの競合を減らすため、ベースを1つのみ選択することを優先してください。

<figure><img src="../../../assets/5baecf3a1e479cb5a9627b45.webp" alt="チャットでの使用 — 説明画像"><figcaption><p>送信前に、選択したナレッジベースと現在の質問が同じ資料範囲に属していることを確認してください。</p></figcaption></figure>
{% endstep %}

{% step %}
### 4. タスク、範囲、形式を明確に記述

例：`選択したナレッジベースだけを根拠に、中国国内の主要都市における宿泊費の上限を回答してください。職位別に項目を分け、それぞれに出典を示してください。`
{% endstep %}

{% step %}
### 5. 出典照合を開く

出典名、スニペットの内容、適用条件を確認してください。資料に記載されていない内容は、事実として補完されるべきではありません。
{% endstep %}

{% step %}
### 6. 失敗時はリコールテストに戻る

同じ質問でナレッジベースが返すスニペットを確認してください。リコールが誤っている場合は、まず資料、解析、検索を修正し、リコールが正しい場合はプロンプトとチャットモデルを調整してください。

<figure><img src="../../../assets/b44776524449cdefe62eaed3.webp" alt="チャットでの使用 — 説明画像"><figcaption><p>チャットの回答が理想でない場合、リコール結果は問題が検索層にあるか回答層にあるかを判断するのに役立ちます。</p></figcaption></figure>
{% endstep %}
{% endstepper %}

## 回答はどのように形成されるか

<figure><img src="../../../assets/192b7298d3bc060e6d5897c9.webp" alt="チャットでの使用 — 説明画像"><figcaption><p>チャットモデルが見るのは最終的なリコールスニペットであり、ナレッジベース内のすべての資料を自動的に読み取っているわけではありません。</p></figcaption></figure>

## 推奨される質問テンプレート

### 明確なルールを1件照会

> 選択したナレッジベースに基づいてのみ回答してください：国内の一线城市の宿泊上限はいくらですか？職位別の基準が異なる場合は、項目ごとにリストアップし、各項目の後にソースを明記してください。

### 複数の資料を比較

> 国内出張と海外出張の承認の違いを比較してください。「トリガー条件、承認者、出発前の資料」を表形式で列挙し、資料に記載されていない箇所は「未記載」とマークしてください。

### 事実と提案の区別を要求

> まず制度原文が支持する事実を列挙し、次に操作提案を個別に提示してください。提案は制度要求として記述せず、各事実にはソース名を保持してください。

{% hint style="success" %}
良い質問には4つの要素が含まれます：完了すべきタスク、使用可能な資料範囲、期待される出力形式、資料が不足している場合の処理方法です。
{% endhint %}

## 1つのナレッジベースか複数か

| 状況 | 推奨事項 | 理由 |
| --------- | -------------- | --------------- |
| 単一の制度または製品の問題 | ベースを1つのみ選択 | 関連しないスニペットの競合を減らす |
| 部門間または製品間の比較 | 複数のベースを選択し、それぞれの用途を説明 | モデルがソースの境界を維持するのを助ける |
| 複数ベースの結果が混在 | 複数の質問に分割して個別に検証 | 各ベースが独立してリコールできることを先に確認 |
| 長期的な多段階の研究が必要 | ナレッジベースにバインドされた Agent を使用 | 継続的な検索、整理、ファイル納品に適している |

## 設定説明

| 設定項目 | 推奨開始点 | 役割 | 注意事項 |
| ----- | ----------- | --------- | ------------ |
| ナレッジベース数 | 1 個 | 資料範囲を制御 | 明確なクロスベースの必要がある場合のみ増加 |
| 質問範囲 | 「ナレッジベースに基づいてのみ」と明確に記述 | 常識による補完を減らす | 重要な結論は依然としてソースを確認する必要がある |
| 出力形式 | テーブルまたは項目別リスト | 項目ごとの検収を容易にする | 推測ではなく「未記載」を要求 |
| 回帰質問 | リコールテストと同じ質問を使用 | 検索と回答の問題を区別 | 各ラウンドで1つの変数のみ変更 |

## チャット内容をナレッジベースに保存

Cherry Studio はメッセージ、トピック、メモをナレッジベースに保存できます。保存前にモデルの推測、重複内容、一時的な議論を削除し、テーマとバージョンを説明できるタイトルを使用してください。

保存後は新しい資料スナップショットが形成され、元のチャットやメモとリアルタイム同期されません。内容が更新された場合は、再保存または置換が必要です。

## ユーザー事例

小林さんは【従業員出張制度】で宿泊上限について質問しました。最初の回答にはモデルの常識が混入していたため、プロンプトを「資料に記載されていない場合は未記載と記述する」に変更し、各項目にソースを保持するよう要求しました。その後、引用を開いて都市レベル、職位、金額を1項目ずつ照合しました。

完了基準は：すべての金額が引用スニペットによって直接支持され、制度に記載されていない例外がモデルによって勝手に補完されないことです。

## よくある質問

<details>

<summary>ナレッジベースのエントリがグレーアウトしているのはなぜですか？</summary>

ツール呼び出しに対応するモデルを選択し、現在のメッセージの添付ファイルを削除してください。その後、準備完了した資料を持つナレッジベースが少なくとも1つ存在することを確認してください。

</details>

<details>

<summary>回答にソースが表示されないのはなぜですか？</summary>

入力エリアに選択したナレッジベースが表示されていることを確認し、同じ質問をリコールテストに投入してください。正しいリコールがない場合は、まずナレッジベースを修正してください。

</details>

<details>

<summary>ソースは正しいが結論が不正確な場合はどうすればよいですか？</summary>

モデルに引用に基づいてのみ回答するよう要求し、タスクをより小さな事実項目に分割し、重要な結論を手動で照合してください。この場合、通常はプロンプト、モデルの能力、またはコンテキストの構成の問題です。

</details>
