# よくある質問

ナレッジベースの問題が発生した場合は、失敗がインポート、解析、チャンク分割、検索（リコール）、または回答のどの層で起きているかをまず判断してください。一度に1つの変数だけ変更することで、どの調整が実際に有効かを確認できます。

{% hint style="info" %}
最も迅速な特定方法は、実際の質問を1つ選び、一貫してチェックすることです。本文に回答が含まれているか、チャンクが完全か、検索が正しいか、回答がソースに忠実かを順に確認します。
{% endhint %}

## 5ステップで迅速に特定する

{% stepper %}
{% step %}
### 1. 資料の状態を確認する

資料の状態は【準備完了】である必要があります。長期間処理中になっている場合やエラーが表示されている場合は、まずエラーメッセージを確認し、ファイル、プロセッサ、モデルサービスが利用可能であることを確認してください。
{% endstep %}

{% step %}
### 2. 解析された本文を確認する

本文プレビューを開き、回答が実際に存在すること、テキストが認識されていること、2カラムやテーブルの順序が正しく並んでいることを確認してください。
{% endstep %}

{% step %}
### 3. チャンクを確認する

質問に必要な条件と結論が、理解しやすい断片に含まれていることを確認してください。ヘッダー、フッター、目次が結果を占拠しないように注意してください。

<figure><img src="../../../assets/5bd8c12bd8d08e785c6a4c42.webp" alt="よくある質問 — 説明画像"><figcaption><p>本文は正しいがチャンクが不完全な場合は、チャンク分割を調整し、既存の資料を再インデックスしてください。</p></figcaption></figure>
{% endstep %}

{% step %}
### 4. 検索テストを実行する

ソース名、関連度、チャンクの内容を確認してください。正しいチャンクが全く存在しない場合と、正しいチャンクが順位が下位にある場合は、異なる2つの問題です。

<figure><img src="../../../assets/b44776524449cdefe62eaed3.webp" alt="よくある質問 — 説明画像"><figcaption><p>まず検索層が正しい証拠を返していることを確認してから、対話のプロンプトを調整してください。</p></figcaption></figure>
{% endstep %}

{% step %}
### 5. 対話または Agent を確認する

検索は正しいが回答が誤っている場合は、ナレッジベースが選択またはバインドされていることを確認し、ソースに基づいてのみ回答するよう指示し、質問をより小さな事実項目に分割してください。
{% endstep %}
{% endstepper %}

## 問題のフィードバック先

<figure><img src="../../../assets/66f4111676793ffe87e7a979.webp" alt="よくある質問 — 説明画像"><figcaption><p>まず最小限のトラブルシューティングを完了してください。安定して再現できる場合は、匿名化された手順、エラー、期待される結果を添付してください。</p></figcaption></figure>

{% hint style="danger" %}
スクリーンショット、ログ、サンプル資料には、API Key、内部ファイルの内容、メールアドレス、ローカルの機密パスを公開しないでください。
{% endhint %}

## 作成とインポート

<details>

<summary>埋め込みモデルなしでナレッジベースを作成できますか？</summary>

はい。【使用しない】を選択しても、BM25 キーワード検索が引き続き使用されます。異なる表現のマッチングが必要な場合は、埋め込みモデルを追加してください。

</details>

<details>

<summary>どのソースとファイル形式に対応していますか？</summary>

ソースにはファイル、Cherry Studio のメモ、ローカルディレクトリ、Web リンクが含まれます。ファイル形式には PDF、DOCX、DOC、PPTX、XLSX、XLS、Markdown、TXT、CSV、HTML、EPUB が含まれます。

</details>

<details>

<summary>一度に何項目追加できますか？</summary>

対話的な選択では最大 20 項目です。多くの資料はバッチで追加するか、ディレクトリエントリを使用してください。

</details>

<details>

<summary>同名の資料は【すべて保持】と【置換】のどちらを選択しますか？</summary>

制度、マニュアル、メモのスナップショットを更新する場合は、通常【置換】を選択します。本当に併存させる必要があるバージョンの場合のみ【すべて保持】を選択し、名前に日付やバージョンを追加してください。

</details>

<details>

<summary>資料がずっと処理中になっている場合はどうすればよいですか？</summary>

ファイルが開けるか、プロセッサと OCR が利用可能か、モデルサービスが設定されているかを確認してください。エラーメッセージに基づいて、読み取り、解析、埋め込みのどの段階で失敗したかを判断してください。

</details>

## 解析と検索

<details>

<summary>スキャンされた PDF にテキストがないのはなぜですか？</summary>

スキャンされた文書には OCR が必要です。【設定】→【ドキュメント処理】で利用可能な OCR を選択し、ドキュメントを再インデックスしてください。複雑なレイアウトの場合は、専用のドキュメントプロセッサを試してください。

</details>

<details>

<summary>チャンク設定を変更しても結果が変わらないのはなぜですか？</summary>

新しい設定は既存の資料に自動的に適用されません。関連するエントリに【再インデックス】を実行し、同じ質問で再テストしてください。

</details>

<details>

<summary>検索テストに全く結果がない場合はどうすればよいですか？</summary>

資料の状態、本文に回答が含まれているか、原文のキーワードがヒットするか、埋め込みが完了しているか、リランキングのしきい値が高すぎないか、Top K が小さすぎないかを順に確認してください。

</details>

<details>

<summary>ソースは正しいがチャンクが不完全な場合はどうすればよいですか？</summary>

チャンクを確認し、条件と結論が分割されていないかを確認してください。チャンクサイズや重複を適切に増やすか、構造が乱れたソース資料を明確なメモに整理してから再インデックスしてください。

</details>

<details>

<summary>正しい結果が順位が下位にある場合はどうすればよいですか？</summary>

まず重複した資料や古い資料を削除し、次に埋め込みモデルを検討してください。候補は概ね正しいが順序が安定しない場合は、リランキングを追加し、しきい値を再調整してください。

</details>

<details>

<summary>Top K はどのくらいに設定すべきですか？</summary>

6 から開始し、固定された質問で検索漏れ、ノイズ、所要時間を比較してください。Top K は 1～50 の間で調整可能ですが、値を大きくすることが一般的な修正策ではない点に注意してください。

</details>

## 対話と Agent

<details>

<summary>対話中のナレッジベースエントリが利用できない場合はどうすればよいですか？</summary>

ツール呼び出しをサポートするモデルを選択し、現在のメッセージの添付ファイルを削除してください。また、少なくとも1つのナレッジベースに準備完了の資料が含まれていることを確認してください。

</details>

<details>

<summary>回答にソースが表示されない場合はどうすればよいですか？</summary>

入力エリアでナレッジベースが実際に選択されていることを確認し、同じ質問を検索テストに投入してください。検索に正しいチャンクがない場合は、まずナレッジベースを修正してください。

</details>

<details>

<summary>検索は正しいが、回答が依然として不正確な場合はどうすればよいですか？</summary>

モデルに引用に基づいてのみ回答するよう指示し、タスクをより小さな事実項目に分割し、重要な結論を手動で照合してください。この場合、問題は通常プロンプト、モデル、またはコンテキストの構成にあります。

</details>

<details>

<summary>Agent がナレッジベースを見られないのはなぜですか？</summary>

【エージェント編集】→【ナレッジベース】を開き、対象のナレッジベースを現在の Agent にバインドし、【組み込みツール】で【ナレッジベース検索】を有効にしてください。

</details>

<details>

<summary>ナレッジベース管理は資料を変更しますか？</summary>

はい。【ナレッジベース管理】はドキュメントの追加、削除、更新をサポートします。読み取り専用タスクでは有効にしないでください。書き込み操作の前に、対象、影響、ロールバック方法をチェックしてください。

</details>

## モデル、データ、バックアップ

<details>

<summary>埋め込みモデルを変更すると再構築が必要になるのはなぜですか？</summary>

異なる埋め込みモデルで生成されたベクトルは直接混用できません。新しいモデルが利用可能であることを確認し、完全なバックアップを保持してから、既存のベクトルインデックスを再構築してください。

</details>

<details>

<summary>リランキングと類似度しきい値の関係は何ですか？</summary>

リランキングは候補チャンクに再スコアリングを行い、しきい値はリランキング後の低スコアの結果をフィルタリングします。リランキングが設定されていない場合、ナレッジベース設定には類似度しきい値が表示されません。

</details>

<details>

<summary>ローカル埋め込みモデルをダウンロードすると完全にオフラインになりますか？</summary>

必ずしもそうではありません。解析、OCR、リランキング、チャットもすべてローカル機能を使用する場合に限り、完全にオフラインのプロセスとなります。

</details>

<details>

<summary>元のファイルや Web ページを変更すると自動的に更新されますか？</summary>

いいえ。ファイル、メモ、Web ページはインポート時の内容に基づいて資料が作成されます。同名の資料を再追加し【置換】を選択し、検索テストを完了してください。

</details>

<details>

<summary>簡易バックアップにはナレッジベースファイルが含まれますか？</summary>

完全なナレッジベースデータファイルは含まれません。移行または削除前に完全なバックアップを使用し、復元後に資料と検索を検証してください。

</details>

## 設定説明：診断ベースライン

| 項目 | 推奨開始値 | 調整が必要な場合 |
| ----- | ------------- | ---------------- |
| Top K | 6 | 正しいチャンクが切り捨てられた場合、またはノイズが多すぎる場合 |
| 類似度しきい値 | リランキング設定後 0.0 から開始 | 低スコアのノイズが顕著で、かつ正しいチャンクに余裕がある場合 |
| チャンク | デフォルトのスマートセグメンテーションを維持 | 条件と結論が分割された場合、またはチャンクが長すぎる場合 |
| 埋め込みモデル | BM25 が不十分な場合に追加 | 口語的な質問、同義表現が安定してヒットしない場合 |
| リランキングモデル | 候補が正しいが順序が安定しない場合に追加 | 解析エラーや本文の欠落の修正には使用しない |

## ユーザー事例

小林さんは、チャットで「宿泊費基準」に関する回答が誤っていることに気づきました。まず同じ質問で検索テストを行い、正しいソースが全く表示されていないことを確認しました。本文を開くと、2カラムの PDF が順序が乱れていることがわかりました。プロセッサを変更し再インデックスした後、検索が正しくなり、チャットの回答も正常に戻りました。

このプロセスではパーサーの1つの変数のみを変更したため、Top K、チャンク、閾値を同時に調整して試行錯誤するのではなく、根本原因を特定できます。

{% hint style="warning" %}
それでも解決しない場合は、アプリケーションのバージョン、オペレーティングシステム、プロセッサ、埋め込みモデルとリランクモデル、完全なエラー内容、匿名化された最小サンプル、検索結果、および期待されるソースを記録してください。
{% endhint %}
