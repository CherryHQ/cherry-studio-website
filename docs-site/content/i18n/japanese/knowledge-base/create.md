# ナレッジベースの作成

作成時に最も重要な2つの選択は、名前と埋め込みモデルです。資料は後から追加できますが、名前の範囲と検索方法は今後のメンテナンスに影響します。

{% hint style="info" %}
初めて試す場合は、【埋め込みモデル】を【使用しない】に設定できます。ナレッジベースは引き続き BM25 キーワード検索を使用します。まずインポートとリコールのフローを動作確認することから始めましょう。
{% endhint %}

## 作成前に2つの決定を行う

### 名前は資料の範囲を明確にする

「対象 + 用途」を優先的に使用してください。例えば【従業員出張制度】、【製品アフターサービスマニュアル】、または【市場調査資料】などです。【資料】や【テスト】など、後で内容の範囲を判断できない名前は避けてください。

### 埋め込み方式の選択

| 選択 | 適したシナリオ | 検索方式 | 前提条件 |
| ------ | ------------- | ------------- | ------------ |
| 使用しない | 初めての試み、キーワードが明確 | BM25 キーワード検索 | なし |
| クラウド埋め込みモデル | ユーザーの質問と資料の原文に大きな差異がある場合 | BM25 + ベクトルハイブリッド検索 | 対応するモデルサービスが正常に呼び出せること |
| ローカル埋め込みモデル | ローカルでベクトル化を完了させたい場合 | BM25 + ローカルベクトル検索 | まず【ローカルモデル】でダウンロードを完了させること |

## 作成手順

{% stepper %}
{% step %}
### 1. 作成ウィンドウを開く

左側のナビゲーションで【ナレッジベース】を開き、ナレッジベースリスト上部の追加ボタンをクリックします。
{% endstep %}

{% step %}
### 2. 名前を入力する

範囲を説明できる名前を入力します。例えば【従業員出張制度】などです。
{% endstep %}

{% step %}
### 3. 埋め込みモデルを選択する

利用可能なクラウドまたはローカルの埋め込みモデルを選択します。一時的にセマンティック検索が必要ない場合は、【使用しない】を選択します。

<figure><img src="../../../assets/7f1505c0527aeddf65937cdc.webp" alt="ナレッジベースの作成 — 説明画像"><figcaption><p>名前は資料の範囲を決定し、埋め込みモデルはベクトル検索を追加するかどうかを決定します。</p></figcaption></figure>
{% endstep %}

{% step %}
### 4. 作成をクリックする

名前とモデルを確認した後、【作成】をクリックします。作成が完了すると、空のナレッジベースに移動します。
{% endstep %}

{% step %}
### 5. 最初の資料を追加する

資料追加ボタンをクリックし、回答が明確なファイルやメモを1〜2件インポートし、処理完了を待ちます。
{% endstep %}
{% endstepper %}

## ローカル埋め込みモデルの使用

【設定】→【ローカルモデル】を開き、【埋め込みモデル】エリアで利用可能なモデルをダウンロードします。インターフェースに表示されるモデルとダウンロードサイズはインストール環境によって変化するため、現在のリストを基準としてください。

<figure><img src="../../../assets/ba97a6075b29a5304d81dc79.webp" alt="ナレッジベースの作成 — 説明画像"><figcaption><p>ダウンロードが完了したら、ナレッジベースの作成または設定ページに戻り、そのモデルを選択します。</p></figcaption></figure>

{% hint style="warning" %}
ローカル埋め込みは、ベクトル化がローカルで完了することを意味するだけです。ドキュメント解析、リランキング、チャットがクラウドを使用するかどうかは、それぞれ選択したサービスとモデルによって決まります。
{% endhint %}

## 既存の資料がある場合のモデル変更

BM25 のみを使用しているナレッジベースで埋め込みモデルを有効にする場合、ベクトルインデックスを作成できます。既にベクトルがあるナレッジベースで埋め込みモデルを変更する場合、インターフェースは【ナレッジベース再構築】フローに入ります。

{% hint style="danger" %}
再構築を開始する前に、新しいモデルが正常に呼び出せることを確認してください。再構築後、リコールテストを再実行してください。同じラウンドでモデルを変更し、チャンク分割を変更すると、結果の変化の原因を判断できなくなります。
{% endhint %}

## 設定の説明

| 設定項目 | 製品デフォルト値 | 推奨スタートポイント | 役割 | 適用シナリオ | 注意事項 |
| ------ | ----- | ----------- | ---------- | ----------- | ------------------ |
| 名前 | 空 | 対象 + 用途 | 資料の範囲を区別する | すべてのナレッジベース | 権限またはライフサイクルが異なる資料は分離すべきです |
| 埋め込みモデル | 使用しない | 初めての試みではまず使用しない | ベクトル検索を追加するかどうかを決定する | 口語的な質問、同義表現が多い場合 | クラウドモデルの課金とデータ処理はプロバイダーに依存します |
| ローカル埋め込みモデル | 未ダウンロード | ローカル処理が必要な場合にダウンロード | ローカルでベクトル化を完了させる | オフラインまたはプライバシー要件が高い場合 | 解析、リランキング、チャットモデルは別途確認が必要です |

## 期待される結果

* 新しいナレッジベースがリストに表示され、他のナレッジベースと区別できる名前になっています。
* 現在、キーワード検索かハイブリッド検索を使用しているかが明確です。
* 選択したクラウドモデルが呼び出せるか、ローカルモデルのダウンロードが完了しています。

## ユーザー事例

小林さんは初めて【従業員出張制度】ナレッジベースを作成しました。まず埋め込みモデルを【使用しない】に設定し、3件の制度をインポートしてリコールテストを完了しました。キーワード検索が安定した後、埋め込みモデルを設定し、同じ質問で口語的な質問の結果を比較しました。

完了基準は、検索方式をアップグレードした後、元の固定質問が劣化しておらず、口語的な質問でより安定して同じ制度を見つけられることです。

## よくある質問

<details>

<summary>作成ボタンが使用できない場合はどうすればよいですか？</summary>

名前が空でないか、選択したモデルがまだ利用可能かを確認してください。モデルサービスが設定されていない場合は、まず【使用しない】に変更して作成を完了できます。

</details>

<details>

<summary>埋め込みモデルを使用しないと、完全に検索できないようになりますか？</summary>

いいえ。ナレッジベースは引き続き BM25 キーワード検索を使用します。質問の用語が資料に近づくほど、結果は通常より安定します。

</details>

<details>

<summary>各トピックごとに個別にナレッジベースを作成する必要がありますか？</summary>

「使用時に一緒に検索すべきか」を判断基準とします。権限、ライフサイクル、またはトピックが全く異なる資料は、分離する方が適しています。

</details>
