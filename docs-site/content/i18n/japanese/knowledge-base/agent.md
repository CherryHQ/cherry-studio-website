# Agent との連携

ナレッジベースを Agent にバインドすると、Agent はマルチステップタスクにおいて承認済みの資料を検索・読み取ることができます。資料の更新が必要な場合は、ナレッジベース管理を有効にすることもできます。

{% hint style="info" %}
通常の対話は単発の質問応答に適しており、Agent は継続的な調査、比較、ファイル生成、段階的な検収に適しています。Agent は設定でバインドされたナレッジベースのみアクセスします。
{% endhint %}

## 通常の対話と Agent の違い

| 通常の対話 | Agent |
| ------------ | --------------- |
| メッセージごとにナレッジベースを一時選択 | Agent 設定で長期的にバインド |
| 即時の質問応答や短い比較に適する | マルチステップ調査やファイル納品に適する |
| 主に検索結果の断片で回答 | 資料を検索し、権限に基づいてナレッジベースを管理 |
| 現在の対話が資料範囲を決定 | Agent 設定がアクセス可能な範囲を決定 |

## 読み取り専用ナレッジベース Agent の設定

{% stepper %}
{% step %}
### 1. まずナレッジベースを検収合格させる

対象資料が準備できていることを確認し、実際の質問で検索テストを実施してください。Agent は欠落した本文や誤ったチャンク分割を補完することはできません。
{% endstep %}

{% step %}
### 2. Agent 編集ウィンドウを開く

【ワークスペース】に入り、対象の Agent を選択し、メニューから【エージェント編集】を開きます。
{% endstep %}

{% step %}
### 3. 最小限の必要なナレッジベースをバインド

【ナレッジベース】タブを開き、【ナレッジベースを追加】をクリックします。このタスクに必要なライブラリのみをバインドし、部門間やバージョン間の資料が相互に干渉することを避けてください。
{% endstep %}

{% step %}
### 4. ナレッジベース検索を有効にする

【組み込みツール】を開き、【ナレッジベース検索】を有効にします。読み取り専用の調査、質問応答、要約、比較であれば、通常ここまでで十分です。

<figure><img src="../../../assets/39a4ea66c712c2736e5ccf34.webp" alt="Agent との連携 — 説明画像"><figcaption><p>検索は読み取り用、管理は資料変更用です。デフォルトでは最小権限から開始します。</p></figcaption></figure>
{% endstep %}

{% step %}
### 5. 境界が明確なタスクでテストする

Agent にまず出典を列挙し、その後結論を出すよう指示してください。資料に裏付けがない場合は明示的に記載し、常識に基づく補完は許可しないでください。
{% endstep %}

{% step %}
### 6. 出典と成果物を検収する

各結論がどのナレッジベースから来ているか、ファイル内の事実と提案が分離されているか、証拠が不足している部分がマークされているかを確認してください。
{% endstep %}
{% endstepper %}

## 組み込みツール、ナレッジベース、スキル、MCP の使い分け

<figure><img src="../../../assets/cc38d8a6378ca8270ceda746.webp" alt="Agent との連携 — 説明画像"><figcaption><p>資料検索にはナレッジベース、繰り返し手順にはスキル、外部システムアクセスには MCP を使用します。権限の拡大で明確なタスクを代替しないでください。</p></figcaption></figure>

## ナレッジベース検索と管理

| 機能 | 実行可能な操作 | 適用タスク | デフォルト推奨 |
| ----- | -------------- | ----------- | ----------- |
| ナレッジベース検索 | バインド済みナレッジベースの検索、一覧表示、読み取り | 質問応答、調査、要約、比較 | 有効のままにしておく |
| ナレッジベース管理 | ナレッジベース文書の追加、削除、更新 | 承認済みの資料メンテナンス | デフォルト無効、必要に応じて一時有効化 |

{% hint style="warning" %}
ナレッジベースのバインドはアクセス範囲の付与であり、別のナレッジベースのコピーを作成するものではありません。資料の更新や再インデックス後、Agent は次の検索で更新後の内容を使用します。
{% endhint %}

{% hint style="danger" %}
【ナレッジベース管理】を有効にすると、追加、削除、更新により資料やインデックスが変更されます。承認前に、対象ナレッジベース、具体的な項目、同名競合の処理方法、ロールバック計画を確認してください。
{% endhint %}

## 推奨タスクテンプレート

### 調査してレポートを生成

> バインド済みナレッジベースから、海外出張の承認と保険に関する規定をすべて特定してください。まず出典と矛盾点を列挙し、その後 Markdown 形式のチェックリストを生成してください。資料に裏付けのない内容は補完しないでください。

### よくある質問の更新

> 宿泊費精算に関する既存の項目を検索し、最新の制度と旧 FAQ を比較してください。まず修正予定リストを提示し、承認後に該当する文書を更新してください。

### マルチナレッジベース比較

> 「製品マニュアル」と「アフターサービス事例」のナレッジベースからそれぞれ証拠を見つけ、「公式ルール / 実際の事例 / 推奨トーク」の3列で整理してください。各結論には出典名を保持してください。

## 設定説明

| 設定項目 | 推奨開始点 | 増加タイミング | リスク管理 |
| ----- | ---------- | ------------ | ------------- |
| バインドナレッジベース | タスク関連の1つのライブラリ | 明確なクロスライブラリ比較が必要な場合 | プロンプト内で各ライブラリの用途を明確に記述 |
| ナレッジベース検索 | 有効 | タスクで資料検索が必要な場合 | 出典がバインド範囲内から来ているか検収 |
| ナレッジベース管理 | 無効 | 明確に追加、削除、更新が必要な場合 | 項目ごとに承認し、重要な資料を先にバックアップ |
| 出力要件 | 事実、推論、提案を分離 | レポートやファイル生成が必要な場合 | 各事実に出典名を保持 |

## ユーザー事例

小林氏は、アフターサービス Agent に【公式マニュアル】と【審査事例】をバインドし、ナレッジベース検索のみを有効にしました。Agent にデバイス型別で安全警告、公式手順、事例提案を列挙し、これらを分離するよう指示しました。古い事例の更新が必要な場合のみ、管理ツールを一時有効にし、修正予定リストを確認してから承認しました。

完了基準は以下の通りです：Agent が未バインドの資料にアクセスしないこと、事例提案を公式ルールとして記載しないこと、すべての書き込み操作に明確な目標と検収結果があること。

## 結果検収

* 出典は現在の Agent にバインドされたナレッジベースのみから来ている。
* 検索結果がタスク内のすべての条件をカバーしている。
* 成果物が資料の事実、Agent の推論、提案を分離している。
* 管理操作が目標、影響、結果を説明している。
* 資料更新後、固定の検索質問を再実行している。

## よくある質問

<details>

<summary>通常の対話では検索できるのに、Agent では検索できないのはなぜですか？</summary>

対象ナレッジベースが現在の Agent にバインドされているか、および【ナレッジベース検索】が有効になっているかを確認してください。異なる Agent のバインド範囲は相互に継承されません。

</details>

<details>

<summary>ナレッジベース管理を有効にすべきでない場合とは？</summary>

読み取り専用の調査、チーム共有の制度ライブラリ、履歴バージョンを保持する資料ライブラリは、デフォルトで検索のみを有効にします。更新が必要な場合のみ、管理を一時有効にし、項目ごとに承認してください。

</details>

<details>

<summary>Agent が未バインドのナレッジベースを操作しようとした場合、どうすればよいですか？</summary>

すべてのナレッジベースに権限を拡大しないでください。タスクが本当に必要であることを確認した後、対象ライブラリを現在の Agent に追加するか、すでにそのライブラリをバインドしている Agent を使用してください。

</details>
