# 機能の違い

V2 ではデータ構造と複数の機能の入口が変更されました。アップグレード前に再設定が必要な項目を確認してください。具体的な手順は [【V1 から V2 へのアップグレード】](v1-to-v2-migration.md) を参照してください。

## V2 の移行変更点

| 状況 | V2 の処理方法 | 注意事項 |
| --------- | ----------------------- | ------------------------------ |
| V1 からの初回移行 | V1.9.13 から V2 を直接インストール可能 | 特定の V2 リリースを先にインストールする必要はありません。 |
| V2 の通常アップグレード | 直接アップグレードし、現在の V2 データを継続使用 | 【再移行】をクリックしないでください。 |
| V1 の再移行 | 【設定】→【データ】で【再移行】を選択 | 現在の V2 データは完全に削除されます。以前の移行失敗やデータ漏れの場合にのみ使用してください。 |

{% hint style="danger" %}
【再移行】は V1 データを現在の V2 に追加マージしません。まず現在の V2 データを削除し、保持されている V1 データから再インポートします。V1 の移行失敗やデータ漏れでない場合は、絶対にクリックしないでください。
{% endhint %}

## データの処理方法

| 処理方法 | データ範囲 | アップグレード後の対応 |
| ---- | --------------------------------------------------------------------- | ------------- |
| 自動移行 | 設定、モデルサービスとモデル、アシスタントとグループ、セッションとメッセージ、Agent とセッション、MCP、ナレッジベースと有効なインデックス、ファイル、描画、翻訳、メモ、プロンプト、使用量記録 | よく使用する項目が正常に開けるか確認してください。 |
| 再確認が必要 | Anthropic 認証情報、Web 検索のデフォルトサービス、Agent のツール権限とナレッジベースのバインド、プロンプトの順序、ナレッジベースの失敗項目、カスタム CSS、サイドバーのお気に入り、欠落ファイル | 下表に従って再確認してください。 |
| 引き継がれない | Agent のスケジュールタスク履歴、旧版サイトマップの展開結果、一部の一時画像参照、メモの現在開いている状態、削除された機能の設定 | 必要に応じて再作成してください。 |

{% hint style="info" %}
移行により V1 の元データは削除されません。V2 の新データは V1 に同期されず、両バージョンのバックアップは相互に復元できません。
{% endhint %}

## 主な違い

| 機能 | V1 | V2 | アップグレード後の対応 |
| --------------- | ------------------------------- | --------------------------------------------- | -------------------------------- |
| アシスタントとプロンプト | 独立したアシスタントライブラリ；クイックフレーズをアシスタントに関連付け可能 | アシスタントはチャットと Agent で管理；クイックフレーズはグローバルプロンプトに統合 | アシスタントのグループとプロンプトの順序を確認してください。 |
| Agent | 一部の設定とワークスペースがセッションに従属；旧承認でツールを自動承認可能 | アイデンティティ、メモリ、主要設定は Agent に帰属；セッション作成後ワークスペースは固定；ツールは再承認を要求する場合あり | モデル、ワークスペース、ツール、権限を確認してください。 |
| Agent ナレッジベース | ナレッジツールがグローバルナレッジベースにアクセスする場合あり | 明示的にバインドされたナレッジベースのみアクセス | 各 Agent のナレッジベースバインドを再確認してください。 |
| ナレッジベース検索 | 検索モードとサイトマップソースを手動選択可能 | 埋め込みモデルがない場合は BM25、ある場合はハイブリッド検索；サイトマップは通常 URL として処理 | 埋め込みとリランキングモデルを確認；失敗ソースを再構築してください。 |
| Web 検索 | アシスタントまたは入力エリアでサービス選択可能；ローカル検索、RAG 圧縮、サブスクリプションブラックリストを含む | 【設定】→【Web 検索】でキーワード検索と URL 読み取りを個別設定；関連する旧オプションは削除 | 2 つのデフォルトサービスを再選択し、認証情報を確認してください。 |
| MCP | 追加済みサービスとサードパーティの発見マーケットが併存 | 追加済みサービスは移行継続；旧サードパーティの発見マーケットは提供終了 | サービス状態を確認；新サービスは現在のマーケットまたは JSON から追加してください。 |
| モデルサービス | Anthropic で OAuth 認証情報を保存可能 | Anthropic OAuth は移行されない；AWS Bedrock のリージョンは保持；新規サービスはデフォルトで無効 | Anthropic の API Key を再入力し、必要に応じてサービスを有効にしてください。 |
| ファイル | ファイルコピーと業務オブジェクトの参照関係が弱い | 管理ファイルは参照で管理；最後の参照削除後、管理コピーは遅延クリーンアップ | 長期保存するファイルは【ファイル】に配置またはエクスポート；ユーザーの元ファイルは削除されません。 |
| 描画、Mini App とサイドバー | パラメータと入口が旧版エリアに位置 | 描画パラメータはプロンプトツールバーへ移動；Mini App は上部タブバー；サイドバーのお気に入りはリセット | 新入口に慣れ、お気に入りを再設定してください。 |
| カスタム CSS | V1 のセレクタが直接有効 | コンテンツは保持されるが、移行後デフォルトで無効 | V2 のセレクタに適合させた後に有効にしてください。 |
| Code CLI | iFlow を選択可能 | iFlow は Qoder に置き換え | 関連ワークフローが必要な場合は Qoder を使用してください。 |

## 開発者互換性

<details>

<summary>API と外部統合にはどのような変更がありますか？</summary>

* API Gateway のモデル識別子が `provider::model` から `provider:model` に変更されました。
* Knowledge API が返すエントリは V2 フィールドを使用します。
* MCP-over-HTTP エンドポイントは削除されましたが、アプリ内 MCP には影響しません。
* SSE の起動失敗時に通常の HTTP エラーが直接返される場合があります。クライアントは HTTP と SSE のエラーパスの両方に互換性を持たせる必要があります。
* スケジュールタスクインターフェースのパラメータが変更され、過去の実行記録は移行されません。

</details>
