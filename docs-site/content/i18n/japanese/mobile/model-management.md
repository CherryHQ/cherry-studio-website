# モデルの追加・編集・管理

通常、プロバイダーのリストを取得して、使用するモデルを追加するだけで済みます。手動構成は、モデルが見つからない場合、より明確な名前が必要な場合、またはプラットフォームと異なる情報が含まれている場合に役立ちます。

**設定 → モデルサービス → 対象のプロバイダー → モデル**を開きます。

## モデルを手動で追加する

1. 「モデル」タブの「追加」ボタンをタップします。
2. プラットフォームが使用する正確な識別子である **モデルID** を入力します。プラットフォームのドキュメントまたはカタログから翻訳せずにコピーします。
3. 「毎日の質問」などの表示名を選択します。これにより、どのモデルが呼び出されるかではなく、モデルの認識方法が変わります。
4. モデルタイプとAPIを確認してください。不明な場合は、他のオプションをデフォルトのままにしてください。
5. 「**追加**」をタップします。初めてプロバイダーをセットアップする場合は、セットアップを完了し、そのスイッチがプロバイダー リストで有効になっていることを確認してください。

手動入力では、一度に 1 つのモデルを追加します。複数のモデルの場合は[モデル同期](model-updates.md)を使用してください。同じプロバイダー内で重複する ID は許可されません。

## 表示と編集

モデルをタップして詳細を表示し、その ID をコピーして、右上の **編集** をタップします。リスト項目を長押しして、詳細、編集、選択、または削除を行うこともできます。

モデル エディターは **明示的な保存** を使用します。必要なセクションを展開し、変更を加えて、「**保存**」をタップします。保存に失敗した場合は、表示されたフィールドを修正し、終了する前に再試行してください。

既存の **モデル ID はエディターでは変更できません**。間違っている場合は、正しい ID を持つモデルを追加し、エージェントまたはデフォルトを新しいエントリに切り替えてから、古いエントリを削除します。

## 設定にはどんな意味があるのでしょうか？

| 設定 | 効果 | 不安なときは |
| --- | --- | --- |
| 表示名、グループ、メモ | モデルを整理して認識する | 独自のラベルを使用する |
| モデルID | プラットフォームで呼び出されるモデルを識別します | プラットフォームの正確な値を維持する |
| モデルタイプ | テキスト、画像生成、その他の目的を区別する | プラットフォームの説明に従ってください |
| API | リクエストがモデルに接続する方法を選択します | 自動/デフォルトの選択を維持する |
| 推論 | 思考関連機能のサポートを記録します。 | 提供された情報を保管してください |
| ツール呼び出し | 検索、カレンダー、プラグイン ツールのレコードのサポート | モデルの実際のサポートと一致する |
| サポートされている入力 | 録画画像、音声、またはビデオ入力のサポート | サポートされていない入力を有効にしないでください |
| ストリーミング | プログレッシブ応答のサポートを記録します | デフォルトのままにしておきます。このフラグだけでは実行は変わりません |

**機能フラグは機能を追加しません。** テキストのみのモデルを画像対応としてマークしても、写真を理解できるようにはなりません。また、オーディオ/ビデオ フラグは、モバイル アプリがそのようなすべての添付ファイルを送信できることを意味するものではありません。

埋め込みと再ランキングは、検索に使用されるモデル カテゴリです。情報は管理できますが、通常のモバイル チャットでは現時点では利用できません。会話用のテキストまたは描画用の画像生成を選択します。

## コンテキストと入出力制限

**トークン** は、文字数や単語数ではなく、モデルがコンテンツを測定するために使用する単位です。

* **コンテキスト ウィンドウ:** 履歴、ツールの結果、および新しい応答のための合計スペース。
* **最大入力:** リクエストで取り込めるコンテンツの量。
* **最大出力:** モデルが 1 回の応答で生成できる量。

数値を大きくしてもプロバイダーの制限は回避されず、リクエストが拒否される可能性があります。これらの値は、プラットフォームによって異なる制限が与えられている場合にのみ変更してください。正の整数を使用し、制限の競合に関する警告を解決します。

制限オーバーライドをクリアして保存し、カタログまたはアプリのデフォルトを復元します。長い会話でも制限を超える場合は、添付ファイルを減らすか、内容を短くするか、新しい会話を開始してください。

## 価格とコストの見積もり

価格設定は使用量の見積もりをサポートします。 **編集してもプロバイダーの請求書は変更されません**。

* USD または CNY を選択します。入出力レートは **100 万トークンあたり**です。
* キャッシュの読み取り/書き込みレートは、プラットフォームが再利用されたコンテンツに価格を設定する方法を表します。空のキャッシュ レートは入力レートを使用します。
* 未知は無料とは異なります。 `0` は明示的にゼロレートを意味します。価格不明の場合は使用しないでください。
* 入力層は、長いリクエストの場合、より高い料金を表す可能性があります。各段階の開始しきい値は、前の段階より大きい値にしてください。該当するレベルでは、しきい値を超えた部分のみではなく、リクエスト全体の価格が設定されます。

信頼できる価格設定がない場合は、デフォルトのままにしてください。推定コストと不完全なコストについては、[設定と使用法](settings-and-usage.md) を参照してください。

## API を変更するとすぐに保存されますか?

管理リストでモデルの API を直接変更すると、すぐに保存されます。 **エディタ**で選択すると、[保存]をタップするまで下書きが変更されます。

デフォルトに従うと、プロバイダーの現在のデフォルト API が使用されます。使用できなくなった場合は、モデルの名前を繰り返し変更するのではなく、プロバイダーの構成された接続を確認してください。

## モデルの削除と整理

長押しして選択モードに入り、現在のフィルター内の複数のモデルを削除します。削除が失敗しても選択内容は保持されるため、問題を解決して再試行できます。

* グローバル デフォルト モデルは保護されています。削除する前に、**設定 → デフォルトモデル** で変更またはクリアしてください。
* エージェントが使用するモデルを削除するということは、エージェントが別のモデルを選択する必要があることを意味します。
* ローカル構成を削除しても、プロバイダー アカウントは閉鎖されず、料金も取り消されません。

一時的に使用しない場合は、後で構成を再構築するのではなく、プロバイダーを無効にします。リモート情報が変更されたときに編集内容に何が起こるかについては、[モデルの更新](model-updates.md) を参照してください。
