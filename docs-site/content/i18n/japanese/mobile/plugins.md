# プラグインと外部ツール

プラグインを使用すると、エージェントは、Feishu ドキュメントの読み取り、Notion ページの整理、Amap でのルート検索など、承認内の他のサービスにアクセスできます。

モデルはタスクを解釈します。プラグインはサービスにアクセスします。最初にツール呼び出しをサポートするテキスト モデルを選択します。

## プラグインを接続して使用する

1. サイドバーで **プラグイン** を開き、サービスを選択します。
2. その機能、例、権限を読んでから、「**接続する**」をタップします。
3. アカウント認証を完了するか、必要なサービス キーを入力します。
4. Cherry Studio に戻り、要求に応じてアカウント/ワークスペースを確認し、**接続済み** が表示されるまで続けます。
5. チャットで具体的なリクエストを伝えます。必要に応じて、**＋ → プラグイン** を使用してターゲット プラグインを挿入し、質問を追加します。

例: 「Feishu を使用して、この文書からの 3 つの結論を要約します: [リンク]。」挿入された名前はコンポーザーと送信されたメッセージに表示されます。

接続されたプラグインは、それぞれに個別の承認を必要とせずに、エージェント間で動作します。 Composer を選択すると、目的のサービスが明確になります。使用可能なプラグインが接続されていない場合、チャット コンポーザーの **＋ → プラグイン** オプションは非表示になります。

## 一般的な接続

| プラグイン | 役に立つ | 接続に関する注意事項 |
| --- | --- | --- |
| Feishu | ドキュメント、ベーステーブル、タスク、カレンダー | Feishu アプリケーションをセットアップし、アカウントを認証します。組織の承認が必要な場合があります。現在、この接続は Feishu アカウントをサポートしていますが、国際 Lark アカウントはサポートしていません |
| Notion | ページとデータベース レコードの検索/読み取り/編集 | ワークスペースを承認し、アカウントを確認します。ワークスペースの権限は引き続き適用されます |
| GitHub | リポジトリ/ディスカッションを読み取り、問題/プル リクエストを管理します | アプリ認証または個人アクセス トークンを使用します。組織のアクセスには承認が必要な場合があります |
| Amap | 場所、近くのサービス、天気、ルート | Amap のプラットフォームの **Webサービスキー** を使用します。ルート クエリではデバイスの位置が自動的に読み取られません |
| DingTalk | 書類、カレンダー、タスク、その他のオフィス業務 | アカウントと組織を承認します。一部のアクションには追加の承認が必要です |
| WeCom | 承認された文書、スプレッドシート、スケジュール、その他のオフィスデータ | 生成された認証リンクを WeCom のファイル転送アシスタントに貼り付けて開き、Cherry Studio に戻ります。 |

リストされている機能は、アカウントへのアクセスを保証するものではありません。プラン、組織設定、リソース権限、およびクォータによって、アカウントで使用できるものが決まります。

### Feishuの準備中

このフローの「アプリケーション」は、Feishu 認証構成であり、インストールする別の電話アプリではありません。接続ページの **アプリケーションの構成** またはセットアップ ガイドのリンクに従います。既存のアプリケーションを使用する場合は、そのアプリケーション ID とアプリケーション シークレットを入力し、ドキュメント/タスク/カレンダーに必要な権限を有効にして、個人アカウントを認証します。

部分的な許可でも、使用可能な接続を生成できます。後で機能を追加するには、対応するアプリケーション権限を有効にし、組織の承認を完了し、承認を更新します。再接続だけでは、不足している権限は付与されません。

### 追加のDingTalk承認

DingTalk で要求されたアクションの承認を完了してから、戻って **操作を再度要求**してください。承認では、失敗したアクションが自動的に再生されません。

### 期限切れの WeCom リンク

リンクは 5 分間持続します。新しいリンクを生成し、通常のブラウザだけでなく、WeCom 内で開きます。

## 接続後は何ができますか?

まずは読書から始めましょう。括弧で囲まれたテキストをリンク、名前、または日付に置き換えて、結果のソースと範囲を確認してください。

| プラグイン | 柔軟なリクエスト | 何を確認するか |
| --- | --- | --- |
| Feishu | 「この文書を読んでください: [リンク]。結論、タスク、担当者、期限をリストします。不足している情報には未確認としてマークを付けます。タスクはまだ作成しないでください。」 | 担当者と日付が明示的かどうか。タスクの作成は別の次のステップです |
| Notion | 「このページを読んでください: [リンク]。最近のプロジェクトの進捗状況を要約し、ソース リンクを保持してください。」 | ワークスペースへのアクセスと、関連するページのコンテンツが完全に読み取られたかどうか |
| GitHub | 「[リポジトリ URL] で先週の問題のディスカッションを読み、トピックごとにグループ化し、リンクを含めます。」 | リポジトリの可視性、日付範囲、および議論の結論が確認されたかどうか |
| Amap | 「[都市と出発地] から [目的地] までの公共交通機関を、徒歩、乗り換え、推定所要時間を含めて比較します。」 | 重複する地名の市区町村と住所。見積もりは実際の出発時刻ではありません |
| DingTalk | 「この文書 [リンク] を読み、[トピック] に関する資料を要約してください。編集しないでください。」 | 組織およびドキュメントへのアクセス、および DingTalk でのその他の権限 |
| WeCom | 「この文書を読んでください: [リンク]。編集せずに、出典とともに 3 つの重要な結論を要約してください。」 | 承認されたアカウントのアクセスと、接続上で実際に使用できるツール |

### ドキュメントのメモを保存済みタスクに変える

たとえば、Feishu で 2 つのリクエストを使用します。

1. 「これらの会議メモを読んでください: [リンク]。提案されたタスク、担当者、期限をリストしますが、作成しないでください。」
2. 確認後：「項目 1 と 2 のみを、確認した担当者と日付で Feishu タスクとして作成します。結果とリンクを返します。」

文書の読み取り、人物の検索、タスクの作成はすべて、必要なときに利用できる必要があります。重複する名前と不明瞭な日付を最初に解決します。チャット内のタスク テーブルは、タスクが保存されたことを証明するものではありません。割り当てや招待状は他の人に通知される場合もあります。

### ベーステーブルまたはデータベースの読み取りと更新

テーブルのリンクとビューを提供し、「このビューではステータスが進行中のレコードのみを読み取ります。変更を加えずに名前と期限をリストします。」というフィルターを指定します。プロジェクトには、類似した名前のテーブルまたはビューが複数存在する場合があります。

編集する前に、正確なレコードとフィールドを特定してください。結果にページネーションや制限がある場合は、エージェントに範囲を説明するよう依頼します。 1 回の問い合わせでデータベース内のすべての記録を取得できるとは限りません。現在の Notion 接続では、添付ファイルの処理や Notion エージェントへのアクセスは提供されません。

### ツールは連携できますか?

利用可能な接続ツールは、ドキュメントの読み取りと[チェックリスト ファイルの保存](file-generation.md)など、1 つのタスクで連携できます。サービス間で素材をコピーする場合は、コピー先と正確な内容を指定して、それぞれの結果を確認します。あるステップが成功しても、別のステップが失敗しても自動的にロールバックされません。

承認、結果確認、失敗時の対応については、[AIにツールを使わせる](using-tools.md)をご覧ください。

## 認証を閉じましたが接続されません

ブラウザを閉じても、認証はキャンセルされず、接続が成功したことも証明されません。接続ページに戻り、必要に応じて **認証ページを開く** または **もう一度確認** を使用し、アカウントの確認を完了します。

期限切れまたは拒否されたリクエストを再起動します。アカウントを切り替えるには、まず手順に従って既存のアカウントを切断します。

## 切断して取り消す

**切断** への接続管理または詳細メニューを使用します。これにより、ローカル アクセスが削除されます。

リモート失効が確認されていない場合は、プロバイダーの Web サイトで **認可の管理** を使用してください。ローカルの削除とプロバイダー側​​の取り消しは、必ずしも同時に完了するとは限りません。

プラグインの認証情報はこのデバイス上に残り、デスクトップ構成のインポートによって転送されません。別の電話には別の接続が必要です。取得されたコンテンツはモデルによって使用される場合があります。 [データとプライバシー](data-privacy.md) を参照してください。

## カスタム MCP サービスを追加する

**MCP** は、エージェントを追加のツール サービスに接続します。リモート ツール サーバー アドレスをすでに持っている場合は、これを使用します。組み込みプラグインは、ニーズを満たす場合にはよりシンプルになります。

1. **設定 → MCP → サーバーを追加**を開きます。
2. 指定されたサーバー アドレスを入力します (できれば `https://`)。
3. 認証が必要な場合は、サービスの手順に従って、**Headers** に `Authorization=Bearer your-token` など、1 行に 1 つの `Name=Value` エントリを入力します。
4. 保存して接続を待ち、**ツール** リストを調べます。不要なツールを無効にします。
5. ターゲット エージェントのエディタで対応するサーバーを有効にして、新しいリクエストを送信します。エージェントが新しい場合は、まずエージェントを保存し、エディターを再度開いてツールを設定します。

サーバーが接続されて有効になっており、ツールがグローバルに有効になっており、対応するサーバーがエージェントに対して有効になっている必要があります。自動承認では、これらの要件はいずれも回避されません。

このフィールドは、`npx` や `uvx` などのデスクトップ起動コマンドではなく、リモート アドレスを受け入れます。 iOS はプレーン `http://` をブロックできます。サービスの安全なアドレスを優先します。

## 接続されたプラグインはまだタスクを実行できません

接続ステータスとモデル ツール呼び出しのサポートを確認します。ターゲットのリンク/名前/日付範囲を指定します。権限エラーは、エージェントの指示を変更するのではなく、サービスで修復する必要があります。

書き込みの場合は、まず、提案された変更を読み取ってリストするように要求します。実行時に確認を求めるかどうかは、[ツール承認](agents-and-tools.md)に依存します。
